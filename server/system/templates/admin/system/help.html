一、常用管理操作

学生管理

  • 创建学生：先确保该用户已注册（通过 App 用邀请码注册），在 Admin 中找到相应用户，加上 Student 关联。建议用"邀请码 → 注册"流程，不建议在 Admin 手动创建 Student。
  • 学号：系统会自动生成，不要手动填写。格式为 XS-XXXXXX（前缀 + LCG 混淆数字）。生成规则见系统配置 student_id_template。
  • 删除学生：删除 Student 不会删除关联的 User。如需彻底删除，需分别删除 Student 和 User 两条记录。

邀请码管理

  • 生成：在「系统工具」页面批量生成。也可在 /admin/accounts/invitationcode/add/ 手动创建单个。
  • 有效期：留空 = 永不过期；填写数字（如 30）= 从创建起 n 天后过期。
  • 使用状态：is_used 标记已使用；used_by 关联使用人。已使用的邀请码不可复用。
  • 列表中已使用的行为灰色显示，过期行有标记。

课程与讲义

  • 讲义系列：填写名称和描述，用于组织一组相关讲义。
  • 讲义：每个课程可以有多个讲义。讲次标识 chapter 固定两位数字，如 01、02。md_content 为完整 Markdown 内容，支持 LaTeX 公式（$$...$$）。
  • 讲义更新后，需要重新「构建讲义资产」才能推送到 App（见系统工具章节）。

题库

  • 不建议在 Admin 手动操作题目。题库数据以原始 JSON/YAML 源码为准，通过构建脚本生成。
  • 如需修改题目，应修改 qbank/data/ 下的源文件，然后重新构建题库资产（见系统工具章节）。
  • Admin 中查看题目用于核对数据，不要直接编辑。

二、系统配置

App 版本

  • 平台：android / ios。当前仅维护 Android 版本。
  • 版本名 vs 版本号：version_name 展示用（如 1.2.0），version_code 是整数递增版号，新版本必须大于旧版本。
  • 强制更新：开启后用户不更新到该版本无法继续使用 App。仅在大版本不兼容时开启。
  • 下载地址：上传 APK 后填写下载 URL。Android 版当前通过静态文件或 CDN 分发。
  • 更新说明：填写后会展示在 App 更新弹窗中。
  • 新增版本记录后，App 启动时自动检测并提示更新。

数据库版本

  • db_type：qbank（题库）和 lecture（讲义）两种。
  • 版本递增：通过系统工具「构建并发布」时自动递增 data_version，无需手动修改。
  • 强制更新：默认不开启。如需让学生立即拉取新资产，可勾选 force_update。
  • 校验和 / 文件大小 / 下载路径：构建时自动填写，无需手动维护。
  • 更新说明：构建时可以填写，会展示在 App 资产更新弹窗中。

公告

  • 标题 + 内容（纯文本）。is_active 控制前台是否显示。
  • 多条有效公告同时展示，按创建时间倒序排列。
  • App 启动时拉取公告，在首页展示。

系统配置键值

目前使用中的配置项：

cooling_duration 评分冷却时间（秒），默认 60。学生做完题后需等待此时间才能再次评分。 default_solve_count 自由练习每次出题数，默认 10。 student_id_template 学号模板，默认 XS-{lcg}。{lcg} 会被替换为 LCG 混淆后的数字 ID。 system_maintenance 维护模式开关。true 时 App 提示维护中，不可使用。
⚠️ 修改配置值后立即生效，无需重启服务。修改前确认键名和格式正确，错误的键值可能导致 App 行为异常。

等级与成就

  • 等级：按 level 编号升序排列。每个等级有最小积分阈值 min_xp，学生积分到达后自动升级。配置完成后不要频繁调整阈值，以免影响已有学生等级。
  • 成就定义：trigger_type 决定触发条件（连续登录、做题数量等），threshold 是达成阈值。修改后只能影响新进度，已有进度不受影响。
  • 成就进度：每个学生每项成就一条记录，可手动调整 progress 或勾选 is_unlocked 强制解锁。

三、系统工具

构建资产

📍 进入方式：Admin 首页 → 系统工具 → 构建 & 发布
  • 题库数据和讲义内容以源码形式管理。修改源文件后，需要「构建」才能生成 App 可下载的数据库文件。
  • 测试模式：构建到临时文件，不递增版本号，不覆盖正式文件。用于验证修改是否正确。
  • 发布模式：构建到正式目录，自动递增 data_version 版本号，App 启动时检测到新版本后会下载更新。
  • 什么时候需要构建：
    • 修改了题库 JSON/YAML 源文件 → 构建题库
    • 修改了讲义 Markdown 内容 → 构建讲义
  • 构建日志会直接展示在当前页面顶部。
⚠️ 发布模式不可逆。确保在测试模式验证无误后再发布。

生成邀请码

📍 进入方式：Admin 首页 → 系统工具 → 邀请码管理
  • 单次最多生成 100 个。邀请码格式为 XXXX-XXXX-XXXX（大写字母+数字）。
  • 可设置有效期天数，留空 = 永不过期。
  • 已生成的邀请码在页面的表格中展示。可以使用浏览器搜索（Ctrl+F）查询特定邀请码状态。
  • 如需手动创建单个邀请码或编辑过期时间，在 /admin/accounts/invitationcode/ 操作。

四、服务器维护

数据备份

  • 自动备份：服务器每天 03:00 通过 crontab 执行备份脚本，将 SQLite 数据库备份到 /var/backups/ 目录。
  • 保留策略：自动保留最近 30 天的备份文件，超出自动删除。
  • 备份文件命名：zhangyuzhixue-2026-07-11.sqlite.gz（gzip 压缩），如 zhangyuzhixue-YYYY-MM-DD.sqlite.gz。
  • 手动备份：登录服务器后执行 python manage.py dumpdata > backup.json（Django 原生格式）或直接复制 db.sqlite3 文件。
  • 备份脚本路径：scripts/backup_db.sh。

数据恢复

  • 从备份文件恢复：
    1. 解压备份文件：gunzip /var/backups/zhangyuzhixue-YYYY-MM-DD.sqlite.gz
    2. 停止服务：systemctl stop gunicorn
    3. 替换数据库文件：cp /var/backups/zhangyuzhixue-YYYY-MM-DD.sqlite /path/to/project/db.sqlite3
    4. 启动服务：systemctl start gunicorn
  • 从 JSON 备份恢复：
    1. 停止服务
    2. python manage.py flush（清空数据库）
    3. python manage.py loaddata backup.json
    4. 启动服务
⚠️ 恢复操作会覆盖当前数据，操作前确认备份文件日期，建议先手动备份当前数据。

JSON 数据推送

  • 用途：将业务数据（学生、讲义、提交记录等）以 JSON 格式推送到 Gitee 私有仓库，作为异地数据保险。
  • 频率：每天 04:10 自动执行。
  • 推送内容：业务数据为 JSON 明文；密码字段保存为哈希值（单向，不可还原）。
  • 推送仓库：zhangyuzhixue-v2-data（独立仓库，与代码仓库分离）。
  • 手动触发：登录服务器执行 bash scripts/dump_and_push.sh。
  • 查看数据：在 Gitee 仓库中浏览对应日期的 JSON 文件。

服务启停

  • 通过 systemd 管理：
  • sudo systemctl start gunicorn — 启动
  • sudo systemctl stop gunicorn — 停止
  • sudo systemctl restart gunicorn — 重启（修改配置或代码后执行）
  • sudo systemctl status gunicorn — 查看运行状态
  • 日志查看：sudo journalctl -u gunicorn -n 50 --no-pager（最近 50 行）
  • Nginx 无需频繁操作，修改 nginx 配置后执行 sudo nginx -s reload。
💡 部署在 2C2G ECS，重启通常 5 秒内完成。
