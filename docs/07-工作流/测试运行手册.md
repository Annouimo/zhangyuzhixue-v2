# 测试运行手册

本文档定义本地测试入口、执行顺序和失败分类。Flutter 命令必须串行执行，避免多个 Flutter 工具进程争用 SDK 锁。

## 统一入口

在仓库根目录运行：

```powershell
# 最小环境探测
.\scripts\run_tests.ps1 -Suite Quick

# 分层测试
.\scripts\run_tests.ps1 -Suite Student
.\scripts\run_tests.ps1 -Suite Teacher
.\scripts\run_tests.ps1 -Suite Server

# 学生端 Windows 集成测试
.\scripts\run_tests.ps1 -Suite E2E

# 学生端、教师端和服务端，按顺序执行
.\scripts\run_tests.ps1 -Suite All
```

Flutter 不在 `PATH` 时可以显式指定：

```powershell
.\scripts\run_tests.ps1 -Suite Quick -FlutterPath D:\Programs\flutter\bin\flutter.bat
```

## 运行规则

1. 同一时间只运行一个 Flutter 测试命令。
   学生端全量测试额外使用 `--concurrency=1`，避免进程级数据库和网络单例在测试文件之间竞争。
2. `All` 不包含 E2E；E2E 会访问真实后端并产生账号数据，单独运行。
3. Windows E2E 必须显式使用 `-d windows`。
4. 每个测试进程都有总超时；Flutter 单条测试另有独立超时。
5. 日志写入 `.hermes/tmp/test-logs/`，该目录不进入版本控制。
6. 测试入口不会扫描或结束已有 Flutter 应用；超时时只结束它自己启动的进程树。
7. pytest 缓存写入 `.hermes/tmp/pytest-cache/`；运行器会创建被 Git 忽略的 `server/staticfiles/`，避免沙箱 ACL 和空静态目录产生无关警告。

## 失败分类

| 类型 | 识别方式 | 处理方式 |
| --- | --- | --- |
| 环境失败 | Flutter/Python 不存在，SDK 无写权限，设备不可用 | 修复环境后重跑 Quick |
| 启动失败 | 超时前没有测试用例输出 | 检查 SDK 锁、残留工具进程和日志 |
| 测试超时 | 退出码 124，日志停在具体用例 | 检查无限等待、网络请求或未结束动画 |
| 断言失败 | 日志包含失败用例和期望/实际值 | 判断产品回归或测试契约过期 |
| 后端失败 | 登录、HTTP 或数据准备失败 | 检查测试服务端与 `test_audit` 数据 |

不要把环境失败或启动失败记录为产品测试失败。修复后应先运行 `Quick`，再运行受影响套件。

## 当前阶段边界

阶段 0 只建立可靠的测试运行基线，不调整现有测试断言、不重写 E2E 流程，也不增加 Golden 截图。后续阶段在此入口上逐步接入测试隔离、Windows `integration_test`、截图和 CI 门禁。
