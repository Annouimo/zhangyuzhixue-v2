# 测试运行手册

本文档定义本地测试入口、执行顺序和失败分类。Flutter 命令必须串行执行，避免多个 Flutter 工具进程争用 SDK 锁。

## 统一入口

在仓库根目录运行：

```powershell
# 最小环境探测
.\scripts\run_tests.ps1 -Suite Quick

# 学生端分层测试
.\scripts\run_tests.ps1 -Suite StudentData
.\scripts\run_tests.ps1 -Suite StudentUi
.\scripts\run_tests.ps1 -Suite StudentIntegration
.\scripts\run_tests.ps1 -Suite Student

# UI Golden 对比；仅在确认视觉变更后更新基线
.\scripts\run_tests.ps1 -Suite Golden
.\scripts\run_tests.ps1 -Suite Golden -UpdateGoldens

# 其他项目门禁
.\scripts\run_tests.ps1 -Suite Teacher
.\scripts\run_tests.ps1 -Suite Server

# 学生端 Windows 真实宿主冒烟测试
.\scripts\run_tests.ps1 -Suite E2E

# 学生端、教师端和服务端，按顺序执行
.\scripts\run_tests.ps1 -Suite All
```

Flutter 不在 `PATH` 时可以显式指定：

```powershell
.\scripts\run_tests.ps1 -Suite Quick -FlutterPath D:\Programs\flutter\bin\flutter.bat
```

## 运行规则

1. 同一时间只运行一个 Flutter 测试命令。
   学生端全量测试额外使用 `--concurrency=1`，避免进程级数据库和网络单例在测试文件之间竞争。
2. `All` 不包含 E2E；Windows 测试会启动真实桌面窗口并占用前台，单独运行。
3. Windows E2E 必须显式使用 `-d windows`，默认入口只运行 `integration_test/windows_smoke_test.dart`。
4. 每个测试进程都有总超时；Flutter 单条测试另有独立超时。
5. 日志写入 `.hermes/tmp/test-logs/`，该目录不进入版本控制。
6. 测试入口不会扫描或结束已有 Flutter 应用；超时时只结束它自己启动的进程树。
7. pytest 缓存写入 `.hermes/tmp/pytest-cache/`；运行器会创建被 Git 忽略的 `server/staticfiles/`，避免沙箱 ACL 和空静态目录产生无关警告。
8. 默认 Windows E2E 使用内存 SharedPreferences，不调用 `main()` 的数据库和版本检查启动流程，不访问远程后端，也不读写正式用户数据。
9. `Student` 和 `Teacher` 都先运行 Flutter analyzer，再运行各自测试；分析失败时不继续测试。`Server` 按 flake8、Django migration check、pytest 的顺序执行，前置检查失败时不继续运行后续步骤。

## Windows 真实宿主测试

`E2E` 在 Flutter Windows embedder 中启动 1280×720 的真实应用窗口，验证：

- Windows runner 能完成构建、安装测试资产、启动和退出；
- 应用在桌面逻辑尺寸下显示登录页；
- 登录表单校验能够工作；
- 登录页到注册页的真实 GoRouter 导航能够工作；
- 注册协议勾选能正确改变提交按钮状态并返回登录页。

运行前确保没有其他 Flutter 命令，也不要同时操作新出现的应用窗口。该测试不截图；截图与 Golden 基线在后续阶段处理。

原有 `e2e_auth_test.dart`、`e2e_solve_test.dart`、`e2e_exam_test.dart`、`e2e_sync_test.dart` 依赖远程后端、预置账号和旧页面文案，当前不属于默认门禁。它们将在真实后端测试环境确定后逐条重写，不能用其结果替代默认 Windows E2E。

## 学生端测试分层

| 套件 | 范围 | 用途 |
| --- | --- | --- |
| `Quick` | 标记为 `smoke` 的跨层关键测试 | 环境确认、提交前快速反馈 |
| `StudentData` | `test/data/` | API、数据库、DAO、Repository、同步与本地基础设施 |
| `StudentUi` | `test/pages/`、`test/widgets/`、`test/support/`、应用启动测试 | 页面、组件、响应式规则与导航交互 |
| `StudentIntegration` | `test/data/integration/` 中标记为 `integration` 的测试 | 真实 Repository、DAO、内存数据库与同步队列的关键业务链路 |
| `Golden` | `test/golden/` 中标记为 `golden` 的测试 | 固定视口、固定主题的像素级 UI 回归 |
| `Student` | `test/` 全部测试 | 阶段完成和提交前完整回归 |

测试标签定义在 `flutter_app/dart_test.yaml`。`smoke` 只用于跨层代表性关键路径；`golden` 和 `integration` 分别用于截图回归与进程内集成测试。Quick 同时使用标签和 `scripts/run_tests.ps1` 中的显式文件清单，因为 Flutter 的全目录标签过滤仍会加载未选中的测试文件。不要把所有测试都标记为 `smoke`，否则快速反馈套件会逐渐退化为全量测试。

Golden 不包含在本地 `Student` 中，在 CI 只由固定 Windows runner 执行。基线由固定的 Flutter SDK 和测试平台生成；跨操作系统字体或栅格化差异应在专用 Golden 环境处理，不能通过无条件更新图片掩盖。更新前必须查看全部新图片，确认是预期视觉变化后再提交 PNG。

## CI 门禁与产物

GitHub Actions 按职责拆成四个独立 job：

| Job | 平台 | 阻断门禁 | 上传产物 |
| --- | --- | --- | --- |
| `student` | Ubuntu | analyzer、学生端非 Golden 全量测试 | JSON 测试事件、LCOV 覆盖率 |
| `teacher` | Ubuntu | analyzer、教师端测试 | JSON 测试事件 |
| `django` | Ubuntu | flake8、migration check、deploy check、pytest 与 30% 覆盖率下限 | JUnit、XML 覆盖率 |
| `windows-acceptance` | Windows | 4 个固定 Golden、Windows 真实宿主冒烟测试 | JSON 测试事件、Golden 失败图片 |

四类门禁互相独立，失败时可直接定位所属层。产物无论成功失败都尝试上传，保留 14 天；同一分支的新提交会取消尚未完成的旧 CI，避免 Windows runner 继续执行已过期版本。Golden 只在 Windows 固定环境比较，不在 Linux 重复执行。

新增测试时，优先通过目录归入 `StudentData` 或 `StudentUi`。只有满足以下任一条件时才加入 `smoke`：应用无法启动、认证入口不可用、数据库无法初始化、同步队列无法推进，或共享 UI 测试环境失效。

## 失败分类

| 类型 | 识别方式 | 处理方式 |
| --- | --- | --- |
| 环境失败 | Flutter/Python 不存在，SDK 无写权限，设备不可用 | 修复环境后重跑 Quick |
| 启动失败 | 超时前没有测试用例输出 | 检查 SDK 锁、残留工具进程和日志 |
| 测试超时 | 退出码 124，日志停在具体用例 | 检查无限等待、网络请求或未结束动画 |
| 断言失败 | 日志包含失败用例和期望/实际值 | 判断产品回归或测试契约过期 |
| 后端失败 | 登录、HTTP 或数据准备失败 | 检查测试服务端与 `test_audit` 数据 |

不要把环境失败或启动失败记录为产品测试失败。修复后应先运行 `Quick`，再运行受影响套件。
