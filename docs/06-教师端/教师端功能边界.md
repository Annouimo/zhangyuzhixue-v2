# 章鱼智学 · 教师端功能边界

> 本文档定义教师端的角色定位、职责边界、页面清单、数据流与 API 需求、
> 技术方案决策（含与 Django Admin 端的职责划分）。
>
> 更新日期：2026-07-10 | 技术方案已终稿（学生 App + 轻量 Web 混合方案）

---

## 一、角色定位

| 维度 | 定位 |
|------|------|
| 用户 | 教学工作从事者（当前约 3 人，长期不会大幅增长） |
| 客户端 | 轻量教师 Web（浏览器访问）+ 学生 Flutter App 辅助浏览题库 |
| 核心任务 | 选题发布作业 + 查看学生完成情况 |
| 数据范围 | 可见全部班级和全部学生，不做权限隔离 |
| 与内容的关系 | 只消费内容（题库/讲义），不编辑内容 |

**核心原则：** 教师「选人、选题、发布、看结果」，不做内容编辑。

**技术方案概览：** 教师通过**学生 Flutter App** 浏览题库、创建组卷和阅读讲义（教师账号可登录学生端，讲义 API 对教师角色返回全部课程），组卷同步到服务端后，在**轻量 Web 端**发布为作业和管理学情。教师端的 Web 页面无离线/同步/版本管理能力，纯在线调 REST API。

## 二、职责边界

### 2.1 教师能做的

| 功能 | 说明 |
|------|------|
| 浏览题库并选题 | 登录学生 Flutter App，使用 paper_pick/paper_auto 筛选和勾选题目，保存为组卷 |
| 发布作业到班级 | Web 端选择已创建的组卷 → 设标题/截止日期 → 发布到目标班级 |
| 查看作业完成情况 | Web 端查看每个学生是否已做、正确率、提交详情 |
| 查看班级整体学情 | Web 端查看班级平均正确率、完成率、各题型表现汇总卡片 |
| 查看学生个人报告 | Web 端查看做题量、正确率趋势、薄弱知识点 |
| 发送催交通知 | Web 端催交（未来扩展） |
| 查看讲义 | 登录学生 App 查看（教师身份时可见全部课程，不按班级过滤） |
| 编辑个人资料 | Web 端编辑姓名、头像等 |

### 2.2 教师不能做的

| 功能 | 原因 | 替代方案 |
|------|------|---------|
| 编辑题目（题干/答案/解析/难度等） | 题库为平台统一资产，多人编辑易不一致 | 联系管理员在 Django Admin 修改 |
| 创建新题目 | 同上 | 联系管理员录入 |
| 编辑讲义内容 | 讲义 Markdown 为平台统一维护 | 通知管理员通过 Django Admin 更新 |
| 管理班级信息（增删班级） | 班级结构由管理员维护 | 联系管理员 |
| 管理学生账号 | 学生账号由管理员/系统导入 | 联系管理员 |
| 调整学生积分 | 仅管理员可手动调整 | 联系管理员 |
| 修改系统配置（版本号、公告等） | 运维权限 | 仅管理员可操作 |

### 2.3 讲义编辑的实操方案

教师使用 **Obsidian** 编写讲义 Markdown 文件（含 LaTeX 公式、分隔符 `<!-- pagebreak -->` 和 `<!-- reveal -->`），编写完成后发给管理员，由管理员在 Django Admin 的讲义编辑页面中录入保存。

## 三、教师端页面清单

教师端是 Web 页面，**无底部 Tab 导航**，页面间通过链接跳转：

```

           │  登录页      │
           └──────┬───────┘
                  │
          ┌───────▼────────┐
          │  教师端主页     │
          │  作业列表      │
          └───────┬────────┘
                  │
     ┌────────────┼────────────────┐
     ▼            ▼                ▼
┌──────────┐ ┌──────────┐ ┌──────────────┐
│ 发布作业  │ │ 作业详情  │ │ 班级概览      │
│ (选组卷→  │ │ (按学生  │ │ (汇总卡片)    │
│  设信息→  │ │  列状态) │ └──────┬───────┘
│  发布)    │ └──────────┘        │
└──────────┘                      ▼
                          ┌──────────────┐
                          │ 学生列表      │
                          │ (搜索/筛选)   │
                          └──────┬───────┘
                                 ▼
                          ┌──────────────┐
                          │ 学生详情      │
                          │ (个人报告)    │
                          └──────────────┘
```

### 3.2 页面列表

| 页面 | 路径 | 核心功能 |
|------|------|---------|
| **登录** | `/teacher/login.html` | 教师身份登录，JWT 认证 |
| **主页·作业列表** | `/teacher/` | 已发布作业列表，每项显示标题、班级、截止日期、完成率 |
| **发布作业** | `/teacher/publish.html` | 列出教师创建的组卷 → 选一个 → 设班级/截止日期 → 发布 |
| **作业详情** | `/teacher/detail.html?id=` | 按学生列出完成状态（已做/未做）、正确率，可进入学生详情 |
| **班级概览** | `/teacher/classes.html` | 所有班级汇总统计卡片：人数、总题量、平均正确率等 |
| **学生列表** | `/teacher/students.html` | 全校学生列表，可搜索/筛选，关键指标（题量、正确率）一目了然 |
| **学生详情** | `/teacher/student.html?id=` | 个人详细报告：做题历史、正确率趋势、薄弱知识点分布 |
| **关于** | `/teacher/about.html` | 版本信息、更新日志 |

### 3.3 核心业务流程：发布作业

```
学生 App 端（教师账号登录）
  paper_pick → 筛选 → 勾选题目 → 保存组卷
  ↓
  组卷通过 sync_queue 自动推送到服务端（custom_paper + paper_question）
  ↓

Web 端
  登录 /teacher/
  ↓
  点「发布作业」
  ↓
  选择组卷（从已 sync 的组卷列表中选）
  ↓
  设标题（默认 = 组卷名）/ 截止日期 / 可选说明
  ↓
  勾选目标班级（默认全选，显示各班级人数）
  ↓
  确认 → POST /api/v1/teacher/assignments/
  ↓
  成功 → 回到作业列表
```

### 4.2 教师专属 API 端点

| 方法 | 端点 | 说明 |
|------|------|------|
| `GET` | `/api/v1/teacher/assignments/` | 作业列表（含完成率等统计信息） |
| `POST` | `/api/v1/teacher/assignments/` | 创建并发布作业（含组卷ID、班级列表、截止日期） |
| `GET` | `/api/v1/teacher/assignments/{id}/` | 作业详情（按学生列出完成状态） |
| `DELETE` | `/api/v1/teacher/assignments/{id}/` | 撤销/删除作业 |
| `PATCH` | `/api/v1/teacher/assignments/{id}/` | 修改截止日期等 |
| `GET` | `/api/v1/teacher/papers/` | 拉取教师创建的组卷列表（含题数/创建时间） |
| `GET` | `/api/v1/teacher/classes/` | 班级列表（含学生人数、平均正确率等概览统计） |
| `GET` | `/api/v1/teacher/students/` | 学生列表（可搜索/筛选，含关键指标） |
| `GET` | `/api/v1/teacher/students/{id}/` | 学生详情（做题历史、正确率趋势、薄弱知识点） |
| `POST` | `/api/v1/teacher/assignments/{id}/remind/` | 催交（推送通知给未交学生，未来实现） |

> **关于同步机制：** 仅学生 App → 服务端方向有 sync。组卷通过 sync_queue 推送（`custom_paper` + `paper_question` entity_type），教师 Web 端通过 `GET /teacher/papers/` API 拉取已推送的组卷。Web 端不写本地数据库，写操作（发布作业等）直接调 API。

### 4.3 教师端与学生端共用的端点

| 端点 | 说明 |
|------|------|
| `/api/v1/auth/*` | 登录/Token 刷新 |
| `/api/v1/lectures/courses/` | 讲义课程列表（教师身份时返回全部课程，不按班级过滤） |
| `/api/v1/lectures/courses/{courseId}/chapters/` | 章节目录（教师身份时返回全部章节） |
| `/api/v1/lectures/chapters/{chapterId}/content/` | 讲义内容（教师身份时返回） |

## 五、认证与角色校验

### 5.1 角色体系

系统共有三种角色，由服务端统一管理：

| 角色 | 登录端 | 账号创建方式 |
|------|--------|-------------|
| `student` | 学生 Flutter App | 自助注册（需邀请码） |
| `teacher` | 学生 Flutter App（浏览题库 + 讲义阅读）+ 教师 Web（管理学情） | 管理员在 Django Admin 手动创建 |
| `admin` | Django Admin 内置登录 | 管理员创建 |

### 5.2 技术决策：登录不做角色校验

**背景：** 教师需要在学生 Flutter App 中浏览题库和创建组卷（复用 paper_pick/paper_auto），但学生端登录接口按原有设计会因 `app_type: "student"` 而拒绝教师账号。

**决策：** 登录接口取消 `app_type` 的角色校验。`app_type` 仅用于统计和区分登录来源，**不做准入判断**。角色权限后移至具体 API 端点通过 `IsTeacher` / `IsStudent` 权限类控制。

**影响分析：**

| 场景 | 能否正常工作 | 说明 |
|------|:----------:|------|
| 教师用 `app_type=student` 登录学生 App | ✅ | App 内可浏览题库、创建组卷和阅读讲义（讲义 API 已对教师角色放行，返回全部课程）；提交/评分等学生专属 API 受 `IsStudent` 保护，教师调不通 |
| 教师用 `app_type=teacher` 登录教师 Web | ✅ | Web 端正常调教师 API |
| 学生用 `app_type=student` 登录学生 App | ✅ | 完全不变 |
| 管理员登录 | ❌ 仍拒绝 | 身份全无变化，管理员无 Student/Teacher 记录，任何 `app_type` 均拒绝 |

### 5.3 sync/push 的 entity_type 分发

教师推送组卷（`custom_paper` / `paper_question`）时，服务端需按 entity_type 区分数据归属：

- **`custom_paper` / `paper_question`**：使用 JWT token 中的 `user_id`（不是 `student_id`），教师账号也能正常推送
- **`submission` / `step_feedback` / `card_feedback`**：使用 `student_id`（从 Student 表解析），教师账号不会产生此类数据

### 5.4 JWT 方案

| 组件 | 方案 |
|------|------|
| 库 | `djangorestframework-simplejwt` |
| Access Token | 24 小时 |
| Refresh Token | 30 天 |
| 存储 | Flutter 端 SharedPreferences，Web 端 localStorage |

### 5.5 登录流程

```
POST /api/v1/auth/login/
{
  "username": "...",
  "password": "***",
  "app_type": "student"   // 或 "teacher"，仅区分来源不做校验
}

→ 服务端校验：
   1. 用户名密码验证
   2. 查询角色（Student/Teacher 表是否存在）
   3. 管理员（无 Student/Teacher 记录）→ 拒绝
   4. 通过 → 生成 JWT pair + 返回用户信息（含 role 字段）
```

**启动恢复登录（Flutter App 端）：**
```
App 启动 → 读 SharedPreferences
  ├── access token 存在且未过期 → 直接进首页
  ├── access 过期但 refresh 存在 → POST /api/auth/refresh/ → 新 access → 进首页
  └── 都无或都过期 → 进登录页
```

### 5.6 注册（仅限学生）

教师账号由管理员在 Django Admin 手动创建。注册端点不变，仍仅限学生。

### 5.7 登出

Flutter 端清除 SharedPreferences，Web 端清除 localStorage。服务端无额外操作（JWT 无状态）。

### 5.8 密码找回

当前规模下不做自助找回。联系管理员通过 Django Admin 重置密码即可。

## 八、教师端数据策略

教师端的两个客户端使用完全不同的数据策略：

| 数据类型 | 学生 App（教师端使用） | 教师 Web 端 |
|---------|----------------------|------------|
| 题库（assets.db） | 同学生端，整体下载替换 | **无。** 题库浏览在学生 App 中完成 |
| 讲义（lectures.db） | 同学生端（教师身份时可见全部课程） | **无。** 讲义阅读在 Student App 中完成 |
| 教师操作数据 | 组卷数据通过 sync_queue 推送到服务端 | 纯在线，直接调 API，无本地持久化 |
| 班级/学生数据 | — | API 实时拉取，可简单缓存（localStorage） |

**教师 Web 端不需要 sync_queue、不需要 assets.db、不需要 lecture.db。** 它是一个纯静态的"仪表盘"，数据全部通过 REST API 实时获取。
