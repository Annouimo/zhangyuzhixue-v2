# 章鱼智学 · 教师端功能边界

> 本文档定义教师端的角色定位、职责边界、页面清单、数据流与 API 需求、
> 技术方案决策（含与 Django Admin 端的职责划分）。
>
> 更新日期：2026-07-15 | 技术方案已终稿（独立教师 Flutter App + 轻量 Web 混合方案）

---

## 一、角色定位

| 维度 | 定位 |
|------|------|
| 用户 | 教学工作从事者（当前约 3 人，长期不会大幅增长） |
| 客户端 | 独立教师 Flutter App（题库浏览/讲义阅读/选题导出JSON）+ 轻量教师 Web（发布作业/学情管理） |
| 核心任务 | 浏览题库备课 → 选题 → 发布作业 → 查看学生完成情况 |
| 数据范围 | 可见全部班级和全部学生，不做权限隔离 |
| 与内容的关系 | 只消费内容（题库/讲义），不编辑内容 |

**核心原则：** 教师「选人、选题、发布、看结果」，不做内容编辑。

**技术方案概览：** 教师通过**独立 Flutter App** 浏览题库和阅读讲义（无需登录），选题后导出 JSON 粘贴到 **Web 端** 发布为作业和管理学情。教师端 Flutter App 无服务端通信（除数据库版本检查与下载外），Web 端无离线/同步/版本管理能力，纯在线调 REST API。

## 二、职责边界

### 2.1 教师能做的

| 功能 | 说明 |
|------|------|
| **浏览题库并选题** | 独立 Flutter App 中筛选和浏览题目（含完整选项/答案/解析/解法步骤），勾选后导出 JSON |
| **阅读讲义** | 独立 Flutter App 中阅读讲义（Markdown + LaTeX，支持翻页和逐段展开） |
| **更新题库/讲义数据** | 独立 Flutter App 启动时自动检查服务端版本，下载最新 .db.gz 替换本地数据库 |
| **发布作业到班级** | Web 端导入 Flutter App 导出的 JSON 选题 → 设标题/截止日期 → 发布到目标班级 |
| **查看作业完成情况** | Web 端查看每个学生是否已做、正确率、提交详情 |
| **查看班级整体学情** | Web 端查看班级平均正确率、完成率、各题型表现汇总卡片 |
| **查看学生个人报告** | Web 端查看做题量、正确率趋势、薄弱知识点 |
| **发送催交通知** | Web 端催交（未来扩展） |
| **编辑个人资料** | Web 端编辑姓名、头像等 |

### 2.2 教师不能做的

| 功能 | 原因 | 替代方案 |
|------|------|---------|
| 编辑题目（题干/答案/解析/难度等） | 题库为平台统一资产，多人编辑易不一致 | 联系管理员在 Django Admin 修改 |
| 创建新题目 | 同上 | 联系管理员录入 |
| 编辑讲义内容 | 讲义 Markdown 为平台统一维护 | 通知管理员通过 Django Admin 更新 |
| 管理班级信息（增删班级） | 班级结构由管理员维护 | 联系管理员 |
| 管理学生账号 | 学生账号由管理员/系统导入 | 联系管理员 |
| 调整学生积分 | 仅管理员可手动调整 | 联系管理员 |
| 修改系统配置（版本号、公告等） | 运维权限 | 仅管理员可操作 |

### 2.3 讲义编辑的实操方案

教师使用 **Obsidian** 编写讲义 Markdown 文件（含 LaTeX 公式、分隔符 `<!-- pagebreak -->` 和 `<!-- reveal -->`），编写完成后发给管理员，由管理员在 Django Admin 的讲义编辑页面中录入保存。

## 三、教师端页面清单

| 客户端 | 用途 | 技术方案 |

### 4.2 核心原则

| 维度 | 原则 |
|------|------|
| **无需登录** | App 打开直接进入首页，不需要注册/登录/Token |
| **无用户数据** | 不读写 user.db，没有用户数据、没有积分、没有做题记录 |
| **仅 2 条 HTTP 请求** | 版本检查 API（无需认证）+ 文件下载 |
| **离线可用** | 数据库一旦下载完成，题库和讲义全部本地离线浏览 |
| **筛选增强** | 教师端筛选面板保留学生端全部维度（年份/地区/题型/概念标签树/知识卡片组/难度/计算量），增加排序功能（按年份、难度、题型、题号） |
| **代码复用** | 从学生 Flutter App 复制 assets_db schema、DAO、Repository、Widget、页面 |

### 4.3 数据库更新机制

复用学生端已有的 `UpdateManager` 流程：

```
App 启动 → 检查本地 data_version 缓存（SharedPreferences）
  ↓
并发调用两个版本接口（无需认证）：
  ├─ GET /api/v1/sync/qbank/version/     → 检查 assets.db 版本
  └─ GET /api/v1/sync/courses/version/   → 检查 courses.db 版本
  ↓
data_version > 本地缓存？
  ├─ 否 → 直接进首页
  └─ 是 → 右上角横幅通知 [有新版本]
       ├─ 点击 → 下载 .db.gz
       ├─ sha256 校验
       ├─ gzip 解压
       └─ 替换本地 .db → 刷新界面
```

> **注意：** 教师端不做强制更新弹窗（版本落后 3 个以上也不强制），因为教师不需要做题/登录，旧版只是看不到新题目，不影响使用。此决策与设计文档 docs/02-数据/更新机制.md 的学生端规则不同。
>
> **首次启动：** 教师 App 安装包自带基础版本 `assets.db` 和 `courses.db`（与学生端同源打包），首次启动即开即用，无需联网下载。

### 4.4 JSON 导出格式

```json
{
  "version": 1,
  "questionIds": [101, 205, 378, 412, 523],
  "selectedAt": "2026-07-15T10:30:00",
  "totalCount": 5
}
```

> JSON 仅携带题目 ID，不包含题目内容。教师在 Flutter App 中可通过「预览」页面确认选题内容后再导出。

教师 Web 端的发布作业页接收此 JSON，解析后调 `POST /api/v1/teacher/assignments/`（传 `question_ids` 替代 `paper_id`）。

## 六、数据流与 API

### 6.1 整体数据流

```
┌────────────────────────────────────────────────────────────────┐
│  教师 Flutter App（无需登录）                                    │
│                                                                │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────────────────┐ │
│  │ UI 层     │  │ Repository│  │ 本地 SQLite                  │ │
│  │ (Widget)  │◀─│ (拼装数据)  │◀─│ ├─ assets.db（题库，只读）   │ │
│  └──────────┘  └──────────┘  │ └─ courses.db（讲义，只读）    │ │
│                               │        ↑                      │ │
│                               │   UpdateManager（版本检查更新）│ │
│                               └──────────────────────────────┘ │
│  JSON 导出 → 剪贴板/文件                                         │
└─────────────────────────────────┬──────────────────────────────┘
                                  │ JSON 粘贴
                                  ▼
┌────────────────────────────────────────────────────────────────┐
│  教师 Web 端（landing/teacher/，nginx 直出）                    │
│                                                                │
│  纯静态 HTML/CSS/JS，直接调 REST API（无本地数据库/无缓存）      │
│  页面列表见 3.3 节                                              │
│                                                                │
│  调用的 REST API：                                               │
│  ├─ /api/v1/teacher/assignments/     — 作业 CRUD               │
│  ├─ /api/v1/teacher/assignments/{id}/ — 作业详情/删除/修改     │
│  ├─ /api/v1/teacher/papers/          — 组卷列表（兼容保留）      │
│  ├─ /api/v1/teacher/classes/         — 班级列表                │
│  ├─ /api/v1/teacher/students/        — 学生列表                │
│  └─ /api/v1/teacher/students/{id}/   — 学生详情                │
└────────────────────────────────────────────────────────────────┘
```

### 6.2 教师 Flutter App 独有的 API

| 方法 | 端点 | 认证 | 说明 |
|------|------|:----:|------|
| `GET` | `/api/v1/sync/qbank/version/` | ❌ 无需认证 | 检查题库版本 |
| `GET` | `/api/v1/sync/courses/version/` | ❌ 无需认证 | 检查讲义版本 |
| `GET` | `/static/db/qbank_v{ver}.db.gz` | ❌ 无需认证 | 下载题库数据库包 |
| `GET` | `/static/db/courses_v{ver}.db.gz` | ❌ 无需认证 | 下载讲义数据库包 |

> 教师 Flutter App **不做任何其他 API 调用**。不调 auth、不调 sync、不调 push/pull。

### 6.3 教师 Web 端专属 API 端点（保持不变）

| 方法 | 端点 | 说明 |
|------|------|------|
| `GET` | `/api/v1/teacher/assignments/` | 作业列表（含完成率等统计信息） |
| `POST` | `/api/v1/teacher/assignments/` | 创建并发布作业（新增支持 `question_ids` 参数） |
| `GET` | `/api/v1/teacher/assignments/{id}/` | 作业详情（按学生列出完成状态） |
| `DELETE` | `/api/v1/teacher/assignments/{id}/` | 撤销/删除作业 |
| `PATCH` | `/api/v1/teacher/assignments/{id}/` | 修改截止日期等 |
| `GET` | `/api/v1/teacher/papers/` | 拉取教师创建的组卷列表（兼容保留） |
| `GET` | `/api/v1/teacher/classes/` | 班级列表 |
| `GET` | `/api/v1/teacher/students/` | 学生列表 |
| `GET` | `/api/v1/teacher/students/{id}/` | 学生详情 |
| `POST` | `/api/v1/teacher/assignments/{id}/remind/` | 催交 |

### 6.4 教师端与学生端共用的端点（保持不变）

| 端点 | 说明 |

## 七、认证与角色校验

### 7.1 角色体系

| 角色 | 登录端 | 账号创建方式 |
|------|--------|-------------|
| `student` | 学生 Flutter App | 自助注册（需邀请码） |
| `teacher` | 教师 Web 端（管理学情） | 管理员在 Django Admin 手动创建 |
| `admin` | Django Admin 内置登录 | 管理员创建 |

> **教师 Flutter App 不使用教师账号。** 它没有登录功能，不校验角色，不发送 Token。纯粹是一个本地数据库阅读器。

### 7.2 教师 Web 端认证

沿用现有 JWT 认证方案，无变化。

## 八、需要新增的服务端改动

### 8.1 不新增模型

### 8.2 API 扩展

`POST /api/v1/teacher/assignments/` 新增 `question_ids` 参数支持：

```json
{
  "question_ids": [101, 205, 378],
  "title": "立体几何小测",
  "deadline": "2026-07-20",
  "class_ids": [1, 2],
  "description": ""
}
```

当 `question_ids` 存在时，跳过 `paper_id` 逻辑，直接从 qbank 按 ID 拉取题目创建作业。
