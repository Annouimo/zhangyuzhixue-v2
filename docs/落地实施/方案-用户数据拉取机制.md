# 用户数据拉取机制 · 实施方案

> 对应讨论：2026-07-11 着陆页讨论中发现的用户数据跨设备问题
> 状态：**待批示** | 提案人：Hermes Agent

---

## 一、问题背景

当前同步机制是单向的（Client → Server），用户数据只能推不能拉。

| 场景 | 后果 |
|------|------|
| 卸载重装 | user.db 清空，本地历史记录丢失 |
| 换新设备 | user.db 为空，看不到任何做题记录 |
| 多设备切换 | 看不到另一台设备上的做题记录 |

服务器上有完整数据，但客户端没有途径拿回来。

---

## 二、方案设计

### 2.1 核心思路

复用已有的更新机制（assets.db / lectures.db 的版本检查 + 下载 + 校验 + 替换）来同步用户数据。

### 2.2 数据流

```
登录成功
  │
  ├─ ① 推送本地 sync_queue（登录前可能离线做了题）
  │
  ├─ ② 调用 GET /api/v1/sync/user/pull/
  │    服务器在内存中构建该学生的 user.db → gzip
  │    → 存到临时目录（5分钟 TTL）
  │    → 返回 JSON: { download_url, checksum, size_bytes, version }
  │
  ├─ ③ 客户端调 UpdateManager.downloadAndReplace()
  │    下载 .db.gz → 解压 → checksum 校验 → 关 user.db 连接
  │    → 覆盖文件 → 重开连接 → 更新版本号 → 清理临时文件
  │
  └─ ④ 进入首页

退出登录
  │
  ├─ ① 推送 sync_queue（有网则推，无网静默跳过）
  ├─ ② 清空 user.db + sync_queue
  └─ ③ 清除 token + 版本缓存
```

### 2.3 触发条件

- **每次输入密码登录**（A 方案）：登录成功 → `SyncManager.onLogin()`
- **登录后正常使用**：不触发，直接使用本地 user.db
- **手动触发**：关于页「同步」按钮 → `SyncManager.forcePull()`

## 三、服务端实现

### 3.1 新增端点

```
GET /api/v1/sync/user/pull/
认证：Bearer token（必须）
角色限制：仅 student
```

### 3.2 响应格式

```
Status: 200 OK
Content-Type: application/gzip
X-Checksum-Sha256: <sha256 of gzipped content>
X-Size-Bytes: <uncompressed .db size in bytes>
X-Data-Version: <int>

Body: gzip 压缩的 user.db 文件
```

### 3.3 生成逻辑（Python sqlite3）

```python
def pull_user_db(request):
    student = request.user.student
    if not student:
        return PermissionDenied

    # 临时 .db 文件
    fd, tmp = tempfile.mkstemp(suffix='.db')
    os.close(fd)
    conn = sqlite3.connect(tmp)
    conn.executescript(USER_DB_SCHEMA)

    # 写入该学生的全部数据
    _write_submissions(conn, student)
    _write_step_feedbacks(conn, student)
    _write_card_feedbacks(conn, student)
    _write_ratings(conn, student)
    _write_custom_papers(conn, student)
    _write_points(conn, student)
    conn.commit()
    conn.close()

    # gzip
    gz = tmp + '.gz'
    with open(tmp, 'rb') as f_in:
        data = f_in.read()
    gz_data = gzip.compress(data)
    with open(gz, 'wb') as f_out:
        f_out.write(gz_data)

    # checksum
    checksum = hashlib.sha256(gz_data).hexdigest()
    size = os.path.getsize(tmp)

    response = HttpResponse(gz_data, content_type='application/gzip')
    response['X-Checksum-Sha256'] = checksum
    response['X-Size-Bytes'] = str(size)
    response['X-Data-Version'] = '1'

    # 清理
    os.unlink(tmp)
    os.unlink(gz)

    return response
```

### 3.4 需要导出的表

| 表 | 数据量估计 | 说明 |
|----|----------|------|
| submission | ~1KB/条 | 含 1000 道题约 1MB |
| submission_detail | ~200B/条 | 同上 |
| step_feedback | ~150B/条 | 解答题步数反馈 |
| card_feedback | ~100B/条 | 知识卡片反馈 |
| question_rating | ~150B/条 | 每道题评分 |
| custom_paper | ~500B/条 | 自组卷 |

| user_profile | ~200B/条 | 个人资料 |
| points_transaction | ~100B/条 | 积分记录 |

**重度用户总量估计：** ~500KB 未压缩，~200KB gzip 后。

### 4.2 DatabaseProvider 新增方法

```dart
// data/database/database_provider.dart

/// 替换 user.db（与 replaceAssetsDb / replaceLecturesDb 同构）
Future<void> replaceUserDb(String newPath) async {
  await _appDb?.close();
  final target = File('${_dbDirPath!}/user.db');
  await File(newPath).copy(target.path);
  _appDb = AppDatabase(NativeDatabase(target));
  await _appDb!.customStatement('PRAGMA journal_mode=WAL');
}
```

### 4.3 SyncManager 新增方法

```dart
// data/sync/sync_manager.dart

class SyncManager {
  /// 登录后调用：推送→拉取→替换
  Future<void> onLogin() async {
    await pushNow();                                    // ① 推送本地积压

    // ② 请求 pull 端点获取下载信息
    final pullInfo = await _api.fetchUserPullInfo();
    // pullInfo: { download_url, checksum, size_bytes, version }

    // ③ 复用 UpdateManager 的下载替换流程
    await _updateManager.downloadAndReplace(
      type: 'user',
      url: pullInfo.downloadUrl,
      expectedChecksum: pullInfo.checksum,
      newVersion: pullInfo.version,
    );
  }

  /// 退登前调用：推送→清库
  Future<void> onLogout() async {
    try {
      await pushNow();                                  // ① 尝试推送
    } catch (_) {
      // 无网络，静默跳过
    }
    await _dbProvider.clearUserDb();                    // ② 清空 user.db
    await clearQueue();                                 // ③ 清空 sync_queue
  }

  /// 手动强制拉取（关于页按钮）
  Future<void> forcePull() async {
    final pullInfo = await _api.fetchUserPullInfo();
    await _updateManager.downloadAndReplace(
      type: 'user',
      url: pullInfo.downloadUrl,
      expectedChecksum: pullInfo.checksum,
      newVersion: pullInfo.version,
    );
  }
}
```

## 五、更新机制复用情况

| 阶段 | 复用哪里 |
|------|---------|
| 下载 .db.gz | `UpdateManager.downloadAndReplace()` — 原样调用 |
| 校验 checksum | 同上 |
| 关连接 → 覆盖 → 重开 | `DatabaseProvider.replaceUserDb()` — 与 `replaceAssetsDb` 同构 |
| 临时文件清理 | `downloadAndReplace()` 内置清理 |
| 新增代码 | `UpdateManager` +1 行分支，`DatabaseProvider` +6 行方法（照抄 replaceLecturesDb） |

**Flutter 端彻底零重复逻辑**——所有下载替换的脏活都在 UpdateManager 里，SyncManager 只负责触发。

## 六、边界与异常处理

| 场景 | 处理 |
|------|------|
| **登录时 pull 网络失败** | 不阻塞登录 → 进入首页 → 左下角 SnackBar "数据同步失败，可在关于页手动重试" |
| **pull 下数据但 checksum 不匹配** | 扔异常，不替换 user.db，下次登录重新拉 |
| **退登前 push 网络失败** | 静默跳过，不清队列，下次启动自动重推 |
| **用户离线做题后登录** | ① pushNow 将离线数据推上去 → ② pull 拉回全部（含刚推的）→ 数据完整 |
| **极大数据量（重度用户）** | ~200KB gzip，秒级完成，无需额外处理 |
| **并发登录（两台设备同时登）** | 各自独立拉取，服务器上的数据一致 |
