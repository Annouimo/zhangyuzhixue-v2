# 章鱼智学 · 服务端架构设计

> 本文档定义新版 Django 服务端（纯 API + Admin）的架构设计、App 划分、模型映射、认证方案与部署策略。
>
> **状态**：设计阶段，未落地。
>
> **前置文档**：[数据库结构设计.md](数据库结构设计.md) — 所有表定义以此为源。

---

## 一、定位

| 维度 | 定位 |
|------|------|
| 角色 | 纯 API 后端 + Django Admin 管理端 |
| 客户端 | Flutter App（学生端 + 未来教师端）|
| 不做 | 网页前端（学生端/教师端均无 Web 界面）|
| 部署 | 单一 Django 进程 + gunicorn + nginx + Cloudflare Tunnel |

**核心原则：** 服务端只做三件事——认证鉴权、数据接收与持久化、管理员操作入口。

> **不再使用的旧版字段**：`phone`、`real_name`、`student_id`、`gaokao_year` — 这些移至 Student。

#### Student 模型

```python
class Student(models.Model):
    """学生身份，包含全部学生字段。"""
    user = OneToOneField(User, on_delete=CASCADE, primary_key=True)
    class_group = ForeignKey(ClassGroup, on_delete=SET_NULL, null=True)
    phone = CharField(max_length=11, unique=True, null=True, blank=True)
    real_name = CharField(max_length=50)
    student_id = CharField(max_length=20, unique=True, null=True, blank=True)
    gaokao_year = IntegerField(null=True, blank=True)
```

#### Teacher 模型

```python
class Teacher(models.Model):
    """教师身份，最小模型。
    当前 3 人规模，不需要 phone/real_name 等字段。
    """
    user = OneToOneField(User, on_delete=CASCADE, primary_key=True)
    name = CharField(max_length=50)
```

## 四、认证方案

### 4.1 角色体系

| 角色 | 标识 | 登录端 | 创建方式 |
|------|------|--------|---------|
| `student` | `Student` 表存在 | 学生 Flutter App | 自助注册（需邀请码）|
| `teacher` | `Teacher` 表存在 | 教师 Flutter App | 管理员通过 Django Admin 创建 |
| `admin` | `User.is_staff = True` | Django Admin | 管理员创建 |

### 4.2 JWT 方案

| 组件 | 方案 |
|------|------|
| 库 | `djangorestframework-simplejwt` |
| Access Token | 24 小时 |
| Refresh Token | 30 天 |
| 存储 | SharedPreferences（Flutter 端）|

### 4.3 端点

| 方法 | 端点 | 说明 |
|------|------|------|
| `POST` | `/api/auth/login/` | 登录，接收 `{"username", "password", "app_type"}` |
| `POST` | `/api/auth/register/` | 注册（仅 student），需邀请码 |
| `POST` | `/api/auth/refresh/` | Token 刷新 |

### 4.4 权限类

DRF 的 `IsAuthenticated` + 自定义 `IsStudent` / `IsTeacher` 权限类，用于教师端 API 的鉴权。

## 五、数据库选型

### 决策：SQLite (WAL)

| 维度 | 选型 |
|------|------|
| 引擎 | SQLite 3 |
| 模式 | WAL（Write-Ahead Logging）|
| 配置 | `timeout=20`，`transaction_mode='IMMEDIATE'` |
| 启用 | Django signal `connection_created` 执行 `PRAGMA journal_mode=WAL;` |

沿用旧版的 SQLite 配置已验证可行。当前用户规模极小（~3 教师 + 数十学生），服务端写入为低频批量推送，SQLite 的串行写不构成瓶颈，运维成本为零。
