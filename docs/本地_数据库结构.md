# 🗂 本地数据库结构设计（drift）

> 本文档定义 Flutter 客户端 SQLite 数据库的完整 Schema，供 drift DAO 代码生成和 Repository 层实现使用。

---

## 一、数据库划分

```
本地 SQLite
│
├── assets.db（预置只读）
│   生命周期：随 App 版本整体替换
│   路径：首次启动从 assets/ 复制到 getApplicationDocumentsDirectory()
│   └─ 版本检查：GET /api/sync/question-bank-version
│
└── user.db（用户读写）
    生命周期：跨版本保留，登出清空
    路径：getApplicationDocumentsDirectory()
```

**为什么拆两个库？**
- assets.db 随发版替换（App 更新时覆盖），user.db 跨版本留存
- 合在一个库中，替换 assets 表时容易误清用户数据
- Drift 支持同时挂两个 `DriftDatabase` 实例，Repository 按需读

## 二、Assets 预置库（10 张表）

所有表均**只读**。数据由构建脚本从服务器 Django DB 导出 → 转换 → 生成 `.db` 文件，随 App 打包。

### 2.1 题库核心

#### a1. `question`（题目主表）

与服务器 `BaseQuestion` + `ChoiceExt` + `ConceptTag` M2M 对应，仅对**必然一起读的字段**做 JSON 聚合。

| 字段 | 类型 | 约束 | 映射源 |
|---|---|---|---|
| `id` | INTEGER | PK | BaseQuestion.id |
| `year` | INTEGER | | BaseQuestion.year |
| `exam_type` | TEXT | | 考试类型 |
| `region` | TEXT | | 地区 |
| `number` | TEXT | | 题号 |
| `question_type` | TEXT | NOT NULL | 选择/填空/解答 |
| `difficulty` | REAL | 0-10 | |
| `calculation` | REAL | 0-10 | |
| `stem` | TEXT | NOT NULL | 纯 Markdown，**不含 img 标签** |
| `images` | TEXT | | **JSON list：** `["一模/2024/海淀/q17.webp"]`<br>原因：必随 stem 一起读，不会单独 WHERE 过滤 |
| `options` | TEXT | | **JSON map（仅选择题）：** `{"A":"...","B":"..."}`<br>原因：仅选择题有，必随 question 一起读 |
| `default_score` | REAL | | 参考分值 |
| `concept_tags` | TEXT | NOT NULL | **JSON list：** `["函数","导数"]`<br>原因：筛选在 Dart 层做，无需 SQL WHERE |
| `answer` | TEXT | | 正确答案 |

#### a2. `concept_tag`（概念标签树）

独立表保留，因为筛选面板需要按层级展示。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PK | |
| `name` | TEXT | NOT NULL, UNIQUE | |
| `parent_id` | INTEGER | FK → concept_tag.id, nullable | 自关联树形 |

题目上 `concept_tags` 字段存的是 `name` 数组（而非 ID 数组），读取标签名无需 JOIN。

#### a3. `knowledge_card`（知识卡片）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PK | |
| `title` | TEXT | NOT NULL | |
| `content` | TEXT | NOT NULL | 含 LaTeX |

复用表。`solution_step` 中存的是 `card_titles` JSON list，通过 title 匹配。

#### a4. `solution_step`（解题步骤）

跳过服务器 `SubQuestion` → `SolutionMethod` 两层中间表，直接 `question_id` → `step`。

**理由**：UI 展示步骤时不需要按「解法」分组或按「小题」过滤。如果未来需要按解法筛选，再考虑加 `method_id` 字段。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PK | |
| `question_id` | INTEGER | FK → question.id, NOT NULL | |
| `sub_question_index` | INTEGER | DEFAULT 0 | 小题索引（0=无小题），替代 SubQuestion 层 |
| `step_number` | INTEGER | NOT NULL | 从 1 开始 |
| `method_name` | TEXT | | 解法名称（保留字段，展示用，如"代数法"） |
| `title` | TEXT | NOT NULL | 步骤标题 |
| `content` | TEXT | NOT NULL | 解析正文，含 LaTeX |
| `card_titles` | TEXT | | **JSON list：** `["函数单调性","奇偶性判定"]`<br>原因：仅展示用，不会独立查询 |

### 3.8 同步队列

#### u15. `sync_queue`（同步队列表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PK | 自增 |

> **推送粒度**：一道题做完后，`submission` + `submission_detail` + `step_feedback`(0~N) + `card_feedback`(0~N) 组包为一条推送。`question_rating` 单独推送。`custom_paper` + `custom_paper_question` 组包推送。

## 四、跨库关联说明

```
assets.db              user.db
┌───────────┐         ┌──────────────────┐
│ question   │◄────────│ submission_detail│
│ .id        │  question_id  .question_id│
├───────────┤         ├──────────────────┤
│ concept_tag│         │ step_feedback    │
│ .id  .name │         │ .question_id     │
├───────────┤         ├──────────────────┤
│ knowledge_ │         │ card_feedback    │
│ card       │         │ .card_title      │
├───────────┤         ├──────────────────┤
│ achievement│◄────────│ student_achievement│
│ _def       │  code   │ .achievement_code│
└───────────┘         └──────────────────┘
```

**不声明 SQL 级外键**（SQLite 不支持跨文件 FK），由 Repository 代码保证引用一致性。

## 五、字段映射速查

| 服务器 DB 表 | 服务器字段 | 本地表 | 本地字段 | 说明 |
|---|---|---|---|---|
| BaseQuestion | stem（含 img） | question | stem（纯 MD）+ images（JSON） | 构建脚本提取 img |
| BaseQuestion | — | question | options（JSON） | 从 ChoiceExt 合并 |
| BaseQuestion → ConceptTag M2M | — | question | concept_tags（JSON） | 构建脚本查 M2M 填入 |
| SolutionMethod + SolutionStep | — | solution_step | 跳过 SubQuestion 层 | sub_question_index 区分小题 |
| Course | — | course | 一致 | |
| — | — | chapter | 新增，构建脚本生成 | 服务器尚未有 |
| Lecture | file_url | lecture | blocks（JSON）| 构建脚本解析文件内容 |
| AchievementDef | 一致 | achievement_def | 一致 | 预置 |
| — | — | sync_queue | 本地独有 | 服务器不需要 |

## 六、不进入本地 DB 的数据

| 数据 | 原因 | 替代方案 |
|---|---|---|
| `ClassGroup` / `ClassCourse` / `ClassCourseAssignment` | 学期动态数据 | API 返回，缓存到 SharedPreferences 或 JSON 文件 |
| `PageSatisfactionFeedback` | 纯服务端 | 直接 POST |
| `UserPreference`（ContentType 模式） | 本地用不上泛型外键 | 不用 |
| 审计日志 | 纯服务器 | 不用 |
| 用户密码/token | 安全原因 | SharedPreferences |
