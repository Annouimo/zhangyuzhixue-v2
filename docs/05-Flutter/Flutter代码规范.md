# 章鱼智学 · Flutter 代码规范  > 本文档定义 Flutter 端 Repository 层规范、页面 Dart 文件组织、Widget 复用规则、路由方案及编译常量规范。  ---  ## 一、Repository 层规范  ### 1.1 职责  Repository 为 UI 层提供组合好的数据对象，不直接暴露数据库表结构。  ``` ❌ 错误：AssignmentRepository.getAll()          + ClassCourseAssignmentRepository.getByXxx()          + CourseRepository.getById()    → UI 层自己 join 3 张表  ✅ 正确：AssignmentRepository.getPending()    → 返回已经包含 title/courseName/doneCount/deadline 等所有字段的对象 ```  ### 1.2 与数据库模型的关系  ``` Drift Table (存)   →  数据类 = 数据库表的一行，含主键/外键/原始字段 Repository (用)    →  数据类 = UI 需要的样子，已拼装/已计算 ```  两者用途不同，各自独立。Repository 方法内部负责：查 DB → JOIN/计算 → 拼装 → 返回 Repository 模型。  ### 1.3 简单/复杂分离  Repository 文件中的方法分为两类：  | 类型 | 特征 | 维护频率 | 涉及文件 | |------|------|---------|---------| | **简单方法** | 直接读写本地 db，无额外计算 | 写一次不再动 | 全部 13 个文件 | | **复杂算法** | 需聚合/过滤/推荐/状态计算 | 算法持续迭代 | 5 个文件尾部私有类 |  复杂逻辑写在文件尾部的私有类中（如 `_PointsCalculator`），**仅供本文件 Repository 内部调用**，不对外暴露。页面开发者只需 import Repository 类，不需要知道私有类的存在。  ```dart class ExamRepository {   // 简单方法（直接读写本地 db）   static Future<List<ExamSummary>> getMyExams() async { ... }    // 复杂方法（委托给私有类）   static Future<PoolStats> getPoolStats(SearchFilters f) async {     return _ExamFilterEngine().compute(f);   } }  // 文件尾部私有类 class _ExamFilterEngine { ... } ```  ### 1.4 实现文件  见 `Repository/` 目录下的 13 个 Dart 文件。每个文件包含 Repository 类 + 数据模型类，5 个文件尾部附私有算法类。  | 文件 | Repository | data-db 前缀 | 对应页面 | 尾部算法类 | |------|------------|-------------|---------|-----------| | `auth_repository.dart` | AuthRepository | `auth.*` | login, register | — | | `assignment_repository.dart` | AssignmentRepository | `assign.*` | homework_list, homework_detail, index(待办数) | — | | `lecture_repository.dart` | LectureRepository | `lecture.*`（getContent 返回 LectureContent，解析后 data-db 为 `lecture.getContentParsed.*`） | lecture_courses, lecture_chapters, lecture_content | — | | `question_repository.dart` | QuestionRepository | `question.*` | solve-choice/fill/solve(题干), paper_quicklook(做题动作) | — | | `progress_repository.dart` | ProgressRepository | `progress.*` | solve-solve(解题步骤, 复访重建) | — | | `rating_repository.dart` | RatingRepository | `rating.*` | solve-rate(评分) | — | | `sync_repository.dart` | SyncRepository | `sync.*` | sync_queue, profile(副标题) | — | | `preference_repository.dart` | PreferenceRepository | `preference.*` | preference_*, profile(偏好数), paper_auto/pick(加载预设) | — | | `user_repository.dart` | UserRepository | `user.*`, `tasks.*`, `points.*`, `app.*` | index(任务卡片), profile, profile_edit, points, level_detail, about, solve-choice/fill/solve(积分行) | `_PointsCalculator` | | `exam_repository.dart` | ExamRepository | `exam.*` | 所有组卷页面 (auto/pick/quicklook/explore/favorites/history/answer_sheet) | `_ExamFilterEngine` + `_ExamGenerator` + `_ExamPdfService` | | `recommend_repository.dart` | RecommendRepository | `recommend.*` | recommend | `_RecommendationEngine` | | `statistics_repository.dart` | StatisticsRepository | `stats.*` | statistics, profile(统计摘要) | `_StatisticsAggregator` | | `achievement_repository.dart` | AchievementRepository | `achievement.*` | achievement, profile(成就数) | `_AchievementEngine` |  ### 1.5 文件结构规范  每个 `.dart` 文件按以下顺序排列：  ```dart /// 章鱼智学 — {Domain}Repository /// data-db: {prefix}.* /// 对应页面：{页面列表}  // 1. 数据模型类（const + fromJson） class ModelA { ... } class ModelB { ... }  // 2. Repository 类（static 方法，throw UnimplementedError） class {Domain}Repository {   /// GET /api/xxx/   static Future<T> methodName() async {     throw UnimplementedError('{Domain}Repository.methodName');   } }  // 3. （可选）私有算法类，仅供本文件内部使用 class _{ComplexEngine} { ... } ```  ### 1.6 跨页面数据组织  一个页面可引用多个 Repository。例如 profile.html 的数据来自 5 个领域：  ```dart // profile 页面的 ViewModel final user = await UserRepository.getUserInfo(); final stats = await StatisticsRepository.getOverview(); final prefCount = await PreferenceRepository.getCount(); final achCount = await AchievementRepository.unlockedCount(); final syncStatus = await SyncRepository.hasFailed(); ```  不设 ProfileRepository，不制造没有 data-db 对应关系的包装层。  ### 1.7 缩略名规则  Repository 类名去掉 `Repository` 后首字母小写，即为 data-db 路径的首段和 Flutter 代码中的变量名：  ``` AssignmentRepository → assign  ← data-db="assign.*" ExamRepository       → exam    ← data-db="exam.*" ```  ---  ## 二、Flutter 代码结构  ### 2.1 页面 Dart 文件组织  按照底栏 4 个 Tab 分组，每个 Tab 及其所有子页面归入同一个目录。跨 Tab 复用的页面（solve、preference）独立目录。  ``` lib/pages/ ├── homework/         # 作业 Tab + 子页面 │   ├── list_page.dart │   ├── detail_page.dart │   └── widgets/ │       ├── 登录/注册（独立 Tab 外） │   ├── login_page.dart │   └── register_page.dart ├── preference/       # 偏好管理（多 Tab 引用） │   ├── list_page.dart │   ├── edit_page.dart │   └── welcome_page.dart ├── solve/            # 核心 — 独立目录（跨 Tab 复用） │   ├── solve_page.dart          # 解题主页面（路由分发到 choice/fill/solve 模式） │   ├── solve_choice_page.dart   # 选择题子页 │   ├── solve_fill_page.dart     # 填空题子页 │   ├── Tab 进入，但独立）     ├── courses_page.dart     ├── chapters_page.dart     └── content_page.dart ```  **跨 Tab 页面的归属规则：** - 一个页面只属于一个目录，不因被多个 Tab 引用而复制 - `solve/` 独立：作业→解题、组卷→预览→解题 都引用同一个 `solve_page.dart`（按题型路由到子页） - `preference/` 独立：偏好管理从 profile 进入，但推荐页也引用偏好数据 - Widget 引用路径使用相对导入或 `package:` 导入  ### 2.2 页头编译常量规范  #### 为什么要做  - 所有显示文字集中到文件头部，改文案不用在 widget 树里翻 - 一目了然本页涉及哪些 SharedPreferences key - 方便日后的文案审查和多语言  #### 显示文字：`_Strings` 类  每个页面对应的 Dart 文件头部声明一个私有 `_Strings` 类，所有用户可见的文字定义为 `static const String`，包括该页的 `data-db-empty` 空状态文案：  ```dart // 在页面主文件（或独立的 _strings.dart）头部 class _SolveStrings {   static const String pageTitle = '解题模式';   static const String feedbackCorrect = '全对';   static const String feedbackPartial = '过程对计算错';   static const String feedbackWrong = '不会';   static const String completeCongrats = '🎉 已完成';   static const String cooldownHint = '⏳ 还剩 {n} 秒可提交';  // 格式化   static const String nextStepHint = '点击箭头进入下一步 ▶';    static String formatCooldown(int seconds) =>       cooldownHint.replaceAll('{n}', seconds.toString()); }  class _RecommendStrings {   static const String emptySmart = '暂无推荐题目，多做几道题试试';   static const String emptyPreset = '请选择学习偏好查看推荐'; } ```  **全局共享文字**单独放 `lib/constants/app_strings.dart`，如： - 通用按钮：提交、取消、返回、保存、删除、确认 - 通用提示：加载中、暂无数据、网络错误 - App 名称和品牌文案  #### SharedPreferences key：`_Prefs` 类  同上，每页头部声明一个 `_Prefs` 类：  ```dart class _SolvePrefs {   static const String lastSubmitPrefix = 'solve_last_submit_';   static const String ratingCooldown = 'solve_rating_cooldown';    static String lastSubmitKey(int questionId) =>       '$lastSubmitPrefix$questionId'; } ```  #### 防刷 5s/10s 常量  `_SolveStrings` 中声明 `cooldownHint` 格式化模板；时长常量直接写在计时逻辑中（`const Duration(seconds: 5)` / `const Duration(seconds: 10)`），不需要独立抽为常量。  ### 2.3 Widget 复用规范  #### 判定规则  ``` 跨 2 页以上出现 且 语义一致 → 抽出 Widget ```  - **跨 2 页以上**：出现于 2 个或以上页面（包括同一个 Tab 下的不同子页面） - **语义一致**：交互行为相同、数据结构相同。如果只是长得像但交互不同（如一个点击跳转、一个弹窗），不抽 - **先写内联再抽**：不确定是否会复用时，先内联写，第二次出现时重构抽出  #### 存放目录  ``` lib/widgets/ ├── common/           # 通用组件（跨域复用） ├── {domain}/         # 领域内复用（如 exam/, solve/） └── widgets.dart      # barrel export ```  ### 2.4 可复用 Widget 汇总清单（当前已知）  以下是根据 HTML 原型初步识别的可复用 Widget，后续在实际开发中补充或调整：  | Widget | 使用页面 | 复用次数 | 归属目录 | |--------|---------|---------|---------| `kebab-case`，参数用 query param：  ``` /                            → MainShell（底栏外壳） /login                       → 登录 /register                    → 注册 /homework                    → 作业列表 /homework/detail?id=3        → 作业详情 /solve?qid=42&from=homework  → 解题页（from 标记来源：homework/paper/recommend） /solve/rate?qid=42           → 评分页 /lecture/courses             → 讲义课程列表 /lecture/chapters?id=1       → 讲义章节 /lecture/content?id=1&page=3 → 讲义正文（page 客户端参数，非服务端） /paper/auto                  → 智能组卷 /paper/pick                  → 自主选题 /paper/quicklook?id=5        → 组卷预览 /recommend                   → 推荐 /profile                     → 我的 /statistics                  → 学习统计 /achievement                 → 成就 /points                      → 积分流水 /preference/list             → 偏好管理 /preference/edit?id=         → 偏好编辑 /about                       → 关于 ```  #### 过渡动画  - 常规 push：从右向左滑入（Material 默认） - 底部 Tab 切换：无动画 - 返回：从左向右滑出  #### Web 端浏览器行为  - 每个 Navigator.push 对应一条浏览器历史记录 - 浏览器「后退」按键 = Navigator.pop - 解题页退出时如触发评分弹窗，后退键先关闭弹窗再执行后退  ### 2.6 加载与骨架屏  #### 规则  - **列表页首次加载**：使用骨架屏（Shimmer）占位，数据到达后替换 - **后续刷新**：保留现有内容，列表顶部或底部显示局部转圈 - **非列表页**（如 solve、login）：单纯居中转圈 `CircularProgressIndicator`，不需要骨架屏  骨架屏实现：在 `lib/widgets/common/` 下建 `skeleton_loader.dart`，提供通用骨架屏组件（卡片/列表项/段落三种形状）。  ---  > 其他文档详见： > - [架构概览.md](../01-架构/架构概览.md) — 顶层架构与数据流 > -
