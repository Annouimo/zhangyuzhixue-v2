# 章鱼智学 · 数据访问层设计草案

> 数据访问层位于 Repository/Domain 层之下、本地持久化层之上，
> 是 Repository 与 SQLite/Sync/API 之间的桥梁。
> 本文档定义该层的文件结构、接口约定及关键交互流程。

---

## 一、层间契约

```
┌─────────────────────────────────────────┐
│  Widget / ViewModel                      │
│  new Repository(new Dao(database))       │
└────────────────┬────────────────────────┘
                 │ 调用 Repository 方法
                 ▼
┌─────────────────────────────────────────┐
│  Repository（实例方法，构造注入 DAO）      │
│  QuestionRepository(QuestionDao)        │
│  ExamRepository(ExamDao + SyncApi)      │
└──────┬──────────────────┬───────────────┘
       │ 读               │ 写
       ▼                  ▼
┌──────────────┐ ┌──────────────────────┐
│ DAO 层       │ │ API Client +         │
│ (Drift CRUD) │ │ Sync Engine (推送)   │
└──────────────┘ └──────────────────────┘
```

**关键约定：**

| 项 | 规则 |
|----|------|
| Repository 构造 | 构造时显式注入 DAO 和 API 依赖，不自己 new |
| DAO 构造 | 构造时接收 Drift Database，不持有全局状态 |
| ApiClient / AppPrefs / DatabaseProvider / ConnectivityMonitor | **基础设施单例**——Dio 连接池、SharedPreferences、数据库连接、网络监听器均为进程级全局资源，保留单例。其余组件一律构造注入 |
| 数据流 | Repository → DAO ← DatabaseProvider（单例管理连接生命周期） |

## 三、Database 层设计

### 3.1 三库方案

| 数据库 | 类 | 读写 | 生命周期 |
|-------|------|------|---------|
| assets.db | `AssetsDatabase` | 只读 | 打开 → 替换时关闭重开 |
| lectures.db | `LecturesDatabase` | 只读 | 同上 |
| user.db | `AppDatabase` | 读写 | 打开 → 登出时清空 → 重开 |

### 3.2 DatabaseProvider（单例，管理连接生命周期）

```dart
/// 三库生命周期管理。
/// 基础设施单例——数据库连接是重量级资源，必须全局共用一个。
class DatabaseProvider {
  static final DatabaseProvider _instance = DatabaseProvider._();
  factory DatabaseProvider() => _instance;

  AppDatabase? _appDb;
  AssetsDatabase? _assetsDb;
  LecturesDatabase? _lecturesDb;

  Future<void> init() async {
    final dir = await getApplicationDocumentsDirectory();
    _assetsDb = AssetsDatabase(await _openDb('${dir.path}/assets.db'));
    _lecturesDb = LecturesDatabase(await _openDb('${dir.path}/lectures.db'));
    _appDb = AppDatabase(await _openDb('${dir.path}/user.db'));
    await _appDb!.migrate();
  }

  AppDatabase get appDb => _appDb!;
  AssetsDatabase get assetsDb => _assetsDb!;
  LecturesDatabase get lecturesDb => _lecturesDb!;

  /// 替换 assets.db（更新时调用）
  Future<void> replaceAssetsDb(String newPath) async { … }
  Future<void> replaceLecturesDb(String newPath) async { … }

  /// 替换 user.db（登录拉取时调用）
  Future<void> replaceUserDb(String newPath) async { … }

  /// 清空 user.db（登出时调用）
  Future<void> clearUserDb() async { … }
}
```

### 3.5 创建链（composition root）

在页面 Widget 或 State 中组装：

```dart
// ── 页面级组装 ──
final db = DatabaseProvider();
final repo = QuestionRepository(QuestionDao(db.assetsDb));
final detail = await repo.getDetail(42);

// ── 复杂页面（组合多个 Repository） ──
final db = DatabaseProvider();
final questionRepo = QuestionRepository(QuestionDao(db.assetsDb));
final progressRepo = ProgressRepository(
  ProgressDao(db.appDb),
  questionRepo,
);
```

**不需要 DI 框架**——链往往只有 2~3 层深度，手动 new 的开销可以忽略。

## 四、测试性设计

构造注入的天然优势：每个组件都可以独立构造，传入 fake 依赖。

```dart
// ── DAO 测试（in-memory Drift） ──
void main() {
  test('QuestionDao.getById', () async {
    final db = AssetsDatabase(NativeDatabase.memory());
    // … 插入测试数据到 db
    final dao = QuestionDao(db);
    final result = await dao.getById(1);
    expect(result, isNotNull);
  });
}

// ── Repository 测试（fake DAO） ──
void main() {
  test('QuestionRepository.getDetail', () async {
    final db = AssetsDatabase(NativeDatabase.memory());
    // … 插入测试数据
    final repo = QuestionRepository(QuestionDao(db));
    final result = await repo.getDetail(1);
    expect(result.title, contains('2024'));
  });
}

// ── API 测试（Dio MockAdapter） ──
void main() {
  test('SyncApi.push', () async {
    final dio = ApiClient().dio;
    dio.mockAdapter = MockAdapter();
    // … 配置 mock 响应
    final api = SyncApi(ApiClient());
    final result = await api.push([…]);
    expect(result, isA<PushResponse>());
  });
}
```

没有全局状态需要清理，没有 `setInstance()` 调用，每个测试用例从零构造依赖。

## 五、API Client 层设计

### 5.1 ApiClient（基础设施单例）

Dio 连接池和拦截器是进程级基础设施，适合单例：

```dart
class ApiClient {
  static final ApiClient _instance = ApiClient._();
  factory ApiClient() => _instance;

  late final Dio _dio;

  void init({String baseUrl = 'https://zhangyuzhixue.top/api/v1/'}) {
    _dio = Dio(BaseOptions(
      baseUrl: baseUrl,
      connectTimeout: const Duration(seconds: 10),
      receiveTimeout: const Duration(seconds: 15),
      headers: {'Content-Type': 'application/json'},
    ));
    _dio.interceptors.addAll([
      _AuthInterceptor(),
      _RefreshInterceptor(),
      _ErrorInterceptor(),
    ]);
  }

  Dio get dio => _dio;

  /// 测试用
  @visibleForTesting
  void setMockAdapter(MockAdapter adapter) {
    _dio.mockAdapter = adapter;
  }
}
```

### 5.2 三个拦截器的职责

| 拦截器 | 顺序 | 职责 |
|-------|------|------|
| `_AuthInterceptor` | 请求前 | 从 `AppPrefs().getToken()` 读取 accessToken，附加 `Authorization: Bearer ***` |
| `_RefreshInterceptor` | 请求后(401) | 401 → 检查 refresh token → 调 `/auth/refresh/` 更新 → 重试原请求；refresh 也过期则清除 token 跳登录页 |
| `_ErrorInterceptor` | 请求后(所有) | 统一解析 `{code, message, data}` 格式，code≠0 时转为 `ApiException` |

**Token 刷新时序（同步锁）：**

```
请求 A → 401 → 获取锁 → POST /auth/refresh/ → 更新 token → 释放锁 → 重试 A
请求 B → 401 → 等锁   → （锁释放） → 用新 token 重试 B
```

### 5.3 API 类 — 实例方法，接收 ApiClient

```dart
class SyncApi {
  const SyncApi(this._client);
  final ApiClient _client;

  Future<VersionResponse> checkVersion(String type) async {
    final res = await _client.dio.get('/sync/$type/version/');
    return VersionResponse.fromJson(res.data['data']);
  }

  Future<PushResponse> push(List<Map<String, dynamic>> batch) async {
    final res = await _client.dio.post('/sync/push/', data: {'batch': batch});
    return PushResponse.fromJson(res.data['data']);
  }
}
```

### 5.4 ApiException

```dart
class ApiException implements Exception {
  final int code;
  final String message;
  final int? httpStatus;

  bool get isAuthError => code >= 40001 && code <= 40099;
  bool get shouldRetry => code >= 50001;
}
```

## 六、Network 层

```dart
class ConnectivityMonitor {
  static final ConnectivityMonitor _instance = ConnectivityMonitor._();
  factory ConnectivityMonitor() => _instance;

  final _connectivity = Connectivity();
  final _stateController = StreamController<bool>.broadcast();

  bool get isOnline => _online;
  bool _online = true;
  Stream<bool> get onConnectivityChanged => _stateController.stream;

  void init() {
    _stateController.add(_online);  // 种子值：新订阅者立即收到当前状态
    _connectivity.onConnectivityChanged.listen((results) {
      final online = results.any((r) => r != ConnectivityResult.none);
      _online = online;
      _stateController.add(online);
    });
  }

  void dispose() => _stateController.close();
}
```

### 7.2 AppPrefs 与 _Prefs 分工

| 归属 | 管理哪些 key | 命名前缀 |
|------|-------------|---------|
| AppPrefs（全局） | `app_auth_token`, `app_qbank_version` 等 | `app_` |

两套命名空间前缀不同，永不冲突。已在 Flutter代码规范.md §1.5 中定义。

## 八、与 Sync Engine 的边界

同步引擎的依赖通过构造注入传入：

```dart
// 改造前（设计稿占位）
// await SyncManager().init(db, dio);

// 改造后
final syncManager = SyncManager(
  syncQueueDao: SyncQueueDao(DatabaseProvider().appDb),
  syncApi: SyncApi(ApiClient()),
);
await syncManager.onAppStart();
```

SyncManager 不持有 Database 或 Dio，通过 DAO 和 Api 间接访问。

## 九、设计决策汇总

| # | 问题 | 决定 | 理由 |
|---|------|------|------|
| 1 | DAO 获取方式 | **构造注入**，无全局工厂 | 测试干净，不需要 `setInstance` + 清理 |
| 2 | Repository 方法 | **实例方法**（非 static） | 配合构造注入，天然可测试 |
| 3 | DbProvider 模式 | **单例** | 数据库连接是重量级资源，需全局共享 |
| 4 | ApiClient 模式 | **单例** | Dio 连接池 + 拦截器链需全局共享 |
| 5 | API 类获取方式 | **构造注入** `SyncApi(ApiClient())` | ApiClient 单例，API 类无状态可测试 |
| 6 | Drift DAO 生成 | **复用 Drift generated DAO** | 基础 CRUD 零代码，复杂 JOIN 在 Repository |
| 7 | Token 刷新 | **同步锁 (mutex)** | 简单可靠，并发 401 极少 |
| 8 | AppPrefs 范围 | **仅全局 key** | 页面 key 太多且自有，前缀规范防冲突 |
| 9 | DI 框架 | **不用** | 当前深度 2~3 层，手动注入已足够 |
