## 一、同步引擎架构

本目录包含同步引擎的 4 个 Dart 设计稿文件：

| 文件 | 内容 | 阅读顺序 |
|------|------|---------|
| `sync_types.dart` | 枚举（实体类型、操作类型、状态）+ 响应体模型 | ① 先看 |
| `sync_queue_dao.dart` | 队列表 CRUD 接口 + DAO 封装 | ② 其次 |

## 二、同步队列状态机

```
               入队
                 │
                 ▼
            ┌─────────┐
            │ pending  │
            └────┬────┘
                 │ pushAll() 开始处理
                 ▼
            ┌───────────┐
            │ inProgress │
            └─────┬─────┘
                  │ 请求返回
         ┌────────┼────────┐
         ▼        ▼        ▼
    ┌───────┐ ┌──────┐ ┌──────────────┐
    │ done  │ │failed│ │permanentFail │
    └───────┘ └──┬───┘ └──────────────┘
                 │ retryCount < maxRetries
                 │ → 下次 pushAll() 重新处理（见"孤儿记录"）
```

**约定：**
- `pending` — 待推送，每次 `pushAll()` 从 pending + inProgress 中取出
- `inProgress` — 正在推送中（防止同一记录被多个批次取出）。App 被杀导致的孤儿记录，下次启动时重新取出
- `done` — 推送成功，下次 cleanup 时删除
- `failed` — 推送失败，`retryCount < maxRetries` → 下次 `pushAll()` 取出重新推送
- `permanentFailure` — `retryCount >= maxRetries` → 不再推送，保留供用户查看

## 三、重试策略

**最大重试次数：** 5 次（可通过 SystemConfig 配置）。5 次足够覆盖短暂网络抖动，超出后转为 permanentFailure。

**退避策略：不做指数退避，仅 30 秒冷却检查（可通过 SystemConfig 配置）。** 原因：所有重试触发均为人工操作（"全部重试"按钮 / App 启动），指数退避在手动触发场景下无意义。

```dart
// 冷却检查：距上次推送不足 30 秒则跳过（防连续点击按钮）
if (DateTime.now().difference(_lastPushTime).inSeconds < 30) return;
```

**触发时机：** 仅 App 启动和用户点击"全部重试"。不做后台定时器，不做网络恢复自动推送（省电省流量）。

### 错误分类处理

| 错误类型 | 判定 | 处理 |
|---------|------|------|
| 网络错误（无网/超时/DNS） | DioException | `markFailed()`，retryCount+1，不中断队列 |
| 服务端 5xx | HTTP 500/502/503 | 同上 |
| 服务端 4xx 业务错误 | ApiException.code (40001-40399) | 直接 `permanentFailure` |
| LWW 冲突 | PushItemResult.status == 'conflict' | 视为成功（`markSuccess`） |
| Token 过期（401） | ApiClient 拦截器自行刷新 | 不进入此状态机 |
| 数据校验失败 | code = 40301 | 直接 `permanentFailure` |

### 孤儿记录处理

`getPending()` 改为查 `status IN ('pending', 'inProgress', 'failed')`。App 在推送中途被杀时，`inProgress` 的记录在下次启动时重新取出推送。`failed` 条目自动重试（含重试计数上限）。

### permanentFailure 处理

- 保留 **7 天**，到期 cleanup() 自动删除
- sync_queue 页面中永久失败条目显示"清除"按钮（不可重试）
- 用户可联系管理员排查

### cleanup 清理规则

每次 `pushAll()` 结束后执行：
- `done` → 立即删除
- `permanentFailure` → created_at 超过 7 天 → 删除
- `failed` + retryCount >= maxRetries → 转为 permanentFailure

## 四、用户数据拉取

与同步队列（Client→Server）方向相反，用户数据拉取实现 Server→Client 全量替换。

### SyncManager 新增接口

```dart
/// 登录后调用：推送积压 → 拉取 user.db → 替换
Future<void> onLogin();

/// 退登前调用：推送积压 → 清空 user.db + sync_queue
Future<void> onLogout();

/// 手动强制拉取（关于页按钮用）
Future<void> forcePull();
```

### 复用 UpdateManager

拉取不走 sync_queue，直接复用 `UpdateManager.downloadAndReplace()`：

```dart
final info = await _api.fetchUserPullInfo();
await _updateManager.downloadAndReplace(
  type: 'user',
  url: info.downloadUrl,
  expectedChecksum: info.checksum,
  newVersion: info.version,
);
```
