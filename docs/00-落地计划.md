## 二、工作流原则

### 线性化

服务端 → Flutter 数据层 → Flutter UI → 教师 UAT 验收 → 辅助系统 → 集成测试 → 用户迁移上线，不并行。教师是学生端的验收者，他们签字确认后才发布给学生使用。服务端是数据源头（Django models → Drift 镜像；API → sync engine），Flutter 数据层需要服务端的接口契约就绪后才能对接。

### 每步测试

测试嵌入到每个子步骤中，不攒到最后集中做。L1-L4 嵌入 Phase 1/2 的每一步；L5 Widget 测试嵌入 Phase 3 的每一步。仅 L6-L8（服务端契约/E2E/构建）留到最后的 Phase 5 集中做。

### 设计纪律

严格按照设计文档编码，不清楚的先问项目负责人，不自己拍板决策。项目的每一处细节（字段命名、交互流程、错误处理、Widget 拆分粒度）都已定稿。编码时遇到文档未覆盖的边界情况、想改设计、不理解意图、文档冲突——一律停下来先问。

设计文档之所以写这么细（20+ 篇、30+ HTML 原型、13 个 Repository 设计稿），就是为了让编码阶段只需要执行、不需要决策。擅自决策可能导致与系统不一致、与服务端 API 契约不匹配返工、违背镜像原则。不确定就问。

## 三、横切关注点

以下基础设施不属于某个具体的功能开发步骤，而是贯穿整个项目的质量保障体系。在依赖它们的第一个 Phase 中就需到位。

### CI/CD（Phase 0 搭建，贯穿全程）

**方案：** GitHub Actions

每次 push 到 master 或 PR 时自动运行（总时间 < 5 分钟）：

```
并行运行：
├─ Flutter 检查
│   ├─ dart analyze（静态分析，零 warning 通过）
│   └─ flutter test（全部单元 + Widget 测试）
│
└─ Django 检查
    ├─ flake8（代码规范，max-line-length=100）
    ├─ python manage.py check --deploy（部署检查）
    ├─ pytest（全部 API 契约测试）
    └─ python manage.py makemigrations --check（迁移无遗漏）
```

**配置方式：** `.github/workflows/ci.yml`，在 Phase 0 脚手架阶段写入。

### 错误监控（Phase 1 加入，非"上线后"）

**方案：** Sentry（`sentry-sdk`）

```
Phase 1.1 模型阶段就加：
  pip install sentry-sdk
  # settings.py 配置 DSN（从环境变量读）
  sentry_sdk.init(dsn=config('SENTRY_DSN', default=''))

上线前：
  在 Sentry 后台配置告警规则（错误 > 5/分钟 发邮件/钉钉）
```

**理由：** 第一版上线时最需要监控——未被测试覆盖的边界情况、错误码遗漏、特定设备上的 502 都要靠 Sentry 第一次发现。

### API 自动文档（Phase 1.3 认证 API 阶段加入）

**方案：** `drf-spectacular`

```python
# Phase 1.3 时一行 urls 配置
urlpatterns += [
    path('api/docs/', SpectacularAPIView.as_view(), name='schema'),
]
```

Flutter 开发时浏览器打开 `/api/docs/` 即可查看全部端点、请求体、响应体。零维护成本。

### 数据库备份（Phase 6 上线脚本中加入）

ECS 部署脚本中加一行定时任务：

```bash
# crontab
0 4 * * * cp /path/to/db.sqlite3 /backup/db.$(date +\%Y\%m\%d).sqlite3
find /backup/ -name "db.*.sqlite3" -mtime +30 -delete
```

### Phase 3.5 — 教师 UAT 验收（3-5 天）

Phase 3 UI 全部完成后，让 3 位教师以学生身份试玩全部功能。他们是学生端的验收者——确认可用了，才能发布给学生。

**验收范围：**

| 功能 | 验收重点 |
|------|---------|
| 登录/注册 | 注册流程、邀请码验证、登录后首页展示 |
| 解题模式 | 选填冷却→提交→批改、解答地图→步骤→反馈、评分页、知识卡片弹层 |
| 讲义 | 课程列表→章节→正文三级下钻、分页展开交互、公式渲染 |
| 作业 | 作业列表（含完成状态）、作业详情、解题入口 |
| 组卷 | 智能组卷筛选+难度调优、自主选题勾选、预览、快对答案 |
| 推荐 | 智能推荐/偏好推荐双模式 |
| 统计 | 4 图表卡片的数据展示 |
| 个人中心 | 资料编辑、等级、积分流水、成就、做题历史 |

**流程：**

`
[教师全功能试玩 1 轮]
    ↓
[收集反馈 → 分类: UX/数据/功能]
    ↓
[修改 → 部署到 staging → 通知复测]
    ↓
┌── 全部问题已解决？──┐
│  是              否│
│                   ↓
│              下一轮迭代
↓
[3 位教师签收 → 进入 Phase 4]
`

**不验收的：** 成就/积分/评价弹层（与教学流程无关，影响用户体验但不需要教师判断）。这些放在 Phase 4 正常开发。

**为什么放这里：**
- Phase 4 辅助系统不影响核心功能，可以和 UAT 并行或紧随其后
- 如果 UAT 发现问题需要大改，Phase 5 集成测试还能兜底
- 到 Phase 6 上线前再发现 UX 问题就来不及了
