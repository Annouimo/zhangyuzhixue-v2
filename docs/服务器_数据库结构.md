# 🗂️ 最终应用（App）划分与职责

| App名称 | 职责 | 核心模型 |
| :--- | :--- | :--- |
| **`question_bank`** | 题库核心：题目、小题、解析、知识卡片、用户偏好标记 | `BaseQuestion`, `ChoiceExt`, `FillExt`, `SolutionExt`, `SubQuestion`, `SolutionMethod`, `SolutionStep`, `KnowledgeCard`, `ConceptTag`, `UserPreference` |
| **`course_center`** | 课程、班级、讲义、作业及发布逻辑 | `Course`, `ClassGroup`, `ClassCourse`, `Lecture`, `Assignment`, `AssignmentQuestion`, `ClassCourseAssignment` |
| **`user_management`** | 用户、班级归属、积分流水、成就体系、登录轨迹 | `Student`, `PointsTransaction`, `AchievementDef`, `StudentAchievement`, `UserLoginLog` |
| **`learning_interaction`** | 学习过程记录、反馈、个性化组卷广场、满意度评价 | `StudentSubmission`, `SubmissionDetail`, `StepFeedback`, `CardFeedback`, `QuestionRating`, `CustomPaper`, `CustomPaperQuestion`, `PaperLike`, `PageSatisfactionFeedback` |
| **`system`（通过第三方库实现）** | 审计日志（管理员操作追溯） | 无业务表，由 `django-auditlog` 自动生成审计记录 |

---

# 📐 核心模型结构（字段与关系终稿）

## 0. 审计日志模块

**实现方式**：引入 `django-auditlog` 库，在 `settings.py` 中启用并配置需要审计的模型（或全局启用）。

- **自动记录内容**：操作人（User）、操作时间、操作类型（CREATE/UPDATE/DELETE）、变更字段的 JSON Diff（新旧值对比）、操作对象 ID 及模型名称。
- **优势**：零侵入、经过生产验证、支持历史回溯、无需手动维护审计表。

## 1. 题库 App (`question_bank`)

### ① `BaseQuestion` (题目主表)
- **字段**：
  - `id`：主键
  - `year`：年份
  - `exam_type`：考试类型
  - `region`：地区
  - `number`：题号
  - `question_type`：题型（选择/填空/解答）
  - `difficulty`：难度（Decimal，0-10）
  - `calculation`：计算量（Decimal）
  - `stem`：题干（含图片URL）
  - `default_score`：参考分值
- **关系**：
  - 与 `ConceptTag` 多对多
  - 与 `SolutionMethod` 一对多

### ② `ChoiceExt` / `FillExt` / `SolutionExt` (题型扩展表)
- **继承方式**：均使用 `OneToOneField` 指向 `BaseQuestion`。
- **`ChoiceExt` 独有字段**：`options`（JSONField，存 `{"A":"...", "B":"..."}`）
- **`FillExt`**：无特殊字段（仅占位）
- **`SolutionExt`**：无特殊字段（小问题已彻底分离至 `SubQuestion` 表）

### ③ `SubQuestion` (小题树形表)
- **字段**：
  - `id`：主键
  - `question`：外键指向 `BaseQuestion`
  - `parent`：外键指向自身（允许为空）
  - `stem`：题干
- **作用**：支持无限层级嵌套（如 2 → 2(1) → 2(1)(i)）

### ④ `SolutionMethod` (解法表)
- **字段**：
  - `id`：主键
  - `sub_question`：外键指向 `SubQuestion`
  - `method_name`：解法名称（如"代数法"）
  - `source`：来源（AI生成/汇编PDF）
- **作用**：支持一题多解

### ⑤ `SolutionStep` (解析步骤表)
- **字段**：
  - `id`：主键
  - `method`：外键指向 `SolutionMethod`
  - `step_number`：整数步骤编号
  - `content`：TextField，存文字+LaTeX
- **关系**：与 `KnowledgeCard` 多对多

### ⑥ `KnowledgeCard` (知识卡片表)
- **字段**：
  - `id`：主键
  - `title`：标题
  - `content`：卡片详细内容
- **特点**：全局独立复用

### ⑦ `ConceptTag` (概念标签树)
- **字段**：
  - `id`：主键
  - `name`：标签名称
  - `parent`：外键指向自身（允许为空）
- **特点**：通过自关联实现"集合 → 并集"的父子层级

### ⑧ `UserPreference` (用户偏好表) —— **新增**
- **字段**：
  - `id`：主键
  - `student`：外键指向 `Student`
  - `content_type`：外键指向 Django 的 `ContentType`（模型类型：`BaseQuestion` / `KnowledgeCard` / `ConceptTag`）
  - `object_id`：对应模型实例的 ID
  - `is_preferred`：布尔字段，`True` 表示用户选择了该偏好（喜欢/感兴趣），`False` 表示取消选择
  - `created_at`：首次标记时间
  - `updated_at`：最后修改时间
- **约束**：`unique_together = ('student', 'content_type', 'object_id')`
- **用途**：组卷时筛选 `is_preferred=True` 的记录，提取对应的标签/知识点作为题目过滤依据。

## 2. 课程中心 App (`course_center`)

### ① `Course` (课程)
- **字段**：`id`, `name`, `description`

### ② `ClassGroup` (班级)
- **字段**：`id`, `name`（避开 Python 保留字 `Class`）

### ③ `ClassCourse` (班级-课程绑定)
- **字段**：
  - `id`：主键
  - `class_group`：外键指向 `ClassGroup`
  - `course`：外键指向 `Course`
  - `start_date`：课程开始日期
  - `end_date`：课程结束日期
- **作用**：多对多中间表，存储课程在该班级的有效期

### ④ `Lecture` (讲义)
- **字段**：
  - `id`：主键
  - `title`：标题
  - `file_url`：文件地址
  - `course`：外键指向 `Course`
- **关系**：一份讲义属于一门课（如需复用可改为多对多）

### ⑤ `Assignment` (作业)
- **字段**：
  - `id`：主键
  - `title`：标题
  - `description`：描述
- **关系**：与 `Course` 多对多

### ⑥ `AssignmentQuestion` (作业-题目中间表)
- **字段**：
  - `id`：主键
  - `assignment`：外键指向 `Assignment`
  - `question`：外键指向 `BaseQuestion`
  - `order`：整数顺序
- **作用**：定义题目在作业中的顺序

### ⑦ `ClassCourseAssignment` (作业发布表) —— 核心枢纽
- **字段**：
  - `id`：主键
  - `class_course`：外键指向 `ClassCourse`
  - `assignment`：外键指向 `Assignment`
  - `publish_at`：发布时间
  - `deadline`：截止时间
  - `is_active`：布尔值
- **作用**：决定"哪个班级的哪门课，在什么时间段内能看到并提交哪份作业"

## 3. 用户管理 App (`user_management`)

### ① `Student` (学生)
- **字段**：
  - `id`：主键
  - `user`：一对一关联 Django 内置 `User`
  - `class_group`：外键指向 `ClassGroup`，允许为空
- **流程**：注册时班级为空，管理员手动拉入
- **说明**：此处**不存储任何积分、等级、连续天数等冗余字段**，所有统计数据均由相关流水表实时计算。

### ② `PointsTransaction` (积分流水表) —— 唯一积分数据源
- **字段**：
  - `id`：主键
  - `student`：外键指向 `Student`
  - `amount`：整数字段，**正数为收入，负数为支出**
  - `transaction_type`：选择字段，`EARN` / `SPEND`
  - `source`：来源业务，如 `LOGIN_BONUS`、`PRACTICE_REWARD`、`PAPER_PURCHASE`、`ADMIN_ADJUST`
  - `source_object_id`：关联源业务 ID（可为空，便于查账）
  - `description`：备注（最长 255 字符）
  - `created_at`：交易时间
- **索引**：`(student, -created_at)` 用于积分明细列表展示
- **积分计算规则（全部实时）**：
  - **可用积分** = `SUM(amount)`（全部流水汇总）
  - **累计积分（总赚取）** = `SUM(amount) WHERE amount > 0`
  - **消耗积分（总支出）** = `ABS(SUM(amount) WHERE amount < 0)`
  - **用户等级** = 根据累计积分通过函数实时映射（如 `level = total_earned // 100 + 1`）

### ③ `UserLoginLog` (登录轨迹表)
- **字段**：
  - `id`：主键
  - `student`：外键指向 `Student`
  - `login_date`：登录日期（DateField，同一天仅存一条）
  - `created_at`：记录创建时间
- **约束**：`unique_together = ('student', 'login_date')`
- **用途**：按日期倒序查询，判断连续登录天数（无冗余缓存，实时计算）

### ④ `AchievementDef` (成就定义表)
- **字段**：
  - `id`：主键
  - `code`：唯一编码（如 `LOGIN_7`、`COURSE_MASTER`）
  - `name`：成就名称
  - `description`：描述
  - `icon`：图标 URL（可为空，前端优先使用 `icon_emoji`）
  - `icon_emoji`：图标 emoji（如 `🌱`、`🎯`，可为空）
  - `category`：分类编码（`LOGIN` / `PRACTICE` / `COURSE` / `PAPER` / `RATING`）
  - `category_label`：分类展示名（如 `🔥 登录`）
  - `display_order`：排序序号，同一分类内升序排列
  - `trigger_type`：触发类型（`LOGIN_STREAK` / `PRACTICE_STREAK` / `COURSE_COMPLETE` / `PAPER_COUNT` / `RATING_COUNT`）
  - `threshold`：达成阈值（如连续 7 天、完成 5 门课）
- **数据预置**：由迁移脚本或后台管理预先录入
- **API 返回结构（按 category 分组）**：
  ```json
  {
    "summary": { "unlockedCount": 5, "totalCount": 18 },
    "categories": [
      {
        "name": "🔥 登录", "code": "LOGIN",
        "list": [
          { "name": "开启旅程", "iconEmoji": "🌱", "status": "unlocked", "unlockedAt": "2025-03-01", ... }
        ]
      }
    ]
  }
  ```

### ⑤ `StudentAchievement` (学生成就记录表)
- **字段**：
  - `id`：主键
  - `student`：外键指向 `Student`
  - `achievement`：外键指向 `AchievementDef`
  - `progress`：当前进度（如已连续签到 3 天）
  - `is_unlocked`：是否已解锁
  - `unlocked_at`：解锁时间（可为空）
  - `updated_at`：进度更新时间
- **约束**：`unique_together = ('student', 'achievement')`
- **更新时机**：每次登录或提交作业后，检查相关连续性指标，满足阈值则解锁并记录进度。

## 4. 交互 App (`learning_interaction`)

### ① `StudentSubmission` (提交记录主表)
- **字段**：
  - `id`：主键
  - `student`：外键指向 `Student`
  - `class_course_assignment`：外键指向作业发布表 `ClassCourseAssignment`
  - `submitted_at`：自动记录提交时间

### ② `SubmissionDetail` (提交明细)
- **字段**：
  - `id`：主键
  - `submission`：外键指向 `StudentSubmission`
  - `question`：**直接外键指向 `BaseQuestion`**
  - `answer_text`：学生答案
  - `is_correct`：布尔值（可为空）
- **作用**：直接关联题目本身，用于实现跨作业"已做"标记

### ③ `StepFeedback` (步骤反馈)
- **字段**：
  - `id`：主键
  - `submission_detail`：外键指向 `SubmissionDetail`
  - `step`：外键指向 `SolutionStep`
  - `status`：三选一（全对/流程对/计算错）

### ④ `CardFeedback` (卡片反馈)
- **字段**：
  - `id`：主键
  - `submission_detail`：外键指向 `SubmissionDetail`
  - `card`：外键指向 `KnowledgeCard`
  - `status`：三选一（完全掌握/了解/不了解）

### ⑤ `QuestionRating` (题目评分)
- **字段**：
  - `id`：主键
  - `student`：外键指向 `Student`
  - `question`：外键指向 `BaseQuestion`
  - `difficulty_score`：难度评分
  - `calculation_score`：计算量评分
  - `elegance_score`：优雅度评分
- **约束**：`unique_together = ('student', 'question')`，允许覆盖

### ⑥ `CustomPaper` (个性化组卷主表)
- **字段**：
  - `id`：主键
  - `student`：外键指向 `Student`（创建者）
  - `title`：组卷名称
  - `description`：组卷描述（可为空）
  - `filter_snapshot`：JSONField，存储组卷时的筛选条件快照（如 `{"concepts": [1,2], "difficulty": [3,5]}`）
  - `is_public`：布尔值，是否公开（默认 False）
  - `view_count`：浏览量（默认 0）
  - `created_at`：创建时间
  - `updated_at`：最后编辑时间
- **说明**：此表取代旧的组卷表，旧表数据通过一次性迁移导入，导入后废弃。

### ⑦ `CustomPaperQuestion` (组卷-题目中间表)
- **字段**：
  - `id`：主键
  - `paper`：外键指向 `CustomPaper`
  - `question`：外键指向 `BaseQuestion`
  - `order`：题目在组卷中的顺序（整数）

### ⑧ `PaperLike` (组卷点赞记录)
- **字段**：
  - `id`：主键
  - `student`：外键指向 `Student`（点赞用户）
  - `paper`：外键指向 `CustomPaper`
  - `created_at`：点赞时间
- **约束**：`unique_together = ('student', 'paper')`，防止重复点赞

### ⑨ `PageSatisfactionFeedback` (退出评价反馈表)
- **字段**：
  - `id`：主键
  - `user`：外键指向 Django `User`（登录用户）
  - `page_url`：评价时的页面路径（最长 500 字符）
  - `rating`：评分（1 ~ 5，1=非常不满，5=非常满意）
  - `comment`：选填的文本意见（可为空）
  - `device_type`：设备类型（如 PC / Mobile，可为空）
  - `created_at`：评价时间
- **用途**：用户点击退出时按概率弹出评价对话框，收集满意度数据。

# 🔑 权限查询路径（标准链路）

当学生登录后，系统按此链路获取可见内容：

1. `Student` → `class_group`（找到班级）
2. `ClassGroup` → `ClassCourse`（多对多，找到该班级绑定的所有课程）
3. `ClassCourse` → `ClassCourseAssignment`（找到该课程下已发布的作业）
4. `Assignment` → `AssignmentQuestion`（找到作业里的题目列表）

**讲义**：直接根据 `Course` 过滤，或通过多对多关系获取。

**已做标记**：查询 `SubmissionDetail` 表，过滤条件 `student=当前学生` 且 `question=当前题目ID`，有记录即已做。

# 💎 终稿特性总结

- **完整性**：覆盖题库、课程、用户、交互、审计、成就、积分、偏好、组卷社区等全业务闭环。
- **零冗余设计**：所有统计数据（积分、连续天数、等级）均由流水/日志表实时计算，杜绝数据不一致。
- **灵活扩展**：题目支持无限级小题嵌套、一题多解、概念标签无限层级；偏好系统基于 `ContentType` 支持多维度内容标记。
- **审计合规**：采用业界成熟的 `django-auditlog` 实现管理员操作追溯，零侵入且可回溯。
- **UGC社区生态**：个性化组卷支持公开/私有切换和点赞互动，构建高质量试卷广场。
- **成就驱动**：通过独立的成就定义与进度表，配合登录轨迹，灵活支持连续签到、刷题、课程完结等多种成就。
- **性能优化**：核心查询最多关联 3-4 张表；积分和连续天数若遇性能瓶颈，可叠加 Redis 缓存层而无需修改数据库结构。
