# 章鱼智学 · 服务端架构

> 本文档定义新版 Django 服务端（纯 API + Admin）的架构设计、App 划分、认证方案、部署策略与审计策略。
>
> **状态**：✅ 已实现。Django 服务端已部署运行。

---

## 一、定位

| 维度 | 定位 |
|------|------|
| 角色 | 纯 API 后端 + Django Admin 管理端 |
| 客户端 | Flutter App（学生端）+ 轻量教师 Web（landing/teacher/） |
| 不做 | 学生端网页前端；教师端有轻量 Web（landing/teacher/），但不涉及复杂交互 |
| 部署 | 单一 Django 进程 + gunicorn + nginx + Cloudflare Tunnel |

**核心原则：** 服务端只做三件事——认证鉴权、数据接收与持久化、管理员操作入口。

## 三、认证方案

### 3.1 角色体系

| 角色 | 标识 | 登录端 | 创建方式 |
|------|------|--------|---------|
| `student` | `Student` 表存在 | 学生 Flutter App | 自助注册（需邀请码） |
| `teacher` | `Teacher` 表存在 | 教师 Flutter App | 管理员通过 Django Admin 创建 |
| `admin` | `User.is_staff = True` | Django Admin | 管理员创建 |

### 3.2 JWT 方案

| 组件 | 方案 |
|------|------|
| 库 | `djangorestframework-simplejwt` |
| Access Token | 24 小时 |
| Refresh Token | 30 天 |
| 存储 | SharedPreferences（Flutter 端） |

### 3.3 端点

| 方法 | 端点 | 说明 |
|------|------|------|
| `POST` | `/api/v1/auth/login/` | 登录，接收 `{"username", "password", "app_type"}` |
| `POST` | `/api/v1/auth/register/` | 注册（仅 student），需邀请码 |
| `POST` | `/api/v1/auth/refresh/` | Token 刷新 |

### 3.4 权限类

DRF 的 `IsAuthenticated` + 自定义 `IsStudent` / `IsTeacher` 权限类，用于端点级鉴权。
|
|登录接口不做角色校验——`app_type` 仅用于区分来源，权限放行后在具体端点通过权限类拦截。教师可用 `app_type=student` 登录学生 Flutter App 浏览题库和创建组卷，但无法调提交/评分等学生专属 API。

## 四、数据库选型

### 决策：SQLite (WAL)

| 维度 | 选型 |
|------|------|
| 引擎 | SQLite 3 |
| 模式 | WAL（Write-Ahead Logging） |
| 配置 | `timeout=20`，`transaction_mode='IMMEDIATE'` |
| 启用 | Django signal `connection_created` 执行 `PRAGMA journal_mode=WAL;` |

沿用旧版的 SQLite 配置已验证可行。当前用户规模极小（~3 教师 + 数十学生），服务端写入为低频批量推送，SQLite 的串行写不构成瓶颈，运维成本为零。

## 五、部署方案要点

| 组件 | 方案 |
|------|------|
| 服务器 | 阿里云 ECS 2C2G（123.57.85.160） |
| 应用服务器 | gunicorn |
| 反向代理 | nginx |
| TLS | Cloudflare Tunnel |
| 静态文件 | WhiteNoise |
| 数据库 | SQLite WAL（本地文件） |
| 媒体文件 | 本地文件系统 `media/` 目录（头像） |
| .db 分发 | nginx 直接 serve `media/db/` 目录 |
| 着陆页 | nginx 直接 serve 目录下的静态 HTML（不走 Django） |
| 试卷 HTML | Django `templates/pdf/` 渲染 |
| 试卷配图 | nginx 或 WhiteNoise serve `static/questions/images/` 目录 |
| 错误监控 | 先不配，上线稳定后加 Sentry |

> **不引入 OSS**：当前规模下用户头像和 .db.gz 文件量极小，本地文件系统足够。

### 着陆页说明
- 项目 `landing/` 目录下的 `index.html` 等静态文件，部署时复制到服务器，由 nginx 直出
- 包含：App 下载链接、微信联系方式、隐私政策、用户协议、更新日志
- 不经过 Django 进程，零维护成本

## 六、审计日志策略

### 6.1 方案

引入 `django-auditlog`，零侵入自动记录：操作人、操作时间、操作类型（CREATE/UPDATE/DELETE）、变更字段的 JSON Diff、操作对象 ID 及模型名称。

### 6.2 审计范围

**默认审计（注册 auditlog）：** `BaseQuestion`, `ChoiceExt`, `SubQuestion`, `SolutionMethod`, `SolutionStep`, `KnowledgeCard`, `ConceptTag`, `Document`, `Course`, `ClassGroup`, `ClassCourse`, `Assignment`, `AssignmentQuestion`, `ClassCourseAssignment`, `Student`, `Teacher`, `User`, `DbVersion`, `InvitationCode`

**不应审计：** `StudentSubmission`, `SubmissionDetail`, `StepFeedback`, `CardFeedback`, `QuestionRating`, `CustomPaper`, `CustomPaperQuestion`, `PaperLike`, `PaperCollect`, `UserLoginLog`, `PageSatisfactionFeedback`

**条件审计：** `PointsTransaction` — 注册 auditlog，但只关注 `ADMIN_ADJUST` 类型。

## 八、Admin 与操作入口

### 8.1 默认 Admin 注册策略

所有需要管理的模型统一注册到 Django Admin。注册方式为每模型一行 `@admin.register` + 视情况定制。

### 8.2 两种操作类型

#### 🛠 系统级操作 — `/admin/system/tools/`
这些操作不依赖具体某条数据库记录，作用于系统整体。放在 `system` App 下一个自定义 Admin 视图页面中，以按钮/卡片形式列出：

| 操作 | 说明 |
|------|------|
| 构建并发布 · 题库 | 构建 assets.db → gzip → 更新 DbVersion |
| 构建并发布 · 讲义 | 同上，构建 lectures.db |
| 仅构建测试 · 题库 | 只生成 .db.gz 文件，不更新版本号 |
| 仅构建测试 · 讲义 | 同上 |
|| 批量生成邀请码 | 输入数量 → 生成 N 个随机邀请码 |
| 导出未使用邀请码 CSV | 导出全部未使用的邀请码列表 |

#### 📋 模型级操作 — 对应 ModelAdmin `actions` 下拉
管理员手动调整积分、批量导出/导入 JSON、图片重提取、批量导入学生到班级、讲义预览等。
