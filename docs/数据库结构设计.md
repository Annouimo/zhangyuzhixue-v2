# 🗂 数据库结构设计（Django + drift）

> 本文档是**统一的数据库设计终稿**，同时覆盖 Django 服务端和 Flutter 客户端。
>
> 每条表定义标注其所在位置：
> - `[镜像]` = 服务器 Django DB + 本地 assets 预置库（结构一致）
> - `[服务器]` = 仅 Django 服务端有此表
> - `[本地资产]` = 仅客户端 assets 预置库有（构建脚本生成）
> - `[本地用户]` = 仅客户端 user 数据库有（用户数据）
> - `[本地特有]` = 客户端独占表（assets 或 user），服务器无对应

---

## 一、架构与数据流

```
服务端 (Django PostgreSQL/SQLite)
    │
    ├── REST API（用户数据接收 + 版本号检查 + 登录注册）
    │
    └── POST /api/sync/push  ← 客户端异步推送
         │
         ▼
客户端 (Flutter SQLite)
    │
    ├── assets.db（预置只读）
    │   题库、步骤、卡片、课程、讲义、作业、成就定义、概念标签
    │
    └── user.db（读写）
    │   提交记录、评分、组卷、签到、积分缓存、
    │   筛选预设、成就进度、同步队列
    │
    ├── SharedPreferences（纯客户端状态）
    │   登录 token、用户信息缓存、待办作业/讲义课程离线缓存、
    │   版本弹窗冷却、解题防刷冷却、评价弹窗冷却
    │
    └── Repository 层（按 UI 需求组合数据）
         │
         ▼
    Flutter UI
```

**核心原则**：
- 服务器与客户端 assets 库**尽可能镜像一致**
- 差异仅发生在：服务器有而本地没有的管理表（班级、审计日志），以及本地有而服务器没有的中间数据（chapter、sync_queue）
- 用户数据（user.db）与服务器结构相近，通过同步队列异步推送
- SharedPreferences 不经过 Repository 体系，仅存纯客户端状态

---

## 二、数据库划分

### 服务端（Django DB）
- 完整的关系型数据库，4 个 Django App
- 用于存储：用户账户、班级课程体系、全量题库、所有用户提交数据、系统审计日志

### 客户端（SQLite，双库分离）

| 数据库 | 读写 | 生命周期 |
|---|---|---|
| `assets.db` | 只读 | 随 App 版本整体替换；版本号检查提示更新 |
| `user.db` | 读写 | 跨版本保留，登出时清空（可选） |

**为什么拆两个库？** assets.db 随发版替换，user.db 跨版本留存。合在一个库中替换 assets 表时容易误清用户数据。

### 5.4 `points_transaction` — 积分流水 `[镜像]`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | PK | | |

| `amount` | INTEGER | NOT NULL | 正=收入，负=支出 |
| `transaction_type` | VARCHAR | NOT NULL | EARN / SPEND |

| `source_object_id` | INTEGER | nullable | 关联业务 ID |
| `description` | VARCHAR | | 最长 255 字符 |
| `created_at` | DATETIME | NOT NULL | |

**积分计算规则（全部实时）**：
- 可用积分 = SUM(amount)
- 累计积分（总赚取）= SUM(amount) WHERE amount > 0
- 消耗积分（总支出）= ABS(SUM(amount) WHERE amount < 0)

## 十、权限查询路径与题目状态推算

### 10.1 权限查询路径（服务端）

当学生登录后，系统按此链路获取可见内容：

1. `Student` → `class_group`（找到班级）
2. `ClassGroup` → `ClassCourse` → 找到该班级绑定的所有课程
3. `ClassCourse` → `ClassCourseAssignment` → 找到该课程下已发布的作业
4. `Assignment` → `AssignmentQuestion` → 找到作业里的题目列表

**讲义**：也走同一链路：Student → ClassGroup → ClassCourse → Course → Lecture。学生只能看到自己班级绑定的课程下的讲义。

**离线缓存**：API 返回该学生可访问的 course_id 列表，缓存到 SharedPreferences。离线时读写 `course_id` 缓存即可过滤 assets。

### 10.2 题目状态推算（客户端）

题目有三种状态，全部通过查询 user.db 的提交记录动态推算：

| 状态 | 判断条件 | 推算逻辑 |
|---|---|---|
| **已做** | 选填：`submission_detail.is_correct` 有值（true / false）<br>解答：最后一步的 `step_feedback` 已存在 | `SELECT 1 FROM submission_detail WHERE question_id=? AND is_correct IS NOT NULL LIMIT 1` |
| **进行中** | 有 `submission_detail` 但 `is_correct` 为 NULL<br>或：有 `step_feedback` 但未完成所有步骤 | 选填很少出现此状态（提交即完成），解答题在闪退等边界情况出现 |
| **未做** | `submission_detail` 中无该 `question_id` | `SELECT 1 FROM submission_detail WHERE question_id=? LIMIT 1` |

> 此推算逻辑封装在 `lib/data/helpers/question_status_helper.dart` 中（详见 `架构与技术规范.md`），不写在特定 Repository 内——因为 AssignmentRepository、RecommendRepository、ExamRepository 三个地方都需要它。
