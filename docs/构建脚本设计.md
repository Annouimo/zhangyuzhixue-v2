## 二、构建方案：独立 drift schema 定义

### 2.1 为什么选此方案

不采用「从 Django models 自动推导」，原因：

| 维度 | 独立 schema 定义 | 自动推导 |
|------|----------------|---------|
| 客户端独有表 | 直接定义，无限制 | 需额外补充逻辑 |
| 字段类型 | 一行一条，清晰可控 | 需维护 Django type → SQLite type 完整映射 |
| Django models 改字段 | **不自动同步**，构建会报错（保护） | 自动同步，可能静默破坏客户端 |
| 维护成本 | 两份定义 | 少写代码，但隐含风险 |

客户端 assets 的 schema 和 Django models 职责不同，明确定义比隐式推导更安全。

### 2.2 Schema 定义方式

在 `scripts/` 下用一个 `build_schemas.py` 文件定义所有客户端表的结构。以 Python dict 描述，不是写 SQL 脚本也不是从 Django 读。

```python
# scripts/build_schemas.py 中的定义

ASSETS_TABLES = {
    'question': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('year', 'INTEGER NOT NULL'),
            ('exam_type', 'TEXT NOT NULL'),
            ('region', 'TEXT NOT NULL'),
            ('number', 'TEXT NOT NULL'),
            ('question_type', 'TEXT NOT NULL'),
            ('difficulty', 'REAL'),
            ('calculation', 'REAL'),
            ('stem', 'TEXT NOT NULL'),
            ('images', 'TEXT'),        # JSON list
            ('default_score', 'REAL'),
        ],
        'source_model': 'BaseQuestion',       # Django 模型名
        'transform': 'direct',                 # 字段名与 Django 一致，直接复制
    },

    'choice_ext': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('question_id', 'INTEGER NOT NULL UNIQUE'),
            ('options', 'TEXT NOT NULL'),      # JSON
        ],
        'source_model': 'ChoiceExt',
        'transform': 'direct',
    },

    'sub_question': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('question_id', 'INTEGER NOT NULL'),
            ('parent_id', 'INTEGER'),          # nullable
            ('stem', 'TEXT'),
            ('answer', 'TEXT'),
            ('sort_order', 'INTEGER NOT NULL'),
        ],
        'source_model': 'SubQuestion',
        'transform': 'direct',
    },

    'solution_method': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('sub_question_id', 'INTEGER NOT NULL'),
            ('method_name', 'TEXT'),           # nullable
            ('source', 'TEXT'),
            ('sort_order', 'INTEGER NOT NULL'),
        ],
        'source_model': 'SolutionMethod',
        'transform': 'direct',
    },

    'solution_step': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('method_id', 'INTEGER NOT NULL'),
            ('step_number', 'INTEGER NOT NULL'),
            ('title', 'TEXT NOT NULL'),
            ('content', 'TEXT NOT NULL'),      # 含 LaTeX
            ('card_titles', 'TEXT'),           # JSON list
        ],
        'source_model': 'SolutionStep',
        'transform': 'direct',
    },

    'concept_tag': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('name', 'TEXT NOT NULL UNIQUE'),
            ('parent_id', 'INTEGER'),
        ],
        'source_model': 'ConceptTag',
        'transform': 'direct',
    },

    'knowledge_card': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('title', 'TEXT NOT NULL'),
            ('content', 'TEXT NOT NULL'),
        ],
        'source_model': 'KnowledgeCard',
        'transform': 'direct',
    },

    # 多对多中间表由构建脚本从关联关系生成
    'question_concept_tag': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('question_id', 'INTEGER NOT NULL'),
            ('concept_tag_id', 'INTEGER NOT NULL'),
        ],
        'source': 'm2m:BaseQuestion.concept_tags',
    },

    'question_knowledge_card': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('question_id', 'INTEGER NOT NULL'),
            ('knowledge_card_id', 'INTEGER NOT NULL'),
        ],
        'source': 'relation',   # 从 SolutionStep.card_titles 反向解析
    },

    'course': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('name', 'TEXT NOT NULL'),
            ('description', 'TEXT'),
        ],
        'source_model': 'Course',
        'transform': 'direct',
    },

    'assignment': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('title', 'TEXT NOT NULL'),
            ('description', 'TEXT'),
            ('course_id', 'INTEGER'),
        ],
        'source_model': 'Assignment',
        'transform': 'direct',
    },

    'assignment_question': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('assignment_id', 'INTEGER NOT NULL'),
            ('question_id', 'INTEGER NOT NULL'),
            ('sort_order', 'INTEGER NOT NULL'),
        ],
        'source_model': 'AssignmentQuestion',
        'transform': 'direct',
    },

    'achievement_def': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('code', 'TEXT NOT NULL UNIQUE'),
            ('name', 'TEXT NOT NULL'),
            ('description', 'TEXT'),
            ('icon', 'TEXT'),
            ('icon_emoji', 'TEXT'),
            ('category', 'TEXT NOT NULL'),
            ('category_label', 'TEXT'),
            ('display_order', 'INTEGER'),
            ('trigger_type', 'TEXT'),
            ('threshold', 'INTEGER'),
        ],
        'source_model': 'AchievementDef',
        'transform': 'direct',
    },

    'level_config': {
        'columns': [
            ('level', 'INTEGER PRIMARY KEY'),
            ('min_xp', 'INTEGER NOT NULL'),
            ('title', 'TEXT NOT NULL'),
            ('icon_emoji', 'TEXT'),
        ],
        'source_model': 'LevelConfig',
        'transform': 'direct',
    },
}

LECTURE_TABLES = {
    'course': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('name', 'TEXT NOT NULL'),
            ('description', 'TEXT'),
        ],
        'source_model': 'Course',
        'transform': 'direct',
    },

    'chapter': {
        # 客户端独有表——服务端无此表
        # 构建时从 Document.chapter 字段 GROUP BY 生成
        'columns': [
            ('id', 'INTEGER PRIMARY KEY AUTOINCREMENT'),
            ('course_id', 'INTEGER NOT NULL'),
            ('index', 'INTEGER NOT NULL'),
            ('title', 'TEXT NOT NULL'),
        ],
        'source': 'generate:from_document_chapter',
    },

    'lecture_content': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY AUTOINCREMENT'),
            ('chapter_id', 'INTEGER NOT NULL UNIQUE'),
            ('title', 'TEXT NOT NULL'),
            ('md_content', 'TEXT NOT NULL'),
            ('updated_at', 'TEXT'),
        ],
        'source_model': 'Document',
        'transform': 'lecture_transform',  # 自定义转换函数
    },

    'assignment': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('title', 'TEXT NOT NULL'),
            ('description', 'TEXT'),
            ('course_id', 'INTEGER'),
        ],
        'source_model': 'Assignment',
        'transform': 'direct',
    },

    'assignment_question': {
        'columns': [
            ('id', 'INTEGER PRIMARY KEY'),
            ('assignment_id', 'INTEGER NOT NULL'),
            ('question_id', 'INTEGER NOT NULL'),
            ('sort_order', 'INTEGER NOT NULL'),
        ],
        'source_model': 'AssignmentQuestion',
        'transform': 'direct',
    },
}
```

### 2.3 转换类型说明

`transform` 字段取值：

| 值 | 含义 | 说明 |
|----|------|------|
| `'direct'` | 字段名完全一致，直接复制 | Django 模型字段名 = 客户端列名，值不变 |
| `'lecture_transform'` | 自定义转换函数 | Document → lecture_content：改表名、加 chapter_id、计算 updated_at |
| `'m2m:...'` | 从多对多关系生成中间表 | 如 `'m2m:BaseQuestion.concept_tags'` |
| `'relation'` | 需复杂关系推导 | 如从 SolutionStep.card_titles 反向关联 KnowledgeCard |
| `'generate:...'` | 无 Django 模型对应 | 如 chapter 表需 GROUP BY Document.chapter 生成 |

## 三、构建流程

### 3.1 总流程

```
Django DB (SQLite)
    │
    ▼
build_assets.py  /  build_lectures.py
    │
    ├── 1. 读 Django models（QuerySet）
    ├── 2. 按 schema 定义转换/映射字段
    ├── 3. 创建内存 SQLite 数据库
    ├── 4. 逐表写入数据
    ├── 5. 写入 _meta 表
    ├── 6. gzip 压缩
    └── 7. 输出到 media/db/
```

### 3.2 `_meta` 表

每个 .db 文件内建一张 `_meta` 表，客户端首次打开时读取。无需额外文件。

```sql
CREATE TABLE _meta (
    schema_version INTEGER NOT NULL,
    data_version INTEGER NOT NULL,
    checksum TEXT NOT NULL,
    built_at TEXT NOT NULL  -- ISO datetime
);
```

### 3.3 详细步骤

**build_assets.py：**

1. 读取 `DbVersion.objects.get(db_type='qbank')` 获取本次构建的版本号
2. 逐表处理：
   - `direct` 类型：直接 QuerySet.values() 写入
   - `m2m` 类型：遍历关联关系写入中间表
   - `relation` 类型：遍历 BaseQuestion → SolutionStep.card_titles → KnowledgeCard 建立关联
3. 写入完成后计算整个 .db 文件的 SHA-256 checksum
4. gzip 压缩
5. `DbVersion.checksum` / `DbVersion.size_bytes` / `DbVersion.download_url` 自动更新
6. 输出 `media/db/qbank_v{version}.db.gz`

**build_lectures.py：**

1. 读取 `DbVersion.objects.get(db_type='lecture')`
2. 逐表处理：
   - `course` / `assignment` / `assignment_question`：direct 复制
   - `lecture_content`：从 Document 转换（id → chapter_id，更新表名）
   - `chapter`：`Document.objects.all().values('course_id', 'chapter').distinct().order_by(...)` 逐行生成
3. 同 assets 流程：checksum → gzip → 更新 DbVersion → 输出

## 四、触发方式

### 4.1 系统管理页面（推荐）

`/admin/system/tools/` 自定义 Admin 视图页面中，以按钮形式触发构建：

- **「构建并发布 · 题库」** — 构建 assets.db → gzip 压缩 → 自动更新 DbVersion 的 checksum/size_bytes/download_url/data_version
- **「构建并发布 · 讲义」** — 同上，构建 lectures.db
- **「仅构建测试 · 题库」** — 只生成文件不更新版本号（用于开发验证）
- **「仅构建测试 · 讲义」** — 同上

页面底层调用与 `scripts/build_assets.py` 相同的函数，Admin 仅是可视化入口。

### 4.2 命令行（备选）

```
python scripts/build_assets.py
python scripts/build_lectures.py
```

构建脚本可直接执行，与 Admin 页面调用同样的底层函数。

## 五、验证方式

构建产物的正确性在开发阶段通过以下方式验证：

| 检查项 | 方法 |
|--------|------|
| 表结构完整 | 用 SQLite CLI `.tables` 和 `PRAGMA table_info` 检查 |
| 行数匹配 | 对关键表（question、sub_question）对比 Django 和产物中的行数 |
| 数据正确性 | 随机抽取 5 道题，对比 Django 原始数据和产物中的字段值 |
| checksum 一致 | 构建时算一次，客户端下载后算一次，确保传输无损坏 |
| drift 可读 | 用 drift 的 Database 对象直接打开 .db 文件，确认无 schema 错误 |
