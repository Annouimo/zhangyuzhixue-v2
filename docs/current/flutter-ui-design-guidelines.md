# Flutter UI 设计与实现规范

最后核验：2026-07-31

本文是章鱼智学学生端 Flutter UI 的现行开发规范，适用于
`flutter_app/lib/` 和 `packages/shared/lib/`。新功能必须遵守；修改已有页面时，
必须同步迁移所触及的旧实现，不得复制或扩大存量的不规范写法。

本规范以 Flutter 当前 Material 3 实现为基础，但保留章鱼智学的品牌色、中文排版和
教育产品信息层级。合规目标不是套用 Material 默认外观，而是建立一致、清晰、可访问、
适应手机和桌面的产品体验。

## 1. 实现入口与职责

- 全局主题、语义色和组件主题统一维护在
  `packages/shared/lib/theme/app_theme.dart`。
- 排版角色统一维护在 `packages/shared/lib/theme/app_typography.dart`。
- 间距、圆角、尺寸、断点、内容宽度和动效统一维护在
  `packages/shared/lib/theme/app_tokens.dart`。
- 跨页面复用的展示与交互组件放在 `packages/shared/lib/widgets/`。
- 只服务学生端、但跨多个业务页面复用的组件放在 `flutter_app/lib/widgets/`。
- 页面文件负责业务编排，不重复定义已有的视觉语言和通用状态组件。

当现有组件不能满足需求时，先判断是应扩展共享组件、增加新的语义组件，还是确属业务特例。
不得为了赶进度复制另一页面的 UI 实现。

## 2. 主题令牌

### 2.1 排版

- 普通界面文字必须从 `Theme.of(context).textTheme` 获取。
- 可以用 `copyWith` 调整语义颜色、字重、装饰和对齐；业务页面不得借此重新指定
  `fontSize`、`height` 或 `letterSpacing`。
- 页面标题、区块标题、卡片标题、正文、辅助说明、按钮和标签必须使用稳定的排版角色，
  不得因为局部空间不足随意创造 10、11、12、13、14、15px 等相邻字号。
- 图表刻度、数学公式、画布标注和动态缩放内容可以使用专用字号，但应封装在所属组件中，
  不得扩散到普通业务 UI。
- 中文正文必须验证换行、截断和系统文字缩放；不能以关闭文字缩放解决溢出。

### 2.2 间距、尺寸和形状

- 页面和组件间距必须优先使用 `AppSpacing`、`AppPagePadding` 和 `AppContentWidth`。
- 圆角、控件尺寸、断点和动效必须分别使用 `AppRadius`、`AppControlSize`、
  `AppBreakpoints` 和 `AppMotion`。
- 业务页面不得直接写普通布局间距、圆角或动画时长。画布坐标、图表几何和按内容计算的
  动态尺寸除外。
- 手机和桌面布局按可用宽度判断，不按设备名称判断。紧凑窗口使用 `NavigationBar`，
  中等及以上窗口使用 `NavigationRail`；应用级主导航不得使用 `BottomNavigationBar`。
- 阅读、表单和仪表盘页面必须选择适当的内容最大宽度，桌面窗口中不得无限拉伸正文。

### 2.3 颜色

- 业务代码必须通过 `ColorScheme` 或 `context.colors` 使用语义色。
- 禁止在业务页面新增品牌色、灰阶、状态色和透明度常量。
- 成功、警告、错误、提示和推荐信息必须同时提供图标或文字含义，不能只靠颜色区分。
- 新增颜色角色时，必须同时定义浅色、暗色及前景色，并验证文本对比度。

## 3. 容器与层级：避免卡片滥用

卡片只用于表达一个具有独立边界的对象，不是默认的内容分组方式。

### 3.1 应使用卡片

- 列表中的独立、可点击实体，例如试卷、视频、讲义章节、投稿、成就和同步任务。
- 需要表达选中、悬停、按下或拖动状态的对象。
- 需要与页面背景形成明确浮层关系的内容，例如桌面登录表单。
- 独立的数据摘要或必须突出的结果；同一页面应控制卡片数量和层级。

### 3.2 不应使用卡片

- 页面标题、元信息、说明文字和普通表单章节。
- 同一详情页中的正文、标签、处理记录和相关内容。
- 讲义、题目、答案与解析等连续阅读内容。
- 仅为了获得内边距、圆角或白色背景而创建的容器。
- 卡片内部的普通二级内容；禁止无明确层级意义的卡片嵌套。

以上内容应使用透明章节、留白、标题和必要的分隔线组织。需要提示语义时使用淡色
`AppCallout` 类组件，而不是普通白色 `AppCard`。

评审卡片使用时必须回答：这块内容是否是可独立识别、操作、选择或移动的对象？如果不是，
默认不使用卡片。

## 4. 组件复用

### 4.1 必须优先使用的共享能力

- 按钮使用 `AppButton`；图标操作使用统一的图标按钮组件并提供 tooltip/语义标签。
- 确认、输入和简单选择使用 `AppDialog`；普通消息使用 `AppToast`。
- 加载、错误和空状态使用统一的异步内容组件，不在页面重复编写状态分支和占位布局。
- 题干、图片、选项、答案和解析使用统一的题目内容组件。
- 成功、警告、错误、审核意见和说明使用统一的语义提示组件。
- 手机底部面板和桌面对话框属于同一操作时，使用统一的自适应 action sheet 外壳。
- 页面章节使用统一的透明 section 组件，不用 `AppCard` 代替章节。

部分目标组件仍在迁移中。在共享组件尚未提供时，新代码应先补齐共享能力，再接入业务页面；
不得因此新增另一套临时实现。

### 4.2 不做无意义的万能组件

视觉相近但业务语义不同的实体不强行合并。例如视频卡片、试卷卡片、成就卡片和同步任务
可以拥有各自组件，但它们必须使用相同的令牌、交互状态和无障碍规则。

出现以下任一情况时应评估抽取复用：

1. 同一 UI 结构在两个以上页面出现；
2. 同一状态、弹窗或操作栏被再次手工拼装；
3. 修复视觉或无障碍问题需要同时修改多个文件；
4. 新实现与已有共享组件仅有文案或图标差异。

## 5. Material 3 组件策略

- 应用主题保持 `useMaterial3: true`。
- 主操作使用 `FilledButton` 语义，次操作使用 tonal/outlined/text 层级；业务页面不得自行
  混用 `ElevatedButton` 制造新的按钮层级。
- 应用级导航只使用 `NavigationBar` 和 `NavigationRail`。
- 业务页面原则上不直接创建普通 `FilledButton`、`OutlinedButton`、`TextButton`、
  `ElevatedButton` 或裸 `AlertDialog`，而应通过项目共享组件保持尺寸、状态和文案行为一致。
- 自定义点击面必须使用 Material interaction、键盘焦点和语义；不得只用无反馈的
  `GestureDetector` 实现普通按钮或列表项。

## 6. 无障碍与交互状态

- Android 可点击目标至少为 48×48dp；视觉图标可以更小，但命中区域不能缩小。
- 不得为普通操作使用 `MaterialTapTargetSize.shrinkWrap`。空间受限的特殊控件必须证明其
  外层命中区域仍然合规。
- 纯图标操作必须有 tooltip 或明确的 semantic label。
- 自定义交互组件必须覆盖 enabled、disabled、hover、focused、pressed 和 selected 中
  与其相关的状态。
- 普通小字对背景的对比度至少 4.5:1，大字至少 3:1。
- 页面必须在浅色、暗色、窄窗口、宽窗口和放大文字下保持可读、可操作。
- 错误信息应说明如何修正；重要的破坏性操作必须确认或支持撤销。

## 7. 页面开发与评审清单

提交新增或修改的 Flutter UI 前，至少检查：

1. 是否复用了现有主题令牌，没有新增普通硬编码字号、颜色、间距和圆角；
2. 是否把普通章节误做成卡片，是否存在无意义的卡片嵌套；
3. 是否重复实现已有的加载、错误、空状态、题目展示、提示、弹窗或操作栏；
4. 手机和桌面布局是否按可用宽度适配，并限制了正文最大宽度；
5. 点击目标、语义标签、键盘焦点、文字缩放和颜色对比是否合规；
6. 是否更新相关 widget/golden 测试，并实际检查浅色、暗色、手机和桌面结果。

## 8. 存量迁移规则

当前代码仍有硬编码样式、冗余卡片和重复 UI。它们属于待迁移存量，不代表推荐做法。

- 新页面从第一行代码起执行本规范。
- 修改旧页面时，至少清理本次改动范围内的违规实现。
- 大范围迁移优先顺序为：基础令牌与共享组件、投稿和讲义样板页、做题流程、个人中心、
  其余列表与详情页。
- 不为保持旧 API 永久保留同义参数或两套组件；完成调用方迁移后删除兼容入口。
- 自动审计规则在存量清理期可以只报告旧问题，但必须阻止新增违规；迁移完成后改为全量检查。

当前可运行 `python scripts/audit/audit_flutter_ui.py` 查看存量报告；全量迁移完成后使用
`python scripts/audit/audit_flutter_ui.py --strict` 作为阻断检查。
