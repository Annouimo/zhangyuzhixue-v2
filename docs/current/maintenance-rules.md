# 仓库维护规则

最后核验：2026-07-28

## 目录边界

- 业务代码留在所属应用，不在 `docs/` 保存实现副本。
- 仓库稳定入口保持少量且可发现；辅助脚本按职责分类。
- 品牌原图只在 `assets/brand/` 维护，平台尺寸图由工具生成。
- 当前文档只写当前事实；实施过程、旧设计和阶段报告进入 `docs/archive/`。

## 变更纪律

- 功能删除、目录整理和新功能开发使用独立提交。
- 移动脚本或资产时，同一提交修复全部引用并执行相关 dry-run。
- 修改 Django 模型必须提交迁移；修改 Drift 表必须重新生成代码。
- 不提交本地数据库、构建目录、缓存、覆盖率、`.env` 或签名材料。
- 不以复制文件解决跨模块复用，除非它属于必须独立分发的产物。

## 文档状态

- `docs/current/`：必须与当前主线一致。
- `docs/decisions/`：记录长期决策，不随实现重写历史。
- `docs/archive/`：只读参考，不作为测试、发布或生产操作依据。
- `docs/_archive/`：本机备份，不进入 Git。

## 提交前检查

1. 检查 `git status`，确认没有用户数据、密钥和生成缓存。
2. 搜索移动前的旧路径和已删除领域名。
3. 运行与改动范围相称的测试。
4. 对发布或运维脚本执行语法检查和非破坏性 dry-run。
5. 同步更新 `docs/current/` 和必要的决策记录。
