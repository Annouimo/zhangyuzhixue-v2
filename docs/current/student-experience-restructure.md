# 学生端体验重组计划

最后核验：2026-07-28

实施状态：第一版已完成。本文同时保留本轮边界和下一版预留，作为后续迭代基线。

## 目标

学生端从并列的功能工具调整为简洁的学习入口。复杂选择由系统承担，学生打开推荐后直接做题；主动选题、内容学习、学习反馈和账户设置保持清晰分工。

## 一级导航

| 入口 | 回答的问题 | 本轮承载能力 |
|---|---|---|
| 推荐 | 我现在做什么？ | 单题连续推荐，新题与旧题穿插 |
| 组卷 | 我想自己组织练习 | 智能组卷、自主选题、试卷记录、预览与 PDF |
| 复盘 | 我学得怎么样？ | 做题历史、现有统计、按知识点动态汇总的掌握状态 |
| 内容 | 我需要先学什么？ | 公开讲义；预留未来内容入口 |
| 我的 | 我的目标和账户 | 偏好、积分、成就、同步与设置 |

“练习”不作为一级入口，避免与推荐练习重叠。组卷功能保持现有产品模型；计时作为试卷作答模式，不建立独立的“限时模拟”模块。

## 本轮实施边界

本轮不修改 Flutter Drift 表、Django 模型、同步实体或 API 数据契约。只重组已有功能，并完成第一版核心推荐体验。

### 推荐

- 进入推荐页后直接展示一道题，不展示题目列表。
- 保留明确且始终可发现的“下一题”按钮，不采用上滑切题。
- 未完成时允许跳过；跳过只在当前会话内影响排序，不持久化为学习结论。
- 推荐算法在本地实时运行，直接读取现有题库、概念标签、答题记录、正确性、步骤反馈和时间字段。
- 每次生成一个小批次，并在完成一题后补充候选；当前会话内避免重复题目和连续相同知识点。
- 旧题复习由系统自动混入，学生不管理复习队列，也不选择是否复习。

第一版候选来源：

1. 近期做错或完成不稳定的旧题。
2. 旧题关联知识点下尚未做过的新题。
3. 现有记录中表现较弱知识点的新题。
4. 与学生偏好和当前难度相符的普通新题。

第一版使用可解释规则评分，权重作为纯 Dart 配置集中管理。由于没有专用复习状态，复习优先级根据现有答题时间、最近结果、尝试次数和步骤反馈动态推导。推荐逻辑必须在离线状态完整可用。

### 组卷

- 保持智能组卷、自主选题和试卷管理的核心流程。
- 补齐有价值的题库浏览能力时，优先复用现有筛选器和题目卡片，不恢复教师端结构。
- 普通模式与计时模式共用同一试卷作答流程。
- 本轮计时只维护当前作答会话，不增加持久化耗时字段；需要长期报告的数据下一版再设计。

### 复盘

- 迁入现有做题历史和统计能力。
- 第一版掌握状态由现有记录按知识点动态计算，不写入数据库。
- 状态控制为“数据不足、正在形成、待巩固、基本掌握”。
- 第一版不提供学生手工安排复习、修改掌握状态或维护错题本的操作。
- 周报、完整学习报告和可持久化趋势模型不在本轮范围。

### 内容与我的

- 内容页以公开讲义和自媒体视频目录为核心。
- 视频初版提供分类浏览、详情、外部平台播放和讲义双向关联；不自建视频存储或第三方平台接口。
- 我的页承接目标与偏好、积分、成就、同步和账户设置；现有能力以迁移为主。

## 第一版实施结果

### 阶段 1：导航与功能归位（已完成）

- 建立“推荐、组卷、复盘、内容、我的”五个入口。
- 将现有讲义、历史、统计、积分、成就和设置迁入对应入口。
- 保持旧路由在重组期间可用，确认所有已有功能均可到达后再删除重复入口。

验收：没有丢失现有核心能力，一级入口之间职责不重叠。

### 阶段 2：本地推荐引擎（已完成）

- 建立不依赖 Flutter Widget 的纯 Dart 推荐模块。
- 从现有 DAO 读取候选题和学习记录。
- 实现旧题、新题、同知识点迁移题的候选生成。
- 实现难度匹配、近期重复惩罚、知识点交错和连续答题调节。
- 为固定输入提供确定、可复现的单元测试。

验收：无需新增表或联网即可稳定生成连续推荐序列。

### 阶段 3：单题推荐体验（已完成）

- 推荐 Tab 直接承载当前题目。
- 复用现有选择、填空、解答题作答与解析能力。
- 接入提交、跳过和下一题状态。
- 答题结束后用最新记录刷新后续候选。

验收：学生可连续完成推荐练习，不经过题目列表或手工复习选择。

### 阶段 4：复盘与组卷收口（已完成）

- 用现有数据生成知识点状态和学习概览。
- 整合历史与统计入口。
- 在试卷作答流程中加入非持久化计时模式。
- 补齐导航、空状态、离线状态和回归测试。

验收：推荐结果能在复盘中得到基本反馈，组卷能力没有因导航重构退化。

## 下一版预留

以下内容必须在重新审核数据模型后实施，不提前夹带进本轮：

- 错因记录与 `attempt_diagnosis`。
- 持久化题目复习状态和明确的到期队列。
- 推荐曝光、跳过、开始和切题事件。
- 跨设备推荐状态同步。
- 后台算法配置与策略版本下发。
- FSRS、BKT 或在线学习模型。
- 每题耗时、限时试卷报告和周报。
- 视频收藏、播放进度、平台数据回传和个性化推荐。

下一版新增数据前，先用本轮积累的现有答题结果和产品反馈校验状态定义，避免为尚未验证的交互提前固化表结构。
