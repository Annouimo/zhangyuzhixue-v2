# 学生端 UI 核心体验精修基线

状态：第一阶段基线

范围：学生端 UI，不新增功能，不调整业务规则
上游基准：`a6295ca test(ui): align coverage with redesigned student flows`

## 1. 目标

本阶段不再进行全页面组件迁移。现有主题、语义颜色、间距、圆角、内容宽度和响应式导航继续作为基础，只精修高频学习体验。

产品体验应同时满足以下四条原则：

1. **专业**：符合高考数学学习工具的可信、学术气质。
2. **克制**：强调色、徽章、渐变和装饰只服务于信息优先级。
3. **清晰**：学生进入页面后能快速判断当前位置、当前进度和下一步。
4. **体系化**：推荐、作业、讲义、作答、解析和反馈共同构成连续学习路径，而不是孤立工具。

## 2. 不变边界

- 不新增或删除功能。
- 不改变积分、等级、签到、推荐和组卷规则。
- 不重命名一级导航，不改变现有路由。
- 不建立第二套颜色或组件系统。
- 低频设置、关于、同步队列等页面仅接受共享组件带来的必要调整。

## 3. 核心页面与优先级

| 优先级 | 页面/流程 | 本阶段关注点 |
| --- | --- | --- |
| P0 | 主导航、首页 | 当前状态、唯一推荐行动、信息密度、移动/桌面层级 |
| P0 | 推荐/作业 → 作答 → 解析/评分 | 为什么做、做到哪里、完成后去哪里 |
| P0 | 讲义正文、步骤解析、知识卡 | 数学内容宽度、字号、行高、公式与段落留白 |
| P1 | 推荐页、作业列表/详情、讲义目录 | 入口理由、进度、状态与主操作一致性 |
| P1 | 学习统计、个人中心 | 数据摘要降噪，避免与学习主任务争夺注意力 |
| P2 | 组卷入口及列表 | 继承全局层级规则，不进行结构性重做 |

## 4. 固定测试矩阵

视觉和响应式回归统一使用 `flutter_app/test/support/ui_test_harness.dart`。

| 场景 | 逻辑尺寸 | 用途 |
| --- | --- | --- |
| mobile | 390 × 844 | 主流手机竖屏，验证首屏行动、滚动和窄屏换行 |
| desktop | 1280 × 800 | 桌面端，验证侧栏、最大内容宽度和多栏密度 |

两个尺寸均覆盖 `light`、`dark`，形成四个固定场景。需要验证特殊临界点时可以增加定向测试，但不得替代此基线。

## 5. 页面验收量表

每个核心页面按 1–5 分评估。单项低于 4 分不得结束对应阶段。

| 维度 | 5 分标准 |
| --- | --- |
| 下一步清晰度 | 3 秒内能判断唯一主要行动 |
| 信息层级 | 标题、核心内容、辅助信息和元数据主次明确 |
| 品牌一致性 | 专业、克制；颜色、图标和文案符合官网气质 |
| 学习连续性 | 明确说明来源/进度，并提供合理的完成后去向 |
| 阅读舒适度 | 长题干、公式和段落易读，无拥挤或过长行宽 |
| 响应式质量 | mobile 与 desktop 均无溢出、空洞或简单拉伸 |
| 明暗主题 | 对比度、边框、状态色和教学媒体均清楚自然 |

## 6. 强制体验规则

### 6.1 单主操作

- 一个页面或一个明确任务区域原则上只保留一个主要按钮。
- 次级操作使用次要按钮或文字按钮，不与主操作同权重。
- 同时出现多个操作时，必须能解释优先顺序。

### 6.2 强调色与徽章

- 同一屏最多保留一个主要渐变或大面积强调容器。
- 徽章只表达状态或重要属性，不重复页面标题、卡片标题或相邻数字。
- 普通信息不因“看起来丰富”而使用语义色。

### 6.3 卡片与分区

- 卡片用于形成可独立理解或可独立操作的内容单元。
- 仅用于分隔的内容优先通过留白、标题和分割线组织。
- 桌面端不得因为可用空间增加而无限增加并列强调卡片。

### 6.4 学习路径语言

核心页面尽量回答四个问题：

1. 这项内容从哪里来？
2. 为什么现在建议学习？
3. 当前完成到哪里？
4. 完成后建议做什么？

## 7. 自动验收要求

- 固定矩阵测试不得依赖操作系统主题。
- widget test 中出现 Flutter 布局异常、溢出或语义异常时直接失败。
- 核心页面至少覆盖 mobile/light 与 desktop/dark；高风险页面覆盖全部四种场景。
- 测试优先按用户可见文字、语义和操作验证，不绑定内部 `InkWell` 或具体图标字形。
- 每阶段完成后运行相关定向测试；最终运行 `flutter analyze` 和完整 `flutter test`。

## 8. 人工验收点

只安排三次短验收：

1. **首页**：手机与桌面各看一次，判断主操作和信息密度。
2. **学习闭环**：从推荐或作业进入一道题，完成解析、自评和评分。
3. **数学阅读**：查看一个讲义页面和一道多步骤解答题，重点看长文本与公式。

每次人工验收由实施方明确页面、状态、尺寸和检查问题，不要求用户全面巡检。

## 9. 阶段完成标准

- 本文档、固定测试视口和固定主题工具进入版本控制。
- 基线工具自身四种组合测试通过。
- 后续页面改动均能映射到本文件的核心页面、量表维度和强制规则。
- 第一阶段不改变任何现有页面视觉或业务行为。
