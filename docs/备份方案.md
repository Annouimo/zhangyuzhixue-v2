# 章鱼智学 v2 — 数据库备份方案

> 状态：**已实施** | 最后更新：2026-07-11

---

## 总览

两层备份互为补充，覆盖不同的丢失场景：

| 层 | 名称 | 保什么 | 存放位置 | 频率 | 自动/手动 |
|----|------|--------|---------|------|----------|
| **B** | 服务器每日全量备份 | db.sqlite3 + 构建产物（.db.gz） | `/var/backups/zhangyuzhixue-v2/db/`（与 `/opt/` 不同级） | 每天 04:00 | ✅ 自动（crontab） |
| **C** | 关键数据 JSON 导出到 Gitee | 用户/学生/教师/邀请码/作业/系统配置等业务数据 | Gitee 独立仓库 `zhangyuzhixue-v2-data`（私有） | 每天 04:10 | ✅ 自动（crontab） |

### 各层防御场景

| 场景 | B 服务器备份 | C Gitee JSON |
|------|-----------|-------------|
| 数据库文件损坏 | ✅ 有昨天的完整备份 | ✅ 有关键数据 |
| 误删 `/opt/zhangyuzhixue-v2/` | ✅ 备份在 `/var/backups/` | ✅ Gitee 上有 |
| 服务器硬盘故障 | ❌ 同机 | ✅ Gitee 远端 |
| 本地开发机硬盘坏 | ❌ | ✅ Gitee 远端 |
| 想追溯历史变更 | ⚠️ 30 天滚动 | ✅ git log 可回溯 |
| 想恢复单条记录（如某用户） | ❌ 必须全库恢复 | ✅ 从 JSON 单条摘出 |

## 方案 B — 服务器每日全量备份

### 脚本

`server/scripts/backup_db.sh`

### crontab

```bash
0 4 * * * /opt/zhangyuzhixue-v2/server/scripts/backup_db.sh
```

### 备份位置

```
/var/backups/zhangyuzhixue-v2/db/
├── db.YYYYMMDD.sqlite3.gz        ← db.sqlite3 压缩
├── qbank_v4.db.gz                ← 构建产物（直接复制）
├── qbank_v2.db.gz
├── lecture_v3.db.gz
└── lecture_v2.db.gz
```

**关键设计**：备份目录与项目目录 `/opt/zhangyuzhixue-v2/` 不同级，防止删项目时连带丢失。

### 保留策略

- db 备份保留 **30 天**滚动
- 构建产物保留 **30 天**滚动

### 恢复方式

```bash
# 列出可用备份
ls -lh /var/backups/zhangyuzhixue-v2/db/db.*.sqlite3.gz

# 恢复指定日期
gunzip -k /var/backups/zhangyuzhixue-v2/db/db.20260711.sqlite3.gz
cp /var/backups/zhangyuzhixue-v2/db/db.20260711.sqlite3 /opt/zhangyuzhixue-v2/server/db.sqlite3
systemctl restart gunicorn-math-platform
```

## 方案 C — 关键数据 JSON 导出到 Gitee

### 仓库

**独立仓库**（避免污染代码仓库）：
```
git@gitee.com:annouimo/zhangyuzhixue-v2-data.git  （私有）
```

服务器上 clone 到：
```
/var/data-dumps/zhangyuzhixue-v2-data/
```

### 导出脚本

`server/scripts/dump_data.py`

每天凌晨 04:10 自动运行，输出到上述数据仓库目录，然后 `git add` → `git commit` → `git push`。

### 自动推送脚本

`server/scripts/dump_and_push.sh`

```bash
#!/bin/bash
set -euo pipefail

# 1. 导出 JSON
python /opt/zhangyuzhixue-v2/server/scripts/dump_data.py \
    --out /var/data-dumps/zhangyuzhixue-v2-data

# 2. 提交到数据仓库
cd /var/data-dumps/zhangyuzhixue-v2-data
git add -A
git commit -m "chore(data-dump): $(date +%Y-%m-%d)" || true  # 无变化不提交
git push
```

### crontab（与方案 B 合并）

```bash
0 4 * * * /opt/zhangyuzhixue-v2/server/scripts/backup_db.sh      # 方案 B
10 4 * * * /opt/zhangyuzhixue-v2/server/scripts/dump_and_push.sh # 方案 C
```

### 恢复流程

```bash
# 1. 从 Gitee 拉数据仓库
git clone git@gitee.com:annouimo/zhangyuzhixue-v2-data.git /tmp/restore
cd /tmp/restore

# 2. 选择要恢复的日期快照
ls data_dumps/
# data_dumps/2026-07-11/  data_dumps/2026-07-12/  ...

# 3. 运行恢复脚本
python /opt/zhangyuzhixue-v2/server/scripts/load_data.py \
    --from /tmp/restore/data_dumps/2026-07-11/

# 4. 如用户密码不可用（未含 hash 的恢复场景），手动重置
python /opt/zhangyuzhixue-v2/server/manage.py changepassword <username>
```
