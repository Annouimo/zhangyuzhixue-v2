# 章鱼智学 · 更新机制

> 本文档定义客户端数据库的版本号体系、启动更新流程及强制/非强制更新规则。

---

## 一、更新对象

三个独立数据库，各自追踪版本号，各自下载 .db 整体替换：

| 数据库 | 内容 | 权限过滤 | 更新频率 |
|--------|------|---------|---------|
| assets.db | 题目、步骤、知识卡片、概念标签 | 无（所有学生可见） | 低 |
| lectures.db | 课程、章节、讲义内容、作业 | UI层过滤 course_ids 白名单 | 高 |
| user.db | 用户数据 | — | 不更新 |

## 二、版本号体系

| 版本号 | 类型 | 定义位置 | 变更者 | 不匹配时 |
|--------|------|---------|-------|---------|
| schema_version | int | Flutter 代码硬编码 + DB 内部 _meta 表 | 开发者改表结构 | 强制去商店更新 App |
| data_version | int | SharedPreferences 缓存 + 服务端返回 | 管理员上传 .db 时标注 | 按 force_update 处理 |
| app_version | semver | Flutter 包版本 | 开发者发新版时 | 仅"关于"页展示 |

## 三、统一 API

```
GET /api/sync/{type}/version
  type: qbank | lecture

响应：
{
  "schema_version": 1,
  "data_version": 5,
  "force_update": true,
  "message": "新增2025年高考真题，修正3处解析错误",
  "download_url": "/static/db/{type}_v5.db.gz",
  "checksum": "sha256:...",
  "size_bytes": 4194304
}
```

## 四、启动流程

```
App 启动 → 进入首页（不阻塞主界面）
  ↓
读 SharedPreferences 缓存（app_qbank_version / app_lecture_version）
  ↓
并发调用两个 version 接口
  ↓
schema_version ≠ 本地？
  ├─ 是 → 弹框 "请去应用商店更新 App"
  └─ 否 → data_version > 本地缓存？
       ├─ force_update == true
       │   └─ 全屏弹窗 [立即更新]（不可关闭）
       │       点击 → 前台弹窗 + 进度条 + "请不要退出"
       │       完成 → 验证 checksum → 替换 .db → 重启到首页
       │       失败 → 下次启动重试
       └─ force_update == false
            └─ 右下角横幅 5s [更新] [稍后]
                或 本地落后 ≥ 3 个版本 → 转为强制
```

## 五、更新窗口规则

### 强制更新（满足任一即强制）

1. 管理员上传时标注 `force_update: true`
2. 本地版本落后服务端 ≥ 3 个版本
3. `schema_version` 不匹配

### 非强制更新

- 每次启动展示右下角横幅，5s 后自动消失
- 用户可点击「稍后」关闭
- 不限制跳过次数

### 下载中操作规范

- 前台弹窗 + 进度条，提示"请不要退出此页面"
- 不阻塞用户操作，但替换前不触发数据库读取
- 完成验证后关闭旧 Drift 连接 → 覆盖文件 → 重新打开 → 恢复界面

## 六、与同步队列的关系

更新机制与同步队列同属通信层面，但方向相反：

```
┌────────────────────────────────────────────┐
│        通信层面（Client ↔ Server）           │
│                                            │
│  ┌─────────────┐     ┌──────────────────┐  │
│  │  更新机制     │     │  同步队列          │  │
│  │  Server→Client │     │  Client→Server   │  │
│  │  .db 整体下发  │     │  用户操作批量推送   │  │
│  └─────────────┘     └──────────────────┘  │
│                                            │
│  共同基础设施：                              │
│  - 同一套 API 认证                           │
│  - 统一由 SyncManager 协调启动时序            │
│  - 网络失败处理策略一致                       │
└────────────────────────────────────────────┘
```
