# 品牌颜色系统与深色模式设计规范

学生端 / 教师端 / Landing / Android / iOS / PWA


**版本：V1.0（技术落地版）**

日期：2026 年 7 月 24 日

状态：品牌方向已确认；可进入开发实施


> **已确认的核心方向**
>
> 图标保持现有渐变与立体效果；品牌蓝和交互主色分离；学生端优先，教师端完全共用；浅色与深色一次性完整适配；默认跟随系统；核心界面达到 WCAG AA；渐变只用于品牌展示。


## 0. 文档用途与最终结论
本文档是颜色设计、主题开发、跨平台资源修改和验收的统一依据。除 App
图标本身外，业务页面不得继续新增任意硬编码颜色。


> **一句话方案**
>
> 图标用明亮的品牌蓝保持识别度；操作界面使用同色相、更深且通过对比度要求的交互蓝；浅色模式采用轻微偏冷的中性灰，深色模式采用深蓝灰；暖金色承担智能推荐与收藏，红色只承担错误与危险。

## 1. 设计原则与色彩架构
### 1.1 设计目标
- 专业：保证长时间阅读舒适、信息层级清晰，避免“满屏高饱和蓝”。
- 科技：保留图标的明亮蓝色识别度，在重点品牌场景使用渐变和冰蓝装饰。
- 创新：通过品牌蓝与暖金推荐色建立差异，但不引入过多紫色、粉色或装饰色。
- 学生端优先：高中生是核心用户；教师端共享同一系统，以降低维护成本。
- 可实现：所有颜色均落为语义令牌，Flutter、CSS、Android、iOS 与 PWA
  使用同一命名逻辑。

### 1.2 四层色彩架构
| **层级**          | **职责**                                                                               |
|-------------------|----------------------------------------------------------------------------------------|
| 第 1 层：品牌色   | 图标提取的明亮蓝、浅蓝、白色；用于品牌识别。                                           |
| 第 2 层：基础色阶 | Blue、Neutral、Green、Amber、Red；不直接在业务代码中使用。                             |
| 第 3 层：语义令牌 | primary、background、textPrimary、success、recommendation 等；业务代码主要使用这一层。 |
| 第 4 层：组件令牌 | buttonPrimaryBg、inputBorderFocus、statusCompletedBg 等；组件库内部使用。              |


> **禁止事项**
>
> 不得根据页面“看起来差不多”临时选色；不得把 #1488F7 直接用于所有白字按钮；不得在深色模式中简单反色；不得继续使用 Colors.grey / Colors.black54 作为万能颜色。

### 2.2 品牌蓝与交互蓝为什么分开
brandBlue #1488F7 与白色文字的对比度约为 3.56:1，不满足普通文字
4.5:1；primary #006BD1 与白色文字约为 5.22:1，满足
AA，并且保持相同的蓝色家族。


> **使用规则**
>
> brandBlue 负责“看起来像我们的品牌”；primary 负责“让用户清楚、安全地操作”。两者同源，但职责不同。

### 4.2 主题选择规则
- 默认值：跟随系统（ThemeMode.system / prefers-color-scheme）。
- 设置项：跟随系统、浅色、深色三档；用户选择需要持久化。
- 上线方式：所有主要页面、弹窗、空状态、错误页和原生启动资源一次性适配完成后开放。
- 学生端与教师端使用完全相同的令牌；不得让教师端停留在白底或半残深色状态。

## 6. 组件交互规则
| **组件**        | **颜色状态**                            | **规则**                                            |
|-----------------|-----------------------------------------|-----------------------------------------------------|
| 主要按钮        | primary → primaryHover → primaryPressed | 每页原则上只保留一个主要操作；普通按钮不使用渐变。  |
| 次要按钮        | surface + primaryBorder + primary       | 用于次级操作；深色模式改用 primaryContainer。       |
| 文字按钮 / 链接 | primary；hover 使用 primaryPressed      | 正文链接必须可识别；不要只用下划线或只用颜色。      |
| 输入框默认      | surface + borderStrong + textPrimary    | 标签不能只靠 placeholder；错误态切换到 error。      |
| 输入框焦点      | primaryBorder + focusRing               | Web 使用 focus-visible，移动端保留清晰焦点/选中态。 |
| 底部导航选中    | primary + primaryContainer              | 未选中使用 textMuted；选中同时改变图标和文字。      |
| 禁用态          | disabledBackground + disabledForeground | 去掉阴影和点击；不要只给整个复杂组件统一透明度。    |
| 弹窗遮罩        | scrim                                   | 浅色 rgba(8,18,32,.56)；深色 rgba(0,0,0,.64)。      |
| 阴影            | shadow                                  | 浅色可用柔和阴影；深色主要依靠表面层级和边框。      |

### 6.1 品牌渐变的允许范围
- 允许：App 图标、官网首屏、课程封面、宣传海报、欢迎页装饰、少量品牌/AI
  入口卡片。

- 禁止：普通主按钮、表单、状态标签、错误提示、正文导航、教师管理表格。
- 同一页面最多保留一个主要渐变视觉区域，避免所有元素争夺注意力。

## 7. 深色模式、LaTeX 与教学图片
### 7.1 LaTeX 公式
- 公式默认继承 textPrimary，不在 LaTeX 内容中写死 black / white。
- 说明性公式可以使用
  textSecondary；只有错误、正确或推荐强调才使用语义色。

- 检查并清理 \color{black}、\textcolor{black}{...} 等硬编码命令。
- 当前没有曲线、几何图或多数据系列，因此不建立独立数学绘图色板。

### 7.2 白底 WebP 教学图片
- 浅色和深色模式均放入固定 mediaSurface=#FFFFFF 的媒体容器。
- 建议内边距 12–16 px，圆角 12 px；深色模式添加
  imageBorder，避免白块边缘突兀。

- 禁止使用 filter: invert(1) 或图片整体反色，避免文字和彩色标记失真。
- 图片说明文字位于白色容器外，继续使用当前主题的 textSecondary。


> **后续升级条件**
>
> 只有当深色模式下白底图片明显影响夜间使用，才考虑重新导出透明背景、制作深色版本或改为 SVG/HTML/LaTeX；当前无需为数学内容单独建色板。

| 透明底白色 Logo | 新增长期资产            | 用于品牌蓝启动屏、深色背景、页眉和单色场景。应从源矢量重绘，不建议从 PNG 粗暴抠图。 |
| 透明底彩色 Logo | 建议新增                | 用于白色/浅色背景；保留蓝色与浅蓝层次。                                             |
| 深色单色 Logo   | 可选                    | 仅在印刷或极简深色背景需要时使用。                                                  |

### 8.2 启动屏
- 学生端和教师端完全统一：纯色 brandBlue #1488F7 背景 +
  居中的透明底白色 Logo。

- 不要把完整蓝色方形 App 图标再次放到蓝色背景上。
- 浅色/深色系统均可使用同一品牌启动屏，避免模式切换时出现白闪。
- Android drawable 与 drawable-v21、values 与 values-night
  必须一致；teacher_app 补齐 colors.xml。

- iOS LaunchScreen 不再固定 white，也不再引用已经删除的
  LaunchImage；使用命名颜色和有效 Logo 资产。


> **Logo 实施提醒**
>
> 透明底白色 Logo 需要从设计源文件或矢量结构重新输出。当前图标中白色主体与浅蓝无限符号存在叠加关系，直接全白化可能丢失层次，需由设计稿确认其单色结构。

### 9.2 Flutter 主题结构
```dart
MaterialApp(
  theme: AppTheme.light,
  darkTheme: AppTheme.dark,

```


建议使用 Material 3 ColorScheme 承载 primary、surface、error
等标准字段，再通过 ThemeExtension 补充
recommendation、successContainer、mediaSurface、scrim 等产品语义。

### 9.3 CSS / Landing
```css
:root {
  --color-primary: #006BD1;
  --color-primary-hover: #0062C4;
  --color-background: #F6F8FB;
  --color-surface: #FFFFFF;
  --color-text-primary: #172033;
}

@media (prefers-color-scheme: dark) {
  :root:not([data-theme]) {
    --color-primary: #5CAEFF;
    --color-background: #0B1220;
    --color-surface: #111C2D;
    --color-text-primary: #F4F7FB;
  }
}

[data-theme="dark"] {
  /* 显式深色覆盖 */
}

[data-theme="light"] {
  /* 显式浅色覆盖 */
}
```


Landing 必须补充 hover、active、focus-visible、disabled
和文本选择颜色。手动主题优先级高于系统媒体查询。
