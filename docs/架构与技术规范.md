# 章鱼智学 · 项目架构与技术规范

> 本文档定义项目的整体架构、目录结构、数据流规范，以及 HTML 原型 ↔ Flutter 代码的对照关系。

---

## 一、整体架构

```
┌─────────────────────────────────────────────────────────┐
│                   客户端 (Flutter)                        │
│  ┌───────────┐  ┌───────────┐  ┌───────────────────┐   │
│  │  UI 层     │  │ Repository │  │ 本地缓存           │   │
│  │ (Widget)   │◀─│ (数据适配)  │◀─│ (SQLite / Hive)   │   │
│  └───────────┘  └───────────┘  └────────┬────────────┘   │
│                                         │                │
└─────────────────────────────────────────┼────────────────┘
                                          │ REST API
┌─────────────────────────────────────────┼────────────────┐
│                   服务器 (Django)         │                │
│                                         ▼                │
│  ┌──────────────────────────────────────────────────┐    │
│  │  4 个 App：                                     │    │
│  │  question_bank · course_center                  │    │
│  │  user_management · learning_interaction         │    │
│  └──────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────┘
```

### 数据流

```
  Django DB (MySQL/PostgreSQL)
         │
         ▼
  Django REST Framework API  ←── 服务器
         │
         ▼
  Flutter 本地缓存 (首次加载后存储)
         │
         ▼
  Repository 层 (组合数据、适配 UI)
         │
         ▼
  Flutter UI Widget (展示 + 交互)
```

**核心原则**：Repository 按 **UI 页面需求** 组织数据，不直接暴露数据库表结构。

## 三、HTML 原型标记体系

HTML 原型中通过 5 种自定义属性标记所有与数据库交互的点位：

### 3.1 标记总览

| 属性 | 含义 | 示例 | 对应 Flutter 层 |
|------|------|------|----------------|
| `data-db` | 📖 **只读显示** | `data-db="user.getInfo.realName"` | Repository 方法返回值 |
| `data-db-bind` | 🔄 **双向绑定** | `data-db-bind="auth.login.username"` | TextEditingController + 初始值 |
| `data-db-action` | ✏️ **写入操作** | `data-db-action="rating.submit()"` | Repository 写入方法 |
| `data-db-loop` | 🔁 **列表循环** | `data-db-loop="assign.getPending"` | ListView.builder 数据源 |
| `data-db-empty` | 📭 **空状态文案** | `data-db-empty="暂无待办作业"` | 列表为空时的占位 |

### 3.2 路径命名规范

```
格式：{repository缩写}.{方法名}[].{字段名}
          ↑          ↑          ↑
       哪个层      哪个方法    哪个字段
```

- 首段：Repository 的缩写（`user`、`assign`、`question`、`exam`、`lecture` 等）
- 中段：Repository 的方法名（camelCase）
- `[]`：表示当前数据是一个列表中的单个元素
- 尾段：返回对象的字段（camelCase）

**示例：**

```
data-db="assign.getPending[].title"
         └─┬──┘ └──┬───┘  └──┬──┘
        Repo    方法     字段

data-db-action="exam.downloadPdf(1)"
                └─┬──┘ └──┬────┘  └┬┘
               Repo     方法     参数
```

### 3.3 标记颜色辅助（仅在原型中）

`styles.css` 中对标记了 data-db 的元素加了背景高亮，方便识别：

```
[data-db]       → 浅黄底色 + 橙色虚线下划线
[data-db-loop]  → 蓝色虚线边框
[data-db-empty] → 显示 ⚡ 空状态提示
```

这些 CSS 仅用于原型开发阶段，Flutter 正式代码中不保留。

## 四、Repository 层规范

### 4.1 职责

Repository 的职责是 **为 UI 层提供组合好的数据对象**，而不是映射数据库表。

```
❌ 错误做法（暴露数据库结构）：
   AssignmentRepository.getAll()              → Assignment 表
   ClassCourseAssignmentRepository.getByXxx() → 发布表
   // UI 层需要自己 join 3 张表

✅ 正确做法（按 UI 需求组织）：
   AssignmentRepository.getPendingAssignments() → List<AssignmentSummary>
   // 返回已包含 title/courseName/doneCount/deadline 等 UI 需要的一切字段
```

### 4.2 8 个 Repository

| Repository | 方法 | 返回数据 |
|------------|------|---------|
| **AuthRepository** | `login()`, `register()` | 登录/注册结果 |
| **UserRepository** | `getUserInfo()`, `getAnswerHistory()`, `getPointsHistory()` | 用户信息、历史记录 |
| **AssignmentRepository** | `getPendingAssignments()`, `getAssignmentQuestions()` | 作业列表、题目列表 |
| **QuestionRepository** | `getQuestionDetail()`, `getRecommended()`, `searchQuestions()`, `getFilterOptions()` | 题目详情、推荐、搜索 |
| **ProgressRepository** | `getSteps()`, `submitStepFeedback()` | 解题步骤序列、反馈记录 |
| **RatingRepository** | `getRating()`, `submitRating()` | 用户评分 + 算法评分 |
| **ExamRepository** | `buildSession()`, `getMyExams()`, `getPreview()`, `getQuickAnswers()`, `createExam()`, `deleteExam()` | 组卷全流程 |
| **LectureRepository** | `getCourses()`, `getChapters()`, `getContent()` | 讲义三级页面 |

| 路径前缀 | 对应 Repository | 常见方法 |

## 六、工作流程

### HTML 原型 → Flutter 代码

```
1. 设计阶段
   UI_Phase1.canvas（手绘草图）
        │
        ▼
   UI_Phase2/*.html（可交互原型）
        │
        ▼
   评审定稿
        │
        ▼
2. 开发阶段
   Flutter UI Widgets（对照 HTML 布局）
   Repository 层（对照 data-db 标记）
        │
        ▼
3. 数据对接
   Repository 方法返回 JSON → UI Widget 绑定
   data-db 路径 = Repository 返回对象中的字段
```

### 更新数据库操作清单

修改 HTML 原型后，如需更新操作清单：

```bash
python docs/scan_db_ops.py
```

会自动扫描所有 HTML 文件，重新生成 `Database/操作清单_建议方案.md`。
