> 本文档定义项目的整体架构、数据流规范，以及 HTML 原型 ↔ Flutter 代码的对照关系。

## 一、整体架构

```
┌─────────────────────────────────────────────────────────────────────┐
│                    客户端 (Flutter)                                  │
│  ┌───────────┐  ┌───────────┐  ┌──────────────────┐  ┌──────────┐ │
│  │  UI 层     │  │ Repository │  │ SQLite (drift)    │  │ 同步引擎  │ │
│  │ (Widget)   │◀─│ (数据拼装)  │◀─│ 只读缓存/本地数据  │◀─│ 拉取+推送 │ │
│  └───────────┘  └───────────┘  └──────────────────┘  └─────┬────┘ │
│                                                            │      │
└────────────────────────────────────────────────────────────┼──────┘
                                                             │ HTTPS
┌────────────────────────────────────────────────────────────┼──────┐
│                    服务器 (Django)                           │      │
│                                                            ▼      │
│  ┌────────────────────────────────────────────────────────────┐   │
│  │  旧版 API (运行中) → 逐步重构为新版 Django                  │   │
│  │  适配点仅在 Flutter 的 api_client.dart / sync_api.dart     │   │
│  └────────────────────────────────────────────────────────────┘   │
└───────────────────────────────────────────────────────────────────┘
```

### 数据流

```
  Django DB
     │
     ▼
  Django REST API  ←── 服务器（旧版逐步过渡到新版）
     │
     ▼
  Flutter 同步引擎 (启动时/手动)
     ├→ 拉取：版本号检查 → 全量/增量下载 → 写入 SQLite
     └→ 推送：sync_queue 出队 → POST → 失败重试
     │
     ▼
  SQLite (drift)
     ├→ 只读缓存：题库、课程、讲义（服务端权威，版本号增量更新）
     └→ 读写数据：提交、评分、组卷（本地优先，队列同步到服务器）
     │
     ▼
  Repository 层 (按 UI 需求组合数据)
     │
     ▼
  Flutter UI Widget (展示 + 交互)
```

**核心原则**：
- Repository 按 UI 页面需求组织数据，不暴露数据库表结构
- Drift 模型 = 数据库表的一行（原始字段）；Repository 模型 = UI 要的样子（已拼装/计算）
- 两者不同，不强行统一

## 三、HTML 原型标记体系

### 3.1 标记总览

| 属性 | 含义 | 示例 | 对应 Flutter 层 |
|------|------|------|----------------|
| `data-db` | 📖 只读显示 | `data-db="user.getInfo.realName"` | Repository 方法返回值 |
| `data-db-bind` | 🔄 双向绑定 | `data-db-bind="auth.login.username"` | TextEditingController + 初始值 |
| `data-db-action` | ✏️ 写入操作 | `data-db-action="rating.submit()"` | Repository 写入方法 |
| `data-db-loop` | 🔁 列表循环 | `data-db-loop="assign.getPending"` | ListView.builder 数据源 |
| `data-db-empty` | 📭 空状态文案 | `data-db-empty="暂无待办作业"` | 列表为空时的占位 |

### 3.2 路径命名规范

```
格式：{repo缩写}.{方法名}[].{字段名}
```

- 首段：Repository 类名去掉 `Repository` 后首字母小写（`assign` ← `AssignmentRepository`）
- 中段：Repository 的方法名，camelCase
- `[]`：列表中的单个元素
- 尾段：返回对象的字段名，camelCase

**示例：**

```
data-db="assign.getPending[].title"
         assign  ← AssignmentRepository
                 getPending  ← getPendingAssignments()
                          title  ← AssignmentSummary.title

data-db-action="exam.downloadPdf(1)"
                exam  ← ExamRepository
                     downloadPdf  ← downloadPdf()
```

### 3.3 标记颜色辅助（仅在原型中）

`styles.css` 中对标记了 `data-db` 的元素加了背景高亮，仅用于原型开发阶段：

```
[data-db]       → 浅黄底色 + 橙色虚线下划线
[data-db-loop]  → 蓝色虚线边框
```

## 四、Repository 层规范

### 职责

Repository 为 UI 层提供组合好的数据对象，不直接暴露数据库表结构。

```
❌ 错误：AssignmentRepository.getAll()
         + ClassCourseAssignmentRepository.getByXxx()
         + CourseRepository.getById()
   → UI 层自己 join 3 张表

✅ 正确：AssignmentRepository.getPendingAssignments()
   → 返回已经包含 title/courseName/doneCount/deadline 等所有字段的对象
```

### 与数据库模型的关系

```
Drift Table (存)   →  数据类 = 数据库表的一行，含主键/外键/原始字段
Repository (用)    →  数据类 = UI 需要的样子，已拼装/已计算
```

两者用途不同，各自独立。Repository 方法内部负责：查 DB → JOIN/计算 → 拼装 → 返回 Repository 模型。

### 实现文件

见 `spec/Repository/` 目录下的 8 个 Dart 文件，每个文件自包含 Repository 类 + 相关的数据模型类：

| 文件 | Repository | 对应页面 |
|------|------------|---------|
| `auth_repository.dart` | AuthRepository | login, register |
| `user_repository.dart` | UserRepository | home, profile, question_history, points |
| `assignment_repository.dart` | AssignmentRepository | homework, homework_detail |
| `question_repository.dart` | QuestionRepository | solve, recommend, paper_builder |
| `progress_repository.dart` | ProgressRepository | solve（步骤） |
| `rating_repository.dart` | RatingRepository | solve（评分） |
| `exam_repository.dart` | ExamRepository | paper_builder, paper_quicklook, answer_sheet, paper_history |
| `lecture_repository.dart` | LectureRepository | lecture_courses, lecture_chapters, lecture_content |

这些 Dart 文件是**可运行的规格说明书**：编译通过，运行时抛 `UnimplementedError`。新建 Flutter 项目时直接复制进去，替换 `throw` 为真正的实现即可。

## 五、本地缓存与同步方案

### 5.1 数据分类

| 类别 | 内容 | 写入方 | 同步方式 |
|------|------|--------|---------|
| 题库 | 题目、步骤、知识卡片、概念标签 | 仅服务端 | 版本号增量拉取 |
| 元数据 | 课程、作业、讲义 | 仅服务端 | 版本号增量拉取 |
| 用户操作 | 提交记录、步骤反馈、评分 | 本地用户 | 队列推送到服务器 |
| 组卷 | 学生自组试卷 | 本地用户 | 队列推送到服务器 |
| 积分 | 积分余额 | 服务器计算 | 本地只缓存显示 |

### 5.2 本地数据库

- **选型**：SQLite（通过 drift ORM）
- **结构**：24 张表 + 同步队列表 + 版本号表
- **迁移**：Drift MigrationStrategy 管理
- **表设计依据**：`docs/服务器_数据库结构.md`

### 5.3 同步策略

**拉取（服务器 → 客户端）**：
- 版本域：题库、讲义、课程元数据分别维护版本号
- 启动时检查版本号，需要时全量（或增量 delta）拉取
- MVP 阶段先全量拉取后补增量

**推送（客户端 → 服务器）**：
- 用户写入操作先落本地 SQLite，同时追加 `sync_queue`
- App 启动时/手动触发批量推送
- 失败指数退避重试（最多 5 次）
- 冲突用 LWW（last-write-wins）+ 服务器去重

### 5.4 与旧版 Django 的适配

服务器端先用旧版 Django，逐步重构：

```
旧版 Django API  →  Flutter API 层 (api_client.dart / sync_api.dart)
                     ↑ 这里做字段映射，是唯一的"旧版适配点"
                     ↓ 以下全部不改
                  SQLite + Repository + UI
```

新版 Django 上线后，只改 API 层的字段映射，其余层不动。

## 七、工作流程

### HTML 原型 → Flutter 代码

```
1. 设计阶段
   UI_Phase1.canvas（手绘草图）
        │
        ▼
   UI_Phase2/*.html（可交互原型）
        │
        ▼
   评审定稿
        │
        ▼
2. 开发阶段
   Flutter UI Widget → 对照 HTML 布局
   Repository 层     → 对照 data-db 标记 + spec/Repository/*.dart
   SQLite (drift)    → 对照 docs/服务器_数据库结构.md
        │
        ▼
3. 数据对接
   把 repository.dart 中 throw UnimplementedError
   替换为 drift DAO 调用 + API 调用
```

### 修改 HTML 后的同步流程

修改 HTML 中的 `data-db` 路径后，需要同步更新：

```
1. 修改的 HTML 文件            ← data-db 路径
2. 对应的 repository.dart      ← 模型字段名或方法返回结构
3. 所有 HTML 中相同路径的其他页面 ← 全文搜索确保一致性
```
