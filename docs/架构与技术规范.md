> 它是项目的统一概览文档，覆盖产品设计视角和开发实现视角的核心决策。

## 一、整体架构

> 📐 完整架构图见 [docs/章鱼智学架构图.html](章鱼智学架构图.html)（SVG 图形，浏览器打开）

系统采用 **7 层分层架构 + 横切关注点** 设计，从上到下依次为：

| 层 | 角色 | 核心组件 |
|----|------|---------|
| **表现层** · Presentation | UI 渲染与交互 | Flutter Widget / HTML 原型(data-db体系) / 路由 / 常量文案 |
| **领域层** · Repository/Domain | 数据拼装与业务算法 | 13 个 Repository（8 简单读写 + 5 尾部私有算法类） |
| **数据访问层** · Data Access | 存储抽象与网络抽象 | Drift DAO（表级 CRUD）/ API Client（JWT 自动刷新） |
| **本地持久化层** · Local Storage | 数据实际存储 | SQLite 三库（assets/lectures/user）/ 图片 / SharedPrefs |
| **通信基础设施层** · Communication | 服务端双向通信 | 同步引擎（队列推送）/ 更新机制（版本检查 + .db 替换） |
| **服务端层** · Server | 后端 API 与管理 | Django REST API（5 App）/ Django Admin / JWT 认证 |
| **基础设施层** · Infrastructure | 网络与部署 | nginx / Landing 着陆页 / Cloudflare Tunnel / ECS |

**横切关注点：**
- **测试**：单元测试 → 集成测试 → UI 测试 → 离线测试 → E2E，贯穿各层
- **构建时**：构建脚本（Django data → assets.db / lectures.db）、WebP 转码
- **data-db 标记体系**：HTML 属性 → Repository 接口的映射规范

### 数据流

```
                   ┌─────────────────────────────────┐
                   │  用户操作（Widget 交互触发）       │
                   └──────────────┬──────────────────┘
                                  │
                                  ▼
 ┌──────────────────────────────────────────────────────────────────┐
 │  Repository 层（按 UI 需求组合数据）                               │
 │  简单方法 → 直接查 DB | 复杂算法 → 委托尾部私有类                  │
 └──────┬────────────────────────────────────┬─────────────────────┘
        │ 读                                 │ 写
        ▼                                    ▼
 ┌──────────────┐                  ┌──────────────────┐
 │ Drift DAO    │                  │ 本地 SQLite       │
 │ (表级 CRUD)  │                  │ (即时写入)        │
 └──────┬───────┘                  └────────┬──────────┘
        │                                   │
        ▼                                   ▼
 ┌────────────────┐              ┌───────────────────────┐
 │ SQLite 三库     │              │ sync_queue 队列表     │
 │ assets /       │              │ entity_type / payload │
 │ lectures /     │              │ status / retry_count  │
 │ user           │              └──────────┬────────────┘
 └────────────────┘                         │
                                            │ 批量推送
                                            ▼
                              ┌────────────────────────┐
                              │ API Client (HTTP 封装)  │
                              │ JWT 刷新 · 401 重定向   │
                              └──────────┬─────────────┘
                                         │ HTTPS
                                         ▼
 ┌──────────────────────────────────────────────────────────────┐
 │  Django REST API (/api/v1/)                                   │
 │  accounts / qbank / courses / interactions / system           │
 │  └→ POST /api/sync/push（用户数据接收）                        │
 │  └→ GET /api/sync/{type}/version（版本号检查）                 │
 └──────────────────────────────────────────────────────────────┘
                                         │
                                         ▼
                              ┌──────────────────────┐
                              │  服务端 SQLite (WAL)  │
                              └──────────────────────┘

更新机制（与同步并列，方向相反）：
  版本 API → 弹窗 → .db.gz 下载 → 校验 checksum → 整体替换文件
  （同步是 Client→Server，更新是 Server→Client）

认证数据流（横切，由 API Client 承载）：
  登录 → JWT 存 SharedPrefs → API Client 自动添加 Authorization header
  access 过期 → 自动用 refresh 刷新 → 刷新失败 → 跳登录页
```

**核心原则：**
- **本地优先**：离线可做题，网络仅用于同步和更新
- **三库独立整体替换**：assets.db / lectures.db / user.db 各自追踪版本号
- **Repository 按 UI 需求组织数据**，不暴露数据库表结构
- **Drift 模型 = 数据库原始字段**；**Repository 模型 = UI 需要的样子**（已拼装/计算），两者不同不强行统一
- **镜像原则**：客户端 DB 结构与服务端一致，差异只在渲染层（纯内存函数）做
- **通信层两层并行**：同步引擎（Client→Server）与更新机制（Server→Client）共用 API Client 和网络监听

## 三、HTML 原型标记体系

### 3.1 标记总览

| 属性 | 含义 | 示例 | 对应 Flutter 层 |
|------|------|------|----------------|
| `data-db` | 📖 只读显示 | `data-db="user.getInfo.realName"` | Repository 方法返回值 |
| `data-db-bind` | 🔄 双向绑定 | `data-db-bind="auth.login.username"` | TextEditingController + 初始值 |
| `data-db-action` | ✏️ 写入操作 | `data-db-action="rating.submit()"` | Repository 写入方法 |
| `data-db-loop` | 🔁 列表循环 | `data-db-loop="assign.getPending"` | ListView.builder 数据源 |
| `data-db-empty` | 📭 空状态文案 | `data-db-empty="暂无待办作业"` | 列表为空时的占位 |

### 3.2 路径命名规范

```
格式：{repo缩写}.{方法名}[].{字段名}
```

- 首段：Repository 类名去掉 `Repository` 后首字母小写（`assign` ← `AssignmentRepository`）
- 中段：Repository 的方法名，camelCase
- `[]`：列表中的单个元素
- 尾段：返回对象的字段名，camelCase

**示例：**

```
data-db="assign.getPending[].title"
         assign  ← AssignmentRepository
                 getPending  ← getPending()
                          title  ← AssignmentSummary.title

data-db-action="exam.downloadPdf(1)"
                exam  ← ExamRepository
                     downloadPdf  ← downloadPdf()
```

### 3.3 标记颜色辅助（仅在原型中）

`styles.css` 中对标记了 `data-db` 的元素加了背景高亮，仅用于原型开发阶段：

```
[data-db]       → 浅黄底色 + 橙色虚线下划线
[data-db-loop]  → 蓝色虚线边框
```

### 3.4 SharedPreferences 标记说明

SharedPreferences **不纳入 `data-db` 标记体系**。原因：
- SharedPreferences 不直接驱动 UI 渲染（token、冷却时间、版本弹窗记录均为后台状态）
- `data-db` 的意义是「指着 HTML 元素说数据来自 Repository 的哪个方法」，原型评审者不需要看 key 名

SharedPreferences key 在 Flutter 代码中各页面的 `_Prefs` 类中声明，详见 [Flutter代码规范.md](Flutter代码规范.md) 的页头编译常量规范。

### 3.5 LaTeX/MD 渲染标注

以下 data-db 路径的值可能含 Markdown 和/或 LaTeX 数学公式，Flutter 实现时统一用 `MdLatexBody` 组件渲染。该组件位于 `spec/md&LaTex/md_latex_body.dart`，封装了 `flutter_markdown_plus` + `flutter_math_fork`，支持 `$...$` 行内公式和 `$$...$$` 块级公式。

| data-db 路径 | 内容类型 | 出现页面 |
|-------------|---------|---------|
| `question.getDetail.stem` | 题干 Markdown + LaTeX 公式 | solve-choice/fill/solve (题干区) |
| `progress.getSolveState.subQuestions[].solutions[].steps[].analysis` | 步骤解析 LaTeX 公式 | solve-solve (步骤解析区) |
| `lecture.getContentParsed.pages[].blocks[]` | 讲义正文 Markdown + LaTeX（解析后：pages 外层循环，blocks 内层循环） | lecture_content |
| 知识卡片弹层内容 | 卡片说明 LaTeX | solve-solve, lecture_content |
| `question.getDetail.conceptTags` | 概念标签列表（用 Chip + Wrap 渲染，非 LaTeX） | solve-choice/fill/solve |

## 四、工作流程

### HTML 原型 → Flutter 代码

```
1. 设计阶段
   UI_Phase1.canvas（手绘草图）
        │
        ▼
   UI_Phase2/*.html（可交互原型）
        │
        ▼
   评审定稿
        │
        ▼
2. 开发阶段
   Flutter UI Widget → 对照 HTML 布局
   Repository 层     → 对照 data-db 标记 + spec/Repository/*.dart
   SQLite (drift)    → 对照 docs/数据库结构设计.md
        │
        ▼
3. 数据对接
   把 repository.dart 中 throw UnimplementedError
   替换为 drift DAO 调用 + API 调用
```

### 修改 HTML 后的同步流程

修改 HTML 中的 `data-db` 路径后，需要同步更新：

```
1. 修改的 HTML 文件            ← data-db 路径
2. 对应的 repository.dart      ← 模型字段名或方法返回结构
3. 所有 HTML 中相同路径的其他页面 ← 全文搜索确保一致性
```
