## 一、整体架构

```
┌──────────────────────────────────────────────────────────────────┐
│                    客户端 (Flutter)                                │
│                                                                  │
│  ┌───────────┐  ┌───────────┐  ┌──────────────────────────────┐ │
│  │  UI 层     │  │ Repository │  │ SQLite (drift)                │ │
│  │ (Widget)   │◀─│ (数据拼装)  │◀─│ ├─ assets 预置题库 (只读)   │ │
│  └───────────┘  └───────────┘  │ └─ 用户数据 (读写, 本地优先)   │ │
│                                 │       │                        │ │
│  ┌───────────┐                  │ sync_queue → 推送服务器        │ │
│  │ 版本检查   │──→ 版本落后 → 提示用户去商店更新                    │ │
│  └───────────┘                                                   │ │
└──────────────────────────────────────────────────────────────────┘
                                                             │ HTTPS
┌────────────────────────────────────────────────────────────┼──────┐
│                    服务器 (Django)                           │      │
│                                                            ▼      │
│  ┌────────────────────────────────────────────────────────────┐   │
│  │  新版 Django REST API                                       │   │
│  │  提供接口：用户数据接收 + 版本号检查 + Admin 管理后台         │   │
│  └────────────────────────────────────────────────────────────┘   │
└───────────────────────────────────────────────────────────────────┘
```

### 数据流

```
  Django DB
     │
     ▼
  Django REST API  ←── 服务器（新版 Django，纯 API + Admin）
     │
     ├→ 版本号检查：GET /api/sync/question-bank-version
     │  响应：{ "version": 3, "force_update": false }
     │
     └→ 用户数据接收：POST /api/sync/push
     │
     ▼
  SQLite (drift)
     ├─ assets 预置数据库：题库、步骤、知识卡片（App 自带，首次安装复制到应用目录）
     └─ 用户数据：提交、评分、组卷（本地优先，队列同步到服务器）
     │
     ▼
  Repository 层 (按 UI 需求组合数据)
     │
     ▼
  Flutter UI Widget (展示 + 交互)
```

**核心原则：**
- Repository 按 UI 页面需求组织数据，不暴露数据库表结构
- Drift 模型 = 数据库表的一行（原始字段）；Repository 模型 = UI 要的样子（已拼装/计算）
- 两者不同，不强行统一

### 3.2 解题模式

按题型拆分为三个独立 HTML 原型页面：`solve-choice.html`（选择题）、`solve-fill.html`（填空题）、`solve-solve.html`（解答题）。选择/填空共用冷却→提交/查看→结果→完成横幅模式，Flutter 中应抽象为共享 Widget。评分独立到 `solve-rate.html`，三题型共享入口，允许复访修改。

**Widget 复用说明：** 选填题的流程高度相似（冷却按钮等待 → 提交/查看 → 展示结果 → 🎉 已完成 → [下一题] [⭐ 评分]），Flutter 实现时应抽取 `SolveBaseWidget` 或 `SolveFlowWidget` 处理共同流程，选择/填空分别继承/组合。解答题的步骤卡（冷却箭头 → 展开 → 反馈按钮）单独抽取 `StepCardWidget`。

#### 完整交互序列

```
选填题：
  [题目显示]
  ↓
  10s 冷却 → 按钮禁用 + 小字倒计时
  ↓
  按钮恢复可用 → 用户提交/查看答案
  ↓
  自动展示结果（正确/错误 + 解析）
  ↓
  🎉 已完成 横幅 + [下一题 →] [⭐ 评分]
  ↓
  [下一题] → 继续
  [⭐ 评分] → solve-rate.html

解答题（N 步）：
  [当前步卡片显示]
  ↓
  5s 冷却 → 箭头按钮禁用 + 小字倒计时
  ↓
  箭头恢复可用 → 用户点击箭头 ▶
  ↓
  解析内容展开 → 反馈按钮出现
  ↓
  用户选择反馈 → 下一步卡片显示（重复直到最后一步）
  ↓
  全部完成 → 🎉 已完成 横幅 + [下一题 →] [⭐ 评分]
```

#### 防刷倒计时交互规则

- **计时起点**：题目显示（选填）/ 当前步卡片显示（解答），二者统一
- **冷却时长**：选填 10 秒，解答每步 5 秒
- **禁用对象**：选填题→「提交/查看」按钮；解答题→箭头按钮
- **禁用形态**：按钮 `opacity: 0.4; cursor: not-allowed`；按钮下方显示 `⏳ 还剩 N 秒可提交`
- **恢复时机**：冷却到时，按钮恢复可用，倒计时文字消失
- **重置时机**：进入下一状态时（下一题 / 下一步卡片显示）
- **无额外弹窗/Toast 提示**（视觉禁用 + 小字足够，不干扰读题）

#### 知识卡片交互

- 步骤标题旁的知识标签可点击
- 点击弹出知识卡片弹层（LaTeX 渲染）
- 点击弹层外部关闭

#### 评分交互

评分已从解题页独立到 `solve-rate.html`，三题型共享。
- 用户从完成横幅点击「⭐ 评分」进入评分页
- 评分页展示 3 组 10 星：**难度**、**计算量**、**优雅度**
- 难度和计算量显示算法分对比；优雅度无算法分
- 允许复访修改（不是一次性评分）
- 未来可从其他入口进入（历史记录、错题本、收藏夹）

#### 复访重建

第二次及更多次进入解题页时，不从零开始，而是从 user.db 读取历史记录重建解题状态。

**判断逻辑：**

| 类型 | 判定条件 |
|------|---------|
| 首次 | `submission_detail` 中无该 `question_id` 的记录 |
| 复访 | 有记录 |

**数据源（4 张 user.db 表）：**

| 表 | 用于重建什么 |
|----|------------|
| `submission_detail` | 选填是否已提交、对错 |
| `step_feedback` | 每步的 feedbackGiven + feedbackType |
| `card_feedback` | 知识卡片掌握度（仅状态展示） |
| `question_rating` | 是否已评分 |

**重建流程：**

```
solve 页 init
  ↓
ProgressRepository.getPreviousState(qid)
  ├── null  → 首次 → 正常冷却+交互
  └── PreviousSolveState → reconstructFromState()
       ├── completedSubQs  ← step_feedback 推算：该小问所有步都有反馈=已完成
       ├── currentMethod   ← 取有最新 step_feedback 的方法
       ├── stepState       ← 每条 step_feedback → {card,content,arrowHidden,feedbackGiven}=true
       ├── 未做的下一步    ← 无 step_feedback 的最前步，card=true，其余 false
       ├── 评分区          ← isRated=true 显示已有评分（可修改，跳转 solve-rate）
       └── 冷却计时器不启动（复访不需要防刷）
```

**首次 vs 复访 UI 差异：**

| 元素 | 首次 | 复访-已完成 | 复访-部分完成 |
|------|------|------------|-------------|
| 选择题选项 | 可选+可提交 | 不可选，结果区直接展示 | 同已完成 |
| 填空题按钮 | 10s冷却→可点 | 直接展示答案 | 直接展示答案 |
| 解答题箭头 | 禁用→冷却→可点 | 已完成的步：箭头隐藏，内容展开 | 同上；未完成的步：正常冷却→可点 |
| 反馈按钮 | 可交互 | 已选中的选中态 | 同上；当前步正常 |
| 冷却计时器 | 全部启动 | 不启动 | 只在"当前待继续步"启动 |
| done-section | 全部完成时显示 | 直接显示 | 不显示 |
| 评分 | 独立页 solve-rate，完成横幅有入口 | 可修改 | 可修改 |

### 3.3 讲义

`lecture_courses.html` → `lecture_chapters.html` → `lecture_content.html`

- 三级下钻：课程列表 → 章节目录 → 正文
- 数据流：
  - 服务端 `Document.md_content` 存储含分隔符的原始 markdown
  - 客户端 `lecture_content` 表镜像存储同一份 raw markdown（不解析）
  - 渲染时调用 `parseMdContent()` 解析为结构化 `pages[].blocks[]`（纯内存，不持久化）
  - 分隔符：`<!-- pagebreak -->`（分页）、`<!-- reveal -->`（同页内展开块分割）
- 底部固定翻页栏：
  - ◀/▶ 按钮，智能决定展开或翻页
  - 页码格式：「第 X / Y 页 · 展开 A / B」（B=本页总块数，A=已展开块数）
  - ◀：有已展开块则收回，无则翻上一页
  - ▶：有未展开块则展开，无则翻下一页
  - 全部展开/收回后按钮切换为翻页模式（蓝底白字 `→`/`←` 样式变化）
- REVEAL 逐段展开机制：`parseMdContent()` 解析后，每页分为 blocks[0..N]，blocks[0] 默认可见，blocks[1..N] 初始隐藏，逐步点击展开
- 内容区用 `MdLatexBody` 渲染 Markdown + LaTeX（blocks 中每个元素为独立 Markdown 字符串）
- 讲义中出现的知识标签可点击，弹出知识卡片弹层（复用解题模式的弹层）
- 键盘快捷键支持（低优先级）：← 收回/上一页，→ 展开/下一页
- 路由 page 参数：`/lecture/content?id=1&page=3` 中的 `page` 为客户端初始页索引，非服务端参数（解析后客户端决定展示第几页）

## 四、HTML 原型标记体系

### 4.1 标记总览

| 属性 | 含义 | 示例 | 对应 Flutter 层 |
|------|------|------|----------------|
| `data-db` | 📖 只读显示 | `data-db="user.getInfo.realName"` | Repository 方法返回值 |
| `data-db-bind` | 🔄 双向绑定 | `data-db-bind="auth.login.username"` | TextEditingController + 初始值 |
| `data-db-action` | ✏️ 写入操作 | `data-db-action="rating.submit()"` | Repository 写入方法 |
| `data-db-loop` | 🔁 列表循环 | `data-db-loop="assign.getPending"` | ListView.builder 数据源 |
| `data-db-empty` | 📭 空状态文案 | `data-db-empty="暂无待办作业"` | 列表为空时的占位 |

### 4.2 路径命名规范

```
格式：{repo缩写}.{方法名}[].{字段名}
```

- 首段：Repository 类名去掉 `Repository` 后首字母小写（`assign` ← `AssignmentRepository`）
- 中段：Repository 的方法名，camelCase
- `[]`：列表中的单个元素
- 尾段：返回对象的字段名，camelCase

**示例：**

```
data-db="assign.getPending[].title"
         assign  ← AssignmentRepository
                 getPending  ← getPending()
                          title  ← AssignmentSummary.title

data-db-action="exam.downloadPdf(1)"
                exam  ← ExamRepository
                     downloadPdf  ← downloadPdf()
```

### 4.3 标记颜色辅助（仅在原型中）

`styles.css` 中对标记了 `data-db` 的元素加了背景高亮，仅用于原型开发阶段：

```
[data-db]       → 浅黄底色 + 橙色虚线下划线
[data-db-loop]  → 蓝色虚线边框
```

### 4.4 SharedPreferences 标记说明

SharedPreferences **不纳入 `data-db` 标记体系**。原因：
- SharedPreferences 不直接驱动 UI 渲染（token、冷却时间、版本弹窗记录均为后台状态）
- `data-db` 的意义是「指着 HTML 元素说数据来自 Repository 的哪个方法」，原型评审者不需要看 key 名

SharedPreferences key 在 Flutter 代码中各页面的 `_Prefs` 类中声明，详见 [7.2 页头编译常量规范](#72-页头编译常量规范)。

### 4.5 LaTeX/MD 渲染标注

以下 data-db 路径的值可能含 Markdown 和/或 LaTeX 数学公式，Flutter 实现时统一用 `MdLatexBody` 组件渲染。该组件位于 `spec/md&LaTex/md_latex_body.dart`，封装了 `flutter_markdown_plus` + `flutter_math_fork`，支持 `$...$` 行内公式和 `$$...$$` 块级公式。

| data-db 路径 | 内容类型 | 出现页面 |
|-------------|---------|---------|
| `question.getDetail.stem` | 题干 Markdown + LaTeX 公式 | solve-choice/fill/solve (题干区) |
| `progress.getSolveState.subQuestions[].solutions[].steps[].analysis` | 步骤解析 LaTeX 公式 | solve-solve (步骤解析区) |
| `lecture.getContentParsed.pages[].blocks[]` | 讲义正文 Markdown + LaTeX（解析后：pages 外层循环，blocks 内层循环） | lecture_content |
| 知识卡片弹层内容 | 卡片说明 LaTeX | solve-solve, lecture_content |
| `question.getDetail.conceptTags` | 概念标签列表（用 Chip + Wrap 渲染，非 LaTeX） | solve-choice/fill/solve |

## 五、Repository 层规范

### 职责

Repository 为 UI 层提供组合好的数据对象，不直接暴露数据库表结构。

```
❌ 错误：AssignmentRepository.getAll()
         + ClassCourseAssignmentRepository.getByXxx()
         + CourseRepository.getById()
   → UI 层自己 join 3 张表

✅ 正确：AssignmentRepository.getPending()
   → 返回已经包含 title/courseName/doneCount/deadline 等所有字段的对象
```

### 与数据库模型的关系

```
Drift Table (存)   →  数据类 = 数据库表的一行，含主键/外键/原始字段
Repository (用)    →  数据类 = UI 需要的样子，已拼装/已计算
```

两者用途不同，各自独立。Repository 方法内部负责：查 DB → JOIN/计算 → 拼装 → 返回 Repository 模型。

### 简单/复杂分离

Repository 文件中的方法分为两类：

| 类型 | 特征 | 维护频率 | 涉及文件 |
|------|------|---------|---------|
| **简单方法** | 直接读写本地 db，无额外计算 | 写一次不再动 | 全部 13 个文件 |
| **复杂算法** | 需聚合/过滤/推荐/状态计算 | 算法持续迭代 | 5 个文件尾部私有类 |

复杂逻辑写在文件尾部的私有类中（如 `_PointsCalculator`），**仅供本文件 Repository 内部调用**，不对外暴露。页面开发者只需 import Repository 类，不需要知道私有类的存在。

```dart
class ExamRepository {
  // 简单方法（直接读写本地 db）
  static Future<List<ExamSummary>> getMyExams() async { ... }

  // 复杂方法（委托给私有类）
  static Future<PoolStats> getPoolStats(SearchFilters f) async {
    return _ExamFilterEngine().compute(f);
  }
}

// 文件尾部私有类
class _ExamFilterEngine { ... }
```

### 实现文件

见 `spec/Repository/` 目录下的 13 个 Dart 文件。每个文件包含 Repository 类 + 数据模型类，5 个文件尾部附私有算法类。

| 文件 | Repository | data-db 前缀 | 对应页面 | 尾部算法类 |
|------|------------|-------------|---------|-----------|
| `auth_repository.dart` | AuthRepository | `auth.*` | login, register | — |
| `assignment_repository.dart` | AssignmentRepository | `assign.*` | homework_list, homework_detail, index(待办数) | — |
| `lecture_repository.dart` | LectureRepository | `lecture.*`（getContent 返回 LectureContent，解析后 data-db 为 `lecture.getContentParsed.*`） | lecture_courses, lecture_chapters, lecture_content | — |
| `question_repository.dart` | QuestionRepository | `question.*` | solve-choice/fill/solve(题干), paper_quicklook(做题动作) | — |
| `progress_repository.dart` | ProgressRepository | `progress.*` | solve-solve(解题步骤, 复访重建) | — |
| `rating_repository.dart` | RatingRepository | `rating.*` | solve-rate(评分) | — |
| `sync_repository.dart` | SyncRepository | `sync.*` | sync_queue, profile(副标题) | — |
| `preference_repository.dart` | PreferenceRepository | `preference.*` | preference_*, profile(偏好数), paper_auto/pick(加载预设) | — |
| `user_repository.dart` | UserRepository | `user.*`, `tasks.*`, `points.*`, `app.*` | index(任务卡片), profile, profile_edit, points, level_detail, about, solve-choice/fill/solve(积分行) | `_PointsCalculator` |
| `exam_repository.dart` | ExamRepository | `exam.*` | 所有组卷页面 (auto/pick/quicklook/explore/favorites/history/answer_sheet) | `_ExamFilterEngine` + `_ExamGenerator` + `_ExamPdfService` |
| `recommend_repository.dart` | RecommendRepository | `recommend.*` | recommend | `_RecommendationEngine` |
| `statistics_repository.dart` | StatisticsRepository | `stats.*` | statistics, profile(统计摘要) | `_StatisticsAggregator` |
| `achievement_repository.dart` | AchievementRepository | `achievement.*` | achievement, profile(成就数) | `_AchievementEngine` |

### 文件结构规范

每个 `.dart` 文件按以下顺序排列：

```dart
/// 章鱼智学 — {Domain}Repository
/// data-db: {prefix}.*
/// 对应页面：{页面列表}

// 1. 数据模型类（const + fromJson）
class ModelA { ... }
class ModelB { ... }

// 2. Repository 类（static 方法，throw UnimplementedError）
class {Domain}Repository {
  /// GET /api/xxx/
  static Future<T> methodName() async {
    throw UnimplementedError('{Domain}Repository.methodName');
  }
}

// 3. （可选）私有算法类，仅供本文件内部使用
class _{ComplexEngine} { ... }
```

### 跨页面数据组织

一个页面可引用多个 Repository。例如 profile.html 的数据来自 5 个领域：

```dart
// profile 页面的 ViewModel
final user = await UserRepository.getUserInfo();
final stats = await StatisticsRepository.getOverview();
final prefCount = await PreferenceRepository.getCount();
final achCount = await AchievementRepository.unlockedCount();
final syncStatus = await SyncRepository.hasFailed();
```

不设 ProfileRepository，不制造没有 data-db 对应关系的包装层。

### 缩略名规则

Repository 类名去掉 `Repository` 后首字母小写，即为 data-db 路径的首段和 Flutter 代码中的变量名：

```
AssignmentRepository → assign  ← data-db="assign.*"
ExamRepository       → exam    ← data-db="exam.*"
```

## 六、本地数据方案

### 6.1 数据分类

| 类别 | 内容 | 来源 | 同步方式 |
|------|------|------|---------|
| 题库 | 题目、步骤、知识卡片 | App 预置 | 版本号检查 → 提示商店更新 |
| 元数据 | 课程、讲义、作业 | App 预置 | 同上 |
| 用户操作 | 提交记录、反馈、评分 | 本地写入 | 队列推送到服务器 |
| 组卷 | 学生自组试卷 | 本地写入 | 队列推送到服务器 |
| 积分 | 积分余额 | 服务器计算 | 本地缓存显示 |

### 6.2 预置题库数据库

- 开发时用 drift 建好全量表结构，导入数据生成 `.db` 文件
- 放入 Flutter `assets/` 目录
- App 首次启动复制到应用文档目录（`getApplicationDocumentsDirectory()`）
- 后续启动直接使用，无需等待网络

**更新流程：**
- App 启动时调用 `GET /api/sync/question-bank-version`
- 响应：`{ "version": 3, "force_update": false, "message": "新增2025年真题" }`
- 版本落后 → 非强制则右下角提示；强制则弹框引导去应用商店
- 不做增量拉取，不自动下载；更新 = 发新版 App

### 6.3 用户数据同步

**写入流程：**
```
用户操作 → 写入本地 SQLite（即时响应）
         → 追加 sync_queue 表
         → App 启动时/手动触发批量推送
```

**队列表结构：** `entity_type` / `operation_type` / `payload`(JSON) / `status` / `retry_count`

**冲突处理：** LWW（last-write-wins），服务器比较 `updated_at` 覆盖旧值。用户数据均为单人独写，不存在多用户写同一条记录的情况。

### 6.4 API 层设计说明

服务器（新版 Django）只提供两类接口：

| 接口类型 | 说明 |
|---------|------|
| **REST API** | Flutter 客户端调用（认证、数据同步、查询等） |
| **Django Admin** | 管理员后台（管理学生/班级/题目/数据查看） |

**核心原则：**
- 不提供面向学生/教师的网页端，仅通过 API 与 Flutter 客户端交互
- 数据字段映射仅在 API 层处理（serializer），不侵入业务逻辑
- 同步接口保持幂等（LWW 冲突解决）

### 6.5 SharedPreferences 路径规范

SharedPreferences 用于存储**纯客户端状态**，不经过 Repository 体系（不走数据同步流程）。

#### 使用场景汇总

| 场景 | key 命名 | 对应页面 | 说明 |
|------|---------|---------|------|
| 登录 token | `app_auth_token` | auth, 全局 | 登录成功后存储，登出时清除 |
| 用户信息缓存 | `app_user_cache` | 全局 | JSON，启动时快速展示个人资料 |
| 评价弹窗冷却 | `solve_rating_cooldown_{page}` | solve-solve, paper_quicklook, lecture_content | 同页 24h 内不重复弹出 |
| 版本更新弹窗 | `app_update_last_shown` | 全局 | 上次提示版本更新的时间 |
| 解题防刷上次提交 | `solve_last_submit_{questionId}` | solve-choice/fill | 10s 冷却校验 |
| 新手引导标记 | `{page}_guide_done` | 各页面 | 首次进入新手引导 |

#### key 命名规范

```
{页面缩写}_{用途}
```

- 全局性的 key 以 `app_` 开头
- 页面级的 key 以页面缩写开头
- 需要区分具体对象的 key，在末尾拼唯一标识（如 `{questionId}`）

#### 代码规范

- 每个页面对应的 Dart 文件内声明 `_Prefs` 类，集中管理该页使用的所有 key
- 全局共用的 key 放在 `lib/constants/app_prefs.dart`

```dart
// pages/solve/solve_page.dart 头部
class _SolvePrefs {
  static const String lastSubmit = 'solve_last_submit_{qid}';
  static const String ratingCooldown = 'solve_rating_cooldown';
}
```

不设 HTML 标记，不在原型中标注。

### 6.6 网络请求失败处理

本 App 是本地优先架构，绝大多数数据从本地 SQLite 读取，网络请求仅限于少量场景：

| 请求类型 | 失败处理 |
|---------|---------|
| 登录/注册 | 必须在线，失败则表单上方显示红色内联错误提示 |
| 版本检查 | 静默失败，使用本地缓存的版本号，不提示用户 |
| 同步队列推送 | 保留在队列中，下次启动或手动触发时重试；同步队列页面已有错误提示 |
| 用户信息 / 偏好拉取 | 静默失败，使用 SharedPreferences 缓存的版本 |

登录后 token 存本地 SharedPreferences，只要用户不退出登录即可正常使用全部核心功能（做题、组卷、统计等），无需重复网络请求。

### 6.7 图片路由规范

本规范定义 App 中两类图片（题库配图、用户头像）的存储位置、路径格式和解析规则。

#### 题库配图

图片来源：从源材料（PDF/Word 试卷）中提取的几何/函数示意图，打包为 Flutter assets。

**存储位置：**

```
assets/questions/images/
├── 一模/
│   ├── 2024/海淀/q17.webp
│   └── ...
├── 二模/
│   └── ...
└── 高考/
    └── ...
```

所有配图统一为 **WebP** 格式，由服务端 `convert_to_webp.py` 批量转码后打包到 App 中。

**Repository 模型中的引用：**

`QuestionDetail.images` 字段存储相对路径列表，不含 `/static/questions/附图/` 前缀：

```dart
images: ['一模/2024/海淀/q17.webp']
```

**解析方式：**

配图直接使用 `AssetImage` 加载。assets 中不存在即为 bug，不做网络回退。

**渲染位置：**

配图显示在题干下方。多张配图按 `images` 数组顺序纵向排列。Flutter 实现时用 `ImageResolver` 返回 `AssetImage`。

**后续待完成：**

| 事项 | 时机 | 说明 |
|------|------|------|
| 服务端 WebP 批量转码 | 新版 Django 上线前 | 已有 `convert_to_webp.py` 脚本 |
| 打包 `assets/questions/images/` 目录 | Flutter 构建时 | 在 `pubspec.yaml` 中声明 |
| 图片提取与存储：`images` 字段 | 数据入库阶段 | 从源材料提取 `<img>` 标签或图形，单独存放为 `images` JSON 字段，`stem` 中仅保留自然语言引用 |

#### 用户头像

**上传流程（不进同步队列）：**

```
用户选图 → resize 200×200 → 存本地文件系统
       → POST multipart/form-data → /api/user/avatar/
       → 服务端返回 URL
       → 更新本地 avatar 字段
```

头像不上传涉及的内容：**同步队列**（`SyncQueue`）设计用于 JSON 结构化数据的批量提交。头像是二进制文件，传 multipart/form-data 与传 JSON 的端点不同，混入队列需要 base64 编码（膨胀）且批量推送端点不支持 multipart。头像上传走独立接口，URL 作为用户信息随下次 `UserInfo` 同步推送。

**客户端渲染：**

优先展示本地缓存的版本，后台静默请求最新 URL。使用 `cached_network_image` 实现：首次加载时缓存到磁盘，后续离线时直接读取缓存。

**后续待完成：**

| 事项 | 时机 | 说明 |
|------|------|------|
| Django `Student.avatar ImageField` | 新版 API | 服务端存储 |
| 上传时 resize + WebP 压缩 | 新版 API | 限制体积 |
| Flutter 端上传 UI | Flutter profile_edit 开发时 | 复用原型已有逻辑 |

### 7.2 页头编译常量规范

#### 为什么要做

- 所有显示文字集中到文件头部，改文案不用在 widget 树里翻
- 一目了然本页涉及哪些 SharedPreferences key
- 方便日后的文案审查和多语言

#### 显示文字：`_Strings` 类

每个页面对应的 Dart 文件头部声明一个私有 `_Strings` 类，所有用户可见的文字定义为 `static const String`，包括该页的 `data-db-empty` 空状态文案：

```dart
// 在页面主文件（或独立的 _strings.dart）头部
class _SolveStrings {

      cooldownHint.replaceAll('{n}', seconds.toString());

class _RecommendStrings {
  static const String emptySmart = '暂无推荐题目，多做几道题试试';

```

**全局共享文字**单独放 `lib/constants/app_strings.dart`，如：
- 通用按钮：提交、取消、返回、保存、删除、确认
- 通用提示：加载中、暂无数据、网络错误
- App 名称和品牌文案

#### SharedPreferences key：`_Prefs` 类

同上，每页头部声明一个 `_Prefs` 类：

```dart
class _SolvePrefs {

### 7.3 Widget 复用规范

#### 判定规则

```
跨 2 页以上出现 且 语义一致 → 抽出 Widget
```

- **跨 2 页以上**：出现于 2 个或以上页面（包括同一个 Tab 下的不同子页面）
- **语义一致**：交互行为相同、数据结构相同。如果只是长得像但交互不同（如一个点击跳转、一个弹窗），不抽
- **先写内联再抽**：不确定是否会复用时，先内联写，第二次出现时重构抽出

#### 存放目录

```
lib/widgets/
├── common/           # 通用组件（跨域复用）
├── {domain}/         # 领域内复用（如 exam/, solve/）
└── widgets.dart      # barrel export

### 7.5 路由方案

采用 `Navigator.pushNamed` + 集中路由表 `lib/router.dart`。

#### 路由命名规范

路径用 `kebab-case`，参数用 query param：

```
/                            → MainShell（底栏外壳）
/login                       → 登录
/register                    → 注册
/homework                    → 作业列表
/homework/detail?id=3        → 作业详情
/solve?qid=42&from=homework  → 解题页（from 标记来源：homework/paper/recommend）
/solve/rate?qid=42           → 评分页
/lecture/courses             → 讲义课程列表
/lecture/chapters?id=1       → 讲义章节
/lecture/content?id=1&page=3 → 讲义正文（page 客户端参数，非服务端）
/paper/auto                  → 智能组卷
/paper/pick                  → 自主选题
/paper/quicklook?id=5        → 组卷预览
/recommend                   → 推荐
/profile                     → 我的
/statistics                  → 学习统计
/achievement                 → 成就
/points                      → 积分流水
/preference/list             → 偏好管理
/preference/edit?id=         → 偏好编辑
/about                       → 关于
```

#### 过渡动画

- 常规 push：从右向左滑入（Material 默认）
- 底部 Tab 切换：无动画
- 返回：从左向右滑出

#### Web 端浏览器行为

- 每个 Navigator.push 对应一条浏览器历史记录
- 浏览器「后退」按键 = Navigator.pop
- 解题页退出时如触发评分弹窗，后退键先关闭弹窗再执行后退

### 7.6 加载与骨架屏

#### 规则

- **列表页首次加载**：使用骨架屏（Shimmer）占位，数据到达后替换
- **后续刷新**：保留现有内容，列表顶部或底部显示局部转圈
- **非列表页**（如 solve、login）：单纯居中转圈 `CircularProgressIndicator`，不需要骨架屏

骨架屏实现：在 `lib/widgets/common/` 下建 `skeleton_loader.dart`，提供通用骨架屏组件（卡片/列表项/段落三种形状）。

### 8.3 难度与计算量分段映射

难度和计算量在数据库中为 0-10 连续值，在 UI 中分为 5 段展示，用于筛选滑块和推荐标签。

#### 难度 5 段

| 段 | 范围 | 标签 | 题型举例 |
|---|------|------|---------|
| 基础 | 0-3 | 基础 | 单选1-3·填空11·解答第一问 |
| 中档 | 3-5 | 中档 | 单选4-6·填空12-13·常规解答 |
| 中难 | 5-7 | 中难 | 选填后半·填空14·解答多步推理 |
| 较难 | 7-8.5 | 较难 | 选填压轴·解答最后两问 |
| 压轴 | 8.5-10 | 压轴 | 解答压轴问·创新综合题 |

**数据依据：** 选择题 Q1-Q10 难度从 0.3 递增到 6.9（选择题不含 7+ 题）；填空题 Q11-Q15 难度从 1.7 到 7.2（仅 3 题落在 7 段）；解答题 Q16-Q21 从 0.0 到 9.7 全覆盖（含多小问）。分段边界在题型构成明显变化处：3 以上选择题不再包揽基础，5 以上解答题比例显著增加，7 以上全是解答题，8.5 以上仅解答题压轴问。

**难度分布（798 题统计）：**

| 段 | 题数 | 占比 |
|-----|------|------|
| 0-3 | 271 | 34% |
| 3-5 | 226 | 28% |
| 5-7 | 361 | 45% |
| 7-8.5 | 107 | 13% |
| 8.5-10 | 19 | 2% |

#### 计算量 5 段

| 段 | 范围 | 标签 | 运算描述 |
|---|------|------|---------|
| 少量 | 0-2 | 少量 | 心算即可，不需动笔 |
| 较少 | 2-4 | 较少 | 简单代入化简，2-3步 |
| 适中 | 4-6 | 适中 | 常规运算量，需完整步骤 |
| 较多 | 6-8 | 较多 | 多步代数运算，需仔细 |
| 繁琐 | 8-10 | 繁琐 | 大量代数变换，需耐心推导 |

**计算量分布（798 题统计）：**

| 段 | 题数 | 占比 |
|-----|------|------|
| 0-2 | 180 | 22.6% |
| 2-4 | 132 | 16.5% |
| 4-6 | 212 | 26.6% |
| 6-8 | 220 | 27.6% |
| 8-10 | 54 | 6.8% |

#### 滑块标记位置

难度和计算量在 UI 滑轨上的标签位置不同：

- **难度**：边界在 30%, 50%, 70%, 85%（即 3/5/7/8.5 对应轨道百分比）
- **计算量**：边界在 20%, 40%, 60%, 80%（等分）

#### 注意事项

- `models.py` 注释写的 `difficulty(1-5)` / `workload(1-5)` 已过时，实际是 0-10 连续值
- 问答 rating 表（QuestionRating）的 difficulty/workload 也是 0-10 连续值
- 难度和计算量高度相关（r=0.808），不存在"高难度低计算量"或"低难度高计算量"的题目
- median 难=5.3，median 计=5.3

### HTML 原型 → Flutter 代码

```
1. 设计阶段
   UI_Phase1.canvas（手绘草图）
        │
        ▼
   UI_Phase2/*.html（可交互原型）
        │
        ▼

        │
        ▼
2. 开发阶段
   Flutter UI Widget → 对照 HTML 布局
   Repository 层     → 对照 data-db 标记 + spec/Repository/*.dart
   SQLite (drift)    → 对照 docs/服务器_数据库结构.md
        │
        ▼
3. 数据对接
   把 repository.dart 中 throw UnimplementedError
   替换为 drift DAO 调用 + API 调用
```

### 修改 HTML 后的同步流程

修改 HTML 中的 `data-db` 路径后，需要同步更新：

```
1. 修改的 HTML 文件            ← data-db 路径
2. 对应的 repository.dart      ← 模型字段名或方法返回结构
3. 所有 HTML 中相同路径的其他页面 ← 全文搜索确保一致性
```
